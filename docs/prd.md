## 1. 背景与目标

### 1.1 业务背景

Albedo 以统一产品底座服务多个独立业务租户。租户通过三级域名访问各自站点，例如：

- `albedo-gift.eyescode.top` → 租户号 `gift`
- `albedo-redbook.eyescode.top` → 租户号 `redbook`

不同租户拥有独立品牌配置、成员关系、Agent、Skill、MCP、本地 Tool、会话、消息、权限与运行数据，同时共享平台能力。系统需要完成租户识别、耶瞳 SSO、配置加载、Agent 对话、管理治理与工具编排的完整产品闭环。

### 1.2 业务目标

1. 建立可扩展的多租户 AI 问答底座，使新增租户无需修改业务代码即可启用。
2. 确保租户间成员关系、会话、配置、AI 资源及运行数据严格隔离。
3. 支持站点品牌、Agent、Skill、MCP 与本地 Tool 的租户差异化。
4. 按耶瞳真实接入方式形成授权跳转、Token 接收、续期、失效重登和退出闭环。
5. 提供低学习成本、支持流式反馈与故障恢复的文本问答体验。
6. 通过管理后台、RBAC、审计、埋点和限流形成可运营、可追溯的治理能力。

### 1.3 成功指标

| 指标 | 当前值 | 目标值 | 统计口径 |
|---|---:|---:|---|

| 跨租户数据泄露事件 | 0 | 0 | 安全测试、审计与线上告警确认事件 |

| 会话创建与首条消息保存成功率 | 0 | ≥99.9% | 成功完成数 / 有效请求数 |

## 2. 范围、里程碑与非范围

### 2.1 纳入范围

1. 租户识别、启停、配置降级与全链路隔离。
2. 耶瞳 SSO 授权、Token 存储与续期、鉴权失效重登、惰性建立租户成员关系、退出登录。
3. 站点配置读取、草稿、校验、发布、回滚与版本治理。
4. Agent 展示、选择、运行、管理、版本、默认项与启停。

6. 会话新建、列表、打开、重命名、删除、分页与只读状态。
7. 文本消息、流式响应、停止、重试、重新生成、上下文、Markdown 与工具调用状态。
8. 平台管理员、租户管理员、租户运营、终端用户的权限控制。
9. 审计、埋点、运行指标，以及按租户与用户隔离的对话 QPM 限流和每日对话限额。

### 2.4 M1 最小可用闭环边界

**M1 必须具备：**

- 使用 `gift`、`redbook` 两套有效租户数据验证 Host 识别和隔离。
- 未登录用户可浏览公开站点配置与可用 Agent；访问受保护能力时进入耶瞳 SSO。
- SSO 回跳后可在原页面继续操作，首次访问需登录接口时惰性建立当前租户成员关系。
- 登录用户可选择已发布 Agent，新建/打开/管理本人会话，发送消息并看到流式回答。
- 支持停止、失败重试、重新生成、Markdown 安全展示和确定性错误反馈。
- 已发布站点配置与 Agent 由 M1 验收数据提供，运行时必须按租户读取，不得硬编码租户文案或 Agent。

**M1 不包含，由后续承接：**

- M2（Deferred 至二期）：租户、站点配置、Agent、Skill、MCP、本地 Tool、成员与角色、审计的完整管理后台；草稿/发布/回滚治理；前端权限渲染；管理操作审计。
- M2-min（并入 M3）：M3 接口后端准入、运行时安全事件审计、独立配置校验、凭据离线加密、缓存主动失效及 M3 资源最小后端配置/授权能力。
- M3：Skill 版本化与注入、MCP 配置/连接测试/工具发现与授权后的运行时调用、本地 Tool 注册授权与执行编排、工具风险确认、产品埋点和租户级限流。

### 2.5 不纳入范围

| 非范围项 | 产品边界理由 |
|---|---|
| 图片、文件、音频上传及知识库问答 | 产品定位为文本问答与受控能力编排 |
| 语音输入、语音输出 | 属于多模态交互能力 |
| 终端用户自建 Agent、Skill 或 MCP | 资源由租户管理角色治理，终端用户仅使用已发布能力 |
| 计费、套餐、额度购买 | 属于商业化系统；本项目仅记录可观测用量 |
| 租户自定义域名 | 当前仅支持 `*.eyescode.top` 体系三级域名 |
| 跨租户会话共享或迁移 | 与强隔离原则冲突 |
| 任意代码上传为本地 Tool | 本地 Tool 必须由平台预注册，租户仅可授权与配置 |

## 3. 术语与角色

### 3.1 术语

| 术语 | 定义 |
|---|---|
| 租户 | 独立业务空间，拥有唯一租户号、Host、配置、成员关系与业务数据 |
| 租户号 `tenantId` | 2～32 位稳定唯一标识，如 `gift`、`redbook`，创建后不可修改 |
| 租户上下文 | 由可信 Host 确定并贯穿一次请求的租户身份与有效配置版本 |
| Agent | 面向终端用户提供对话的 AI 助手配置 |
| Agent 版本 | Agent 发布形成的不可变快照；会话绑定创建时使用的版本 |
| Skill | 注入 Agent 的可复用指令、流程或输出约束，不执行任意代码 |
| MCP | 向 Agent 暴露经授权远程工具的 Model Context Protocol 服务 |
| 本地 Tool | 平台预注册、在受控环境执行的工具，租户不可上传代码 |
| 会话 | 当前租户用户与特定 Agent 版本的连续对话容器 |
| 耶瞳 SSO | 通过浏览器跳转、JWT Token 与后端鉴权提供统一身份的 eyesUser 服务 |
| 发布 | 将草稿校验后形成不可变且可供线上读取的版本 |
| 惰性建户 | 用户首次携带有效身份访问某租户任一需登录接口时，才建立该租户成员关系 |

### 3.2 用户角色与认定

| 角色 | 认定来源 | 能力说明 |
|---|---|---|
| 平台管理员 | eyesUser 返回 `role=ADMIN`；对应 `@Permission(PermissionEnum.ADMIN)` | 管理平台级租户、域名、本地 Tool 注册；跨租户访问必须受控 |
| 租户管理员 | 本地租户成员关系 | 管理本租户配置、成员角色、Agent、Skill、MCP、Tool 授权与审计 |
| 租户运营 | 本地租户成员关系 | 管理本租户文案与 AI 能力资源，查看审计；不可管理成员角色 |
| 终端用户 | 本地租户成员关系，默认惰性创建 | 使用已发布 Agent，管理本人会话 |
| 匿名访客 | 无有效 Token | 仅查看公开配置和 Agent 展示信息 |
| 系统服务账号 | 平台任务身份 | 执行配置刷新、归档等任务；必须声明租户或平台作用域 |

**角色规则：**

1. eyesUser 的 `ADMIN` 只认定平台管理员，不直接赋予任何租户内角色。
2. 租户管理员、租户运营、终端用户均由本地租户成员关系维护。
3. 同一 `uid` 可属于多个租户，各租户角色与状态互不继承。

## 4. 总体业务规则

1. 一个有效 Host 只能绑定一个租户；一个租户当前仅有一个主 Host。
2. `tenantId` 必须匹配 `^[a-z][a-z0-9-]{1,31}$`，创建后不可修改。
3. 主 Host 切换必须先完成新绑定校验，再切换并形成审计记录。
4. 租户身份只来源于可信 Host；请求参数中的 `tenantId` 不得作为权限依据。
5. 匿名访客可读取启用租户的公开配置和 Agent 展示列表；消息、会话与管理后台必须登录。
6. 用户首次携带有效 eyesUser 身份访问当前租户任一需登录接口时，自动建立默认“终端用户”成员关系；这不是登录回跳动作。
7. 已存在但状态为 `disabled` 的租户成员不得因再次访问而自动恢复。
8. 站点配置、Agent、Skill 与 MCP 的线上变更遵循“草稿保存 → 校验 → 发布”；失败继续使用上一已发布版本。
9. 发布版本不可修改；再次编辑必须基于已发布版本形成新草稿。
10. 新会话绑定创建时 Agent 的最新已发布版本；旧会话不静默切换版本。
11. Agent 停用后不可新建会话或继续发送；历史会话只读、可查看和删除。
12. Skill、MCP 或本地 Tool 被停用或撤销授权后，尚未进入 `invoke` 的调用必须拒绝；已进入 `invoke` 的单次调用允许在既定超时内完成（本地 Tool 为毫秒级，MCP 不超过 30 秒），之后的新调用必须拒绝。
13. Agent 能力绑定在每次提问开始时形成生成期快照；解绑仅对下一次提问生效。需立即阻断当前生成中的后续工具执行时，必须撤销租户授权 `granted` 或停用资源 `status`。
14. 业务对象默认软删除；会话删除后立即不可见，30 天后物理清除。
15. 面向用户的时间按租户时区展示，存储时间统一为 UTC。
16. 对外反馈不得暴露内部地址、堆栈、密钥、其他租户标识或资源存在性。
17. P0/P1/P2 仅表达价值和依赖顺序，不作为删除纳入范围需求的理由。
18. 对话 QPM 限流与每日对话限额均按可信租户上下文与当前登录 `uid` 组成的主体独立计算；同一用户在不同租户的配置、计数与剩余额度互不影响。
19. QPM 与每日限额是两个独立概念：QPM 用于限制短时突发，等待当前分钟窗结束即可继续；每日限额用于限制租户日历日内生成次数，额度用尽后须等待租户当地下一日零点。
20. 所有阈值、启停与生效规则必须来自数据库配置；产品默认值 QPM=3、每日限额=50 是数据库默认配置，禁止以代码常量或缺键兜底方式实现。

## 5. 租户识别与强制隔离

### 5.1 Host 识别规则

1. 请求 Host 必须先规范化：去端口、转小写、去末尾点；开发验证映射见第 5.1.7 条。
2. 规范化 Host 必须精确匹配有效租户记录，不得仅按字符串截取猜测租户。
3. 生产映射目标：
   - `albedo-gift.eyescode.top` → `gift`
   - `albedo-redbook.eyescode.top` → `redbook`
4. 未知 Host 返回站点级 HTTP 404“站点不存在”页。
5. 租户暂停返回站点级 HTTP 403“站点暂停服务”页，不展示登录入口、Agent 或业务数据。
6. 配置加载失败时使用最后一个成功发布版本；无可用版本返回站点级 HTTP 503“站点配置异常”页并触发告警。
7. **一期主验证路径**：生产三级域名尚未就绪，M1 开发与测试使用 `sys_config` 中的 dev host 映射，将 `localhost:<port>` 或测试请求手工 Host 映射为 `gift`、`redbook`。该能力只允许在非生产环境启用，生产环境必须关闭；生产不得通过自定义业务 Header 模拟租户。

### 5.2 隔离规则

| 层级 | 产品规则 | 验收要求 |
|---|---|---|
| 业务数据 | 所有租户业务数据均有非空租户维度，读写必须限定当前租户 | 跨租户 ID 访问结果为空且不泄露来源租户 |
| 唯一性 | 业务唯一性按租户分别计算 | 两租户可创建相同业务 key |
| 关联关系 | 关联对象必须属于同一租户 | 跨租户关联被拒绝 |
| 缓存与对象 | 租户业务缓存与对象路径必须可区分租户 | 不存在跨租户复用导致的数据命中 |
| 检索 | 每次检索均限定当前租户 | 跨租户检索结果为 0 |
| 异步任务 | 业务任务必须携带租户上下文 | 缺失租户的任务拒绝执行并告警 |
| 日志与审计 | 业务链路包含租户、请求、操作者维度 | 抽检完整率 100% |
| 指标与限流 | 指标和计数按租户隔离 | 单租户行为不占用其他租户额度 |

### 5.3 平台受控访问

平台管理员默认不可浏览用户消息正文。跨租户排障必须选择目标租户、填写原因、获得最长 30 分钟的临时授权并形成不可删除审计；授权结束后立即失效。

## 6. 核心流程

### 6.1 访问与配置加载

1. 用户访问租户站点。
2. 系统依据可信 Host 建立只读租户上下文。
3. 未知、暂停、无有效配置分别进入站点级 404、403、503 分支。
4. 启用租户读取当前已发布站点配置与可展示 Agent。
5. 页面标题、Logo、欢迎语、输入提示和页脚均使用租户配置，不得硬编码租户文案。

### 6.2 耶瞳 SSO 登录、注册、续期与退出

#### 6.2.1 发起授权

1. 用户点击登录、免费注册，或未登录访问需登录能力。
2. 前端保存当前租户页面的安全站内地址和未发送输入草稿；草稿只在当前租户 Host 下恢复。
3. 浏览器整页跳转：

```text
https://user.eyescode.top/OAuth2?clientId=361925&redirectUrl=<URL 编码后的当前页完整 URL>
```

4. 授权地址由前端直接按当前页生成；身份凭据由原业务页面接收并处理，不经过站内认证中转流程。

#### 6.2.2 授权回跳

1. eyesUser 将浏览器回跳至原页面，并附加 `?authorization=<jwt>`。
2. 前端在应用入口立即解析 `authorization`，写入 `localStorage` 的 `authorization` 键。
3. 保存成功后立即调用 `history.replaceState` 清除地址栏中的 Token，同时保留原页面路径和除 `authorization` 外的安全业务参数。
4. URL 中的 Token 不得进入埋点、访问日志、错误日志、Referer 或页面展示。
5. 回跳完成不直接建立租户成员关系；用户首次调用任一需登录业务接口且身份有效时，按第 6.2.4 条惰性建户。

#### 6.2.3 请求鉴权与续期

1. 每次业务请求从 `localStorage` 读取 Token，并通过请求 Header `authorization` 携带。
2. 本项目采用 `auth-type=1` 单 Token 模式；每次响应如包含 Header `authorization`，前端必须立即回写本地 Token 后再处理后续请求。
3. 响应 `body.code` 命中 `20000、20001、20002、20003、20004、20005` 任一值时，前端清除 Token，并整页跳回第 6.2.1 的 SSO 地址；其中账号冻结等状态先传达原因语义再跳转。
4. 本项目不存在 `/login` 路由，不得以站内路由替代 SSO 整页跳转。
5. 后端接入约束为 `com.eyes:eyesAuth-spring-boot-starter:1.1.0`，公开、登录、平台管理员接口分别使用 `@Permission(NO/USER/ADMIN)` 语义；有效身份以 `UserInfoHolder.getUid()` 和 `UserInfoHolder.getRole()` 为准。

#### 6.2.4 惰性建立租户成员关系

1. 触发条件：携带有效身份首次访问某租户任一需登录接口。
2. 以 eyesUser `uid` 与当前租户共同定位成员关系。
3. 不存在成员关系时，建立默认终端用户关系后继续原请求。
4. 已存在且 active 时直接继续；已存在但 disabled 时拒绝，且不得新建或恢复。
5. 同一 `uid` 首次访问不同租户时分别建关系，角色和状态互不影响。
6. eyesUser `role=ADMIN` 同时认定为平台管理员；是否拥有当前租户内操作权仍按平台受控访问或本地租户角色规则判断。

#### 6.2.5 退出登录

1. 用户触发退出后，前端清除 `localStorage.authorization` 和当前租户的敏感临时状态。
2. 浏览器整页跳转至 SSO 授权地址。
3. 退出行为仅由前端完成，不发起任何后端退出请求。

### 6.3 配置与 Agent 发布

1. M1 继续消费已发布配置与 Agent；一期不提供管理 UI，DBA/开发人员直接写入站点配置、Agent、Skill、MCP Server 与 Tool 授权数据。
2. DBA/开发人员改库后必须调用独立配置校验入口，校验必填字段、枚举、资源状态、版本引用、同租户归属、Tool 授权及安全约束。
3. 配置校验通过不自动代表缓存已失效；需由平台管理员调用缓存失效接口，使 `config_version` 指针、Agent 版本快照及 `sys_config` L1/L2 按指定作用域失效并记录审计。
4. 新会话使用写库后生效的 Agent 版本，旧会话保持原版本。
5. 运行时再次校验所消费配置；非法配置必须返回已登记的明确数字业务错误码，不得抛出 NPE 或未分类 500。
6. 草稿、预览、发布、回滚及对应管理 UI 整体 Deferred 至二期。

### 6.4 新建会话与流式对话

1. 登录用户点击“新聊天”或选择已发布 Agent。
2. 输入 1～20,000 个 Unicode 字符；纯空白不可发送。
3. 首次发送原子创建会话、绑定当前租户、`uid`、Agent 与 Agent 版本，并保存用户消息。
4. 系统按里程碑能力组装 Agent、上下文与已授权能力；所有数据限定当前租户。
5. 模型流式返回内容；页面展示生成状态、文本分片和必要的工具状态。
6. 完成后保存助手消息、用量与允许记录的调用摘要；首轮成功后生成标题。
7. 失败保留用户消息，助手尝试标记失败；重试不得重复创建用户消息或重复执行已成功的非幂等工具。

### 6.5 会话管理

- 列表仅返回当前租户当前用户的未删除会话，按更新时间倒序；默认每页 20 条，最大 100 条。
- 用户可打开、重命名和删除本人会话。
- 自动标题为首条用户消息去换行后的前 40 个 Unicode 字符，最长 60 字符；模型标题失败时使用该规则。
- 用户手动改名后不得被自动标题覆盖。
- 删除需二次确认；成功后立即移出列表，30 天后物理清除。
- 其他租户或其他用户的会话 ID 统一按资源不存在处理。

### 6.6 MCP 与本地 Tool 运行时验收流程

1. DBA/开发人员直接写库维护 Skill 版本、MCP 配置与逐项工具授权、本地 Tool 平台注册与租户授权；M2-min 提供独立配置校验、MCP 连接测试与工具发现等无 UI 后端能力。
2. MCP 凭据只能先经离线加密工具生成 AES-GCM 密文，再由 SQL 写入；数据库、接口、日志与审计均不得出现明文或可逆回显。
3. M3 支持 `streamable_http` 与 `sse` MCP 客户端完整链路。
4. MCP 地址在连接测试、工具发现及**每次调用前**均重新执行 HTTPS 与 SSRF 安全校验，不得依赖写库前人工校验结果。
5. 仅已发现、已启用、当前租户已逐项授权且已绑定 Agent 的工具可进入运行清单；新增发现工具默认禁用。
6. 一期内置本地 Tool 仅为 `datetime_now` 与 `calculator`，均为 `low` 风险且无真实业务副作用；租户只能调用平台预注册且当前已授权的工具。
7. MCP 工具未显式配置 `riskLevel` 时默认按 `high` 处理；高风险确认的生产可达路径由 MCP 工具承载。
8. 工具调用前再次校验租户、Agent 绑定、当前状态、风险等级与用户确认条件；授权拒绝、高风险确认/拒绝均写运行时安全审计。
9. AC-TOL-002 的真实业务副作用验证由内置 Mock MCP 承担，不依赖真实外部凭据；Mock 必须覆盖成功、确认、拒绝、鉴权失败、超时、协议异常、非法地址、工具新增默认禁用与超大结果场景。

### 8.2 租户与站点配置（管理流程 Deferred 至二期）

> 本节描述的创建、编辑、预览、发布与回滚管理能力一期不提供 UI；M3 验收数据由 DBA/开发人员直接写库，并执行第 8.10 节的校验与缓存失效流程。

- 平台管理员可创建租户，填写租户号、名称、主 Host、时区和语言。
- 启用前必须满足 Host 唯一、站点配置已发布、至少一个 Agent 已发布且启用、默认 Agent 合法。
- 站点配置支持草稿预览；预览仅管理角色可访问，10 分钟失效且不得被搜索引擎收录。
- 发布后正常情况下 30 秒内生效。
- 回滚形成新版本，不修改历史记录。
- 开发 Host 映射属于环境级验证配置，生产必须关闭。

### 8.3 认证与成员关系

- Token 唯一身份键为 eyesUser `uid`。
- 当前租户成员关系的关键字段语义为：`tenantId`、`uid BIGINT`、租户内角色、状态、必要资料快照、最近访问时间；`(tenantId, uid)` 唯一。
- 成员身份唯一键固定为 eyesUser `uid`，不以昵称、手机号或邮箱作为身份键。
- 用户资料按业务必要性同步；完整手机号、邮箱、Token 不得进入日志或埋点。
- 头像失败不阻断身份建立。
- SSO Token 非法、过期、账号冻结/不存在/角色非法时，按第 6.2.3 条清理并重登。

### 8.4 Agent 管理（Deferred 至二期）

> 一期仅消费 DBA/开发人员直接写入并通过独立校验的 Agent 版本数据，不提供 Agent 管理 UI。

- 列表信息：名称、唯一 key、当前发布版本、状态、是否默认、绑定能力数量、更新时间、更新人。
- 支持名称搜索、状态筛选，默认按更新时间倒序。
- Agent 信息包含基础信息、模型选择、系统提示、上下文策略、能力绑定和安全策略。
- `agentKey` 在租户内唯一，发布后不可修改；不同租户允许相同 key。
- 复制生成新标识和新 key 草稿，不复制密钥或审计记录。
- 存在历史会话的 Agent 不可删除，只能停用。
- 发布前校验所有绑定资源属于同一租户且状态可用。

### 8.5 Skill 版本与管理

> Skill 不可变版本与 Agent 版本绑定属于 M2-min；一期由 DBA/开发人员直接写库并调用独立校验入口。Skill 管理 UI、草稿与发布操作 Deferred 至二期。

- 信息项：名称、key、描述、指令正文、输入变量、输出约束和版本。
- 指令正文最长 50,000 字符；变量使用 `{{variableName}}`，未声明变量校验失败。
- 发布版本不可修改；Agent 发布时保存 Skill 版本引用。
- Skill 停用后不可被新 Agent 版本绑定；历史静态指令不恢复外部工具权限。

### 8.6 MCP 配置与运行前治理

> MCP 后端配置、连接测试、工具发现与逐项授权属于 M2-min；一期由 DBA/开发人员直接写库并通过接口实测与数据核验，不提供管理 UI。MCP 管理 UI Deferred 至二期。

- 支持 `streamable_http` 与 `sse`；不向租户开放 `stdio`。
- 配置信息包含服务地址、鉴权语义、凭据状态、超时和允许工具清单。
- 服务地址仅允许 HTTPS；授权内网地址必须属于平台允许范围；连接测试、工具发现和每次运行前均重新校验 HTTPS/SSRF。
- 连接测试分类：成功、DNS 失败、TLS 失败、鉴权失败、超时、协议不兼容、无可用工具、SSRF 拒绝。
- 连接成功后发现工具；新增工具默认禁用，DBA/开发人员按租户逐项写入授权。
- 凭据必须由离线工具输出 AES-GCM 密文后写库；任何数据库读取、查询接口、日志或审计不返回明文。
- MCP 输出按不可信内容处理，不得覆盖系统权限或泄露提示词与凭据。

### 8.7 本地 Tool 注册、授权与管理

> 平台注册与租户授权的后端数据能力属于 M2-min；一期由 DBA/开发人员直接写库，不提供 `/platform/*` 或 `/admin/*` 管理 UI。对应管理 UI Deferred 至二期。

- 一期内置本地 Tool 固定为 `datetime_now` 与 `calculator`，二者均为 `low` 风险且不产生真实业务副作用；不得内置 `order_refund` 等无真实业务系统承接的副作用工具。
- 平台管理员作用域维护 Tool 的 key、版本、输入输出约束、风险级别、超时、幂等性和说明。
- 租户作用域只能授权、停用及填写允许的非代码配置。
- 风险等级：`low` 可自动执行；`medium` 按 Agent 策略自动或确认；`high` 每次必须由终端用户确认。MCP 工具缺少合法 `riskLevel` 时默认按 `high` 处理。
- 调用校验租户授权、Agent 绑定、输入约束、超时和结果大小。绑定按本次生成快照生效；授权与资源状态在进入 invoke 前复查。
- 撤权发生在进入 invoke 前时拒绝执行；已进入 invoke 时本次可在既定超时内完成，下一次调用必须拒绝。
- 单次结果默认上限 1 MB，超出截断并标记；默认超时 30 秒，最大 120 秒。

### 8.8 会话与 AI 对话

- 用户可见消息角色为 `user` 与 `assistant`；系统内部和工具消息正文不直接展示。
- 用户消息先显示待确认状态，服务端确认后为已发送，失败时可重试。
- 助手状态：`queued → streaming → completed`，或进入 `stopped/failed`。
- Markdown 必须安全渲染；代码块可复制但不得执行。
- 停止操作后 1 秒内停止前端追加，并保存已生成内容为 `stopped`。
- 重新生成保留旧助手尝试，默认只显示当前尝试；不得重复保存用户消息。
- 模型对话历史超过上下文窗口时，优先保留完整 system 提示、最近消息与未完成工具链；更早内容摘要，摘要失败使用确定性滑动窗口。
- system 提示组装总长受平台配置 `chat.system_prompt_max_chars` 约束，默认 100,000 字符；等于上限允许，超过上限时在模型调用前返回 code=30060，禁止截断任一系统约束后继续生成。
- 消息准入仅在建立 SSE 前执行：QPM 超限返回 code=10005 与 `retryAfterSeconds`；每日额度用尽返回独立 `DAILY_QUOTA_EXHAUSTED` 业务码与额度快照。建流后的生成过程不追加限流判断；详细计数与结算以第 8.11 节为准。
- 无可用 Agent 时禁用输入，传达暂不可用语义；管理角色可进入配置入口。

### 8.9 管理后台通用规则（Deferred 至二期）

- 列表具备加载、空、正常、失败和无权限状态；失败不得展示旧租户数据。
- 未保存表单离开前二次确认。
- 保存草稿不影响线上；发布前二次确认并展示差异摘要。
- 前端隐藏入口不能替代后端权限判断。
- 并发编辑采用版本冲突语义；后提交者可查看差异并重新应用，不得静默覆盖。

### 8.10 M2-min 无 UI 运维规则

1. **独立配置校验**：提供可独立运行的 Agent、Skill、MCP、Tool 校验入口；允许按单对象及其引用链执行。返回每个失败字段、对象标识与明确数字业务错误码，不返回密钥、内部地址或其他租户资源存在性。
2. **运行时兜底**：发送消息、组装 Skill、构造 MCP/Tool 清单及执行工具时再次校验当前配置。非法配置必须在进入模型或工具执行前失败；`/api/v1/**` 返回 HTTP 200 + 已登记数字业务错误码，禁止 NPE、未分类 500 或字符串错误码。
3. **MCP HTTPS/SSRF**：连接测试、工具发现以及每次 MCP 调用前均校验 endpoint；命中非 HTTPS、环回、云元数据、未授权内网、DNS 重绑定或解析结果变化时拒绝。
4. **凭据加密工具**：离线工具输入明文凭据，输出可直接用于 SQL 的 AES-GCM 密文及必要版本标识；标准输出、日志、临时文件和错误信息不得包含明文。相同明文多次加密不得产生可用于比对明文的固定密文。
5. **缓存失效接口**：仅平台管理员可调用；支持按租户/配置类型及必要全局作用域失效 `config_version` 指针、Agent 版本快照、`sys_config` L1/L2。成功后后续请求不得命中旧值；失败必须明确返回未完成的作用域，不得伪报成功。
6. **审计**：工具授权拒绝、高风险工具确认/拒绝、跨租户资源探测、MCP 连接测试、MCP 凭据变更、平台管理员排障票据签发、缓存失效接口调用均写运行时安全审计。
7. **验证限制**：上述能力无管理 UI，验收仅采用单元测试、集成测试、接口实测与数据库数据核验；不得因不存在管理页面判定为漏做。

### 8.11 用户维度对话限流与每日限额（新增）

#### 8.11.1 需求目标与需求编号

本需求在既有发送与流式对话能力上增加「短时防突发 + 每日资源权益」双层控制，目标是：每个租户可独立配置每名用户的 QPM 与每日对话总量；终端用户能在发送动作附近持续看到本人当前租户的今日额度；达到不同限制时得到可执行、可区分的恢复指引。

| 需求 ID | 优先级 | 功能 | 可测试结果 |
|---|---|---|---|
| REQ-LMT-003 | P0 | 用户级 QPM 调整与租户配置分层 | 默认数据库配置为 3 次/分钟；同一用户在不同租户分别计数；命中后沿用 `10005 + retryAfterSeconds` |
| REQ-QUOTA-001 | P0 | 对话次数统一计数口径与幂等结算 | 生成前失败不扣日额度；生成已开始后的完成、停止、断流或失败计一次；同一幂等请求不重复计数 |
| REQ-QUOTA-002 | P0 | 租户日历日限额、重置与隔离 | 默认数据库配置为 50 次/日；按租户时区零点重置；租户、用户之间互不占用 |
| REQ-QUOTA-003 | P1 | 当前用户每日额度查询与发送链路同步 | 页面初始、发送结算、额度拒绝及恢复前台时均能得到当前租户权威快照 |
| REQ-QUOTA-004 | P1 | 对话输入区额度展示与用尽状态 | 展示剩余、已用/总量及重置时间；用尽后保留输入和草稿、禁用发送并给出恢复指引 |
| REQ-QUOTA-005 | P0 | 平台默认与租户覆盖配置 | 平台数据库默认可被租户独立覆盖；缺失/非法配置不得以代码常量兜底 |

**与既有需求的关系：**

1. `REQ-CHAT-001` 继续定义文本发送与流式响应；本需求在模型生成前增加 QPM/日限额准入，在结算后同步额度，不改变消息正文与流式内容契约。
2. `REQ-CHAT-002` 继续定义停止、重试、重新生成及不得重复创建用户消息；`REQ-QUOTA-001` 补充这些动作是否产生新的日额度计数。
3. `REQ-LMT-003` 是对已交付 `REQ-LMT-001` 的业务变更：分钟默认值由平台数据库 30 调整为平台数据库默认 3，并支持租户覆盖；仍只在建立 SSE 前拒绝，不恢复已 Deferred 的 SSE 流内限流。
4. 现有 120 次/小时规则在 50 次/日下不会先触发，且会形成第三种等待语义，故自本需求生效时废弃。`REQ-LMT-001` 中“120 次/小时”旧口径由本节替代；历史实现与验收记录保留，不作为新需求验收基线。
5. 本需求不改变 `Idempotency-Key` 的消息幂等约束，也不允许以额度机制重复创建用户消息或重复执行已成功的非幂等工具。

#### 8.11.2 「一次对话」的计数口径

**产品裁决：每日额度按“已开始消耗生成资源的一次有效生成尝试”计数，而不是按请求进入或完整回答成功计数。**

1. 请求须先通过登录身份、租户成员、会话归属、输入参数、幂等、QPM、日额度可用性、Agent 状态及运行配置校验。未通过上述校验的请求不产生一次日额度用量。
2. 对通过校验的请求，在首次模型生成调用前占用一份可用额度，以保证多标签页和并发请求不会共同突破日上限。占用不等于最终扣减；最终按以下规则结算。
3. 出现任一“资源已消耗证据”即结算为一次：产生任意助手文本分片；产生模型发起的工具调用；上游返回可归属于本次尝试的 token 用量；或系统已确认模型生成实际开始且无法撤销资源消耗。
4. 在任何资源已消耗证据出现前失败，释放本次占用，不计日额度。包括：本地 `50003` 且模型未调用、上游请求被 400 拒绝、配置校验失败、SSE 在模型开始前断开。
5. 资源消耗开始后的正常完成、模型错误、SSE 断流均计一次；已产生部分内容后用户主动停止生成也计一次。原因是用户已获得部分输出且系统已经消耗生成资源。
6. 相同 `Idempotency-Key` 的请求重放属于同一生成尝试：返回原尝试及其额度结算结果，不重复占用、不重复扣减。幂等键不得跨租户、跨用户复用结果。
7. 用户明确点击“重试”或“重新生成”会创建新的助手生成尝试；若新尝试达到资源消耗边界则再次计一次，但仍不得重复创建对应用户消息。若新尝试在资源消耗前失败则不计。
8. QPM 统计的是通过前置身份、归属和参数校验后发起的非重复发送/生成尝试，用于抑制瞬时请求；即使随后在模型开始前失败，本次仍占当前分钟请求次数，但不占日额度。两类计数可能不同，这是“请求频率控制”与“已消耗资源限额”的必要差异。

该口径采用“按已消耗资源计日额度”，避免把参数错误或上游直接拒绝转嫁给用户，也避免通过反复停止、断流或重新生成规避额度。

#### 8.11.3 QPM 与日限额的独立语义

| 维度 | QPM 限流 | 每日对话限额 |
|---|---|---|
| 目的 | 防止单用户短时间突发请求 | 控制单用户在一个租户日历日内的生成资源总量 |
| 默认数据库配置 | 3 次/分钟 | 50 次/日 |
| 恢复条件 | 当前固定分钟窗结束 | 当前租户日历日结束 |
| 用户感知 | 稍等若干秒即可继续 | 今日额度已用完，等待明日零点或联系租户管理员调整租户额度 |
| 错误语义 | 沿用 `10005 RATE_LIMITED` | 使用独立业务错误 `DAILY_QUOTA_EXHAUSTED`，数字 code 由 @架构师在业务段登记 |
| 响应关键数据 | `retryAfterSeconds` | 当前额度快照、`resetsAt`、`timezone` |
| 前端状态 | 临时禁用发送并倒计时，结束后不自动重发 | 禁用发送直至权威额度恢复；不显示秒级倒计时 |

不得用 `10005` 表达每日限额。两者引导和恢复条件完全不同，复用会导致现有 `rateLimitStore` 将“明日重置”误表现为秒级倒计时。

**同时命中时的产品优先级**：若请求开始时每日额度已用尽，优先返回 `DAILY_QUOTA_EXHAUSTED`，不再新增本次 QPM 计数，也不启动秒级倒计时；若日额度可用但 QPM 超限，则返回 `10005`，且不得占用或扣减日额度。该优先级确保用户先看到持续时间更长且真正阻断发送的原因。具体校验与预占的原子执行顺序由 @架构师设计，但对外结果必须符合上述规则。

#### 8.11.4 日限额重置与租户时区

1. 一个额度日按当前租户 `timezone` 对应的当地日历日计算，从当地 00:00（含）至下一当地 00:00（不含）。数据库时间仍统一存 UTC。
2. 时区来源固定复用租户基础信息中现有必填 IANA `timezone`，不新增重复配置项。UTC 零点方案会使中国租户在 08:00 重置，与“今日额度”语义冲突，故不采用。
3. 夏令时切换日可能为 23 或 25 小时，仍以该 IANA 时区的相邻两个当地零点为边界，不以固定 24 小时滚动窗口代替。
4. 用户界面按租户时区表达“今日额度”和“明日 00:00 重置”；接口中的 `resetsAt` 为下一重置点的 UTC 绝对时间，同时返回 `timezone` 供正确展示。不得仅由浏览器个人时区推算。
5. 租户时区发生变更时，变更生效后的新请求按新时区所属日历日判定；不得合并、复制或补发旧时区已消耗额度。时区变更属于租户治理动作，须遵循租户配置变更规则。

#### 8.11.5 配置分层与生效规则

采用“平台数据库默认 + 租户级覆盖”两层规则，不要求每个租户重复显式配置。平台默认保证新租户可用，租户覆盖满足独立额度要求。

| 字段语义 | 类型/约束 | 平台默认 | 作用域与规则 |
|---|---|---:|---|
| scope | enum | platform | `platform/tenant`；租户配置必须明确归属当前 `tenantId` |
| qpmEnabled | boolean | true | false 时不执行 QPM；不影响日限额 |
| qpmLimit | integer，≥1 | 3 | `qpmEnabled=true` 时必填；数据库值，禁止代码默认 |
| dailyQuotaEnabled | boolean | true | false 时该租户用户不受每日次数限制，前端显示“不限量”语义 |
| dailyQuotaLimit | integer，≥1 | 50 | `dailyQuotaEnabled=true` 时必填；数据库值，禁止代码默认 |
| effectiveAt | datetime | 配置创建时 | UTC 保存；到达后仅影响新发起尝试，不追溯改写历史结算 |
| version/updatedAt | 版本/时间 | 系统生成 | 用于识别配置变化和避免静默覆盖 |

1. 租户某字段存在有效覆盖时使用覆盖值；未配置覆盖时继承平台默认。租户覆盖可以只覆盖 QPM 或只覆盖日限额，其余字段继承平台值。
2. 平台默认配置缺失、类型错误或越界时不得回退到代码中的 3/50；服务必须拒绝以不受控阈值提供对话，并给出配置异常语义。租户覆盖“未配置”可继承；“已配置但非法”不得静默继承，以免掩盖误配置。
3. 配置到达 `effectiveAt` 后，对新尝试立即生效。降低日限额至小于或等于当日已用量时，用户立即进入用尽状态；提高后按新总量恢复相应剩余次数。历史已用次数不重算、不清零。
4. QPM 配置变化对生效后的新尝试使用当前有效阈值及当前分钟已记录次数；不得因修改配置清空已发生的分钟请求记录。
5. 本需求只定义字段语义、继承与生效规则，不指定表结构、缓存层次、Redis/数据库一致性或配置读取实现。

#### 8.11.6 前端展示与同步规格

1. **展示位置**：每日额度属于发送前决策信息，必须出现在首页与会话详情共用的消息输入 Composer 状态区域、靠近发送操作；不得仅藏在顶栏、侧栏或用户菜单。具体尺寸、排版、色值和视觉组件由 @UI 裁决。
2. **展示内容**：启用限额时至少传达“今日剩余 N 次”“已用 U / 总量 L”“明日 00:00（租户时区）重置”；不限量时传达“今日对话不限量”，不得伪造数值上限。
3. **初始获取**：登录用户进入对话页或切换到另一租户 Host 时，通过新的受保护“当前用户对话额度”接口获取权威快照。不得复用匿名可访问的 `/api/v1/site/config` 下发个人剩余额度。
4. **实时更新**：生成尝试完成日额度结算后，通过当前发送/流式响应链路下发最新额度快照；日限额拒绝响应也携带同形快照。详细 SSE 事件复用或扩展方式由 @架构师裁决，但前端不得只依赖本地自减作为最终事实。
5. **校准时机**：页面重新加载、浏览器标签页恢复前台、额度状态不确定、已到 `resetsAt`、身份或租户变化时重新查询。租户/用户变化时先清除旧快照，禁止短暂显示上一主体数据。
6. **加载/失败状态**：额度加载时需有加载语义；查询失败时显示“额度暂不可用”及可重试语义，不展示旧租户数据。单纯展示接口失败不应清空草稿；发送接口仍由后端作最终准入并返回真实结果。
7. **QPM 命中**：保留草稿，只临时禁用发送；展示“发送太频繁，请 N 秒后重试”，倒计时结束恢复发送但不自动重发。与现有 `rateLimitStore` 和 Composer 内联提示协调，不新增打断式弹窗。
8. **日额度用尽**：输入框仍可编辑并保留草稿，发送按钮及 Enter 发送禁用；持续传达“今日对话额度已用完，将于明日 00:00（{timezone}）重置。如需提高额度，请联系当前租户管理员”。不得允许点击后才反复报错，也不得禁用复制、编辑或对进行中回答的停止操作。
9. **匿名用户**：不请求、不显示个人额度；匿名仍不可发送，触发现有 SSO 流程。登录成功回原页后再加载当前租户额度。
10. **可访问性**：额度变化、限流恢复和用尽状态需以可被辅助技术识别且不过度重复播报的方式传达；不得只用颜色表达。

#### 8.11.7 当前用户额度信息项

| 信息项 ID | 名称 | 类型 | 数据来源/含义 | 约束与空值语义 | 可见权限 |
|---|---|---|---|---|---|
| F-QUOTA-001 | enabled | boolean | 当前租户每日限额是否启用 | false 时数值额度为空并显示不限量 | 当前登录用户本人 |
| F-QUOTA-002 | limit | integer/null | 当前有效日总量 | 启用时 ≥1；禁用时 null | 当前登录用户本人 |
| F-QUOTA-003 | used | integer | 当前租户日已结算次数 | 0～limit；并发结算期间不得返回负数 | 当前登录用户本人 |
| F-QUOTA-004 | remaining | integer/null | `max(limit-used, 0)` | 启用时不小于 0；禁用时 null | 当前登录用户本人 |
| F-QUOTA-005 | status | enum | `available/exhausted/unlimited` | 与 enabled、remaining 一致 | 当前登录用户本人 |
| F-QUOTA-006 | periodStart | datetime | 当前租户额度日开始点 | UTC 绝对时间 | 当前登录用户本人 |
| F-QUOTA-007 | resetsAt | datetime | 下一租户当地零点 | UTC 绝对时间，必须晚于 periodStart | 当前登录用户本人 |
| F-QUOTA-008 | timezone | string | 当前租户 IANA 时区 | 必须与租户上下文一致 | 当前登录用户本人 |
| F-QUOTA-009 | asOf | datetime | 快照计算时间 | UTC，用于识别陈旧状态 | 当前登录用户本人 |

额度快照是受保护的个人运行数据。接口必须只按可信 Host 确定的当前租户和认证上下文中的当前 `uid` 查询，不接受客户端传入 `tenantId` 或目标 `uid`；任何缓存、日志、指标和错误响应均不得返回其他用户或其他租户的额度。额度值本身不是消息正文级敏感内容，但仍属于个人使用数据，禁止跨主体披露。

#### 8.11.8 错误、文案语义与观测

| 场景 | 错误语义 | 必要数据 | 用户文案语义 | 后续动作 |
|---|---|---|---|---|
| QPM 超限 | `10005 RATE_LIMITED` | `retryAfterSeconds ≥ 1` | “发送太频繁，请 N 秒后重试” | 倒计时后恢复，不自动发送 |
| 每日额度用尽 | `DAILY_QUOTA_EXHAUSTED`，独立 30000 段数字码待 @架构师登记 | 完整额度快照，remaining=0 | “今日对话额度已用完，将于明日 00:00（租户时区）重置。如需提高额度，请联系当前租户管理员” | 等待重置或管理员调整租户配置 |
| 配置缺失/非法 | 复用已登记运行配置异常语义或由 @架构师裁决登记 | 不返回内部配置内容 | “对话额度配置异常，请联系管理员” | 禁止以代码值兜底发送 |
| 额度查询失败 | 系统/依赖错误语义 | 不返回旧主体快照 | “额度暂不可用，请重试” | 允许重新查询，保留草稿 |

**审计与埋点裁决：**

1. QPM 命中、每日额度命中和普通次数结算是高频运行事件，不新增安全审计 action，不逐次写入现有安全审计流，避免把资源治理事件误标为安全管理事件。
2. 本需求新增或调整的运行指标/埋点不得包含消息正文、系统提示、Skill 正文、工具输入输出、Token、完整手机号/邮箱；只允许租户、脱敏用户标识、结果分类、有效阈值、剩余量、发生时间等必要字段。
3. 租户额度配置变更属于管理治理动作，但当前管理后台和管理操作审计仍为 Deferred，配置继续由 DBA/开发人员按既有受控改库流程维护。本需求一期不虚构不存在的管理接口或新增应用审计 action；二期产品化配置入口时必须纳入管理操作审计。

#### 8.11.9 一期明确不做

| 不做项 | 理由 |
|---|---|
| 用户级白名单、个人加额或个人独立 QPM | 原始需求只要求租户独立；个人权益会引入授权人、有效期、覆盖优先级和公平性规则，当前没有明确用户价值场景 |
| 小时窗口限流 | 120 次/小时高于 50 次/日，不会先触发；保留只会增加无独立价值的第三种等待语义 |
| 额度购买、套餐、赠送、转移、跨日结转 | 属于商业化权益系统，与本需求的资源治理定位不同 |
| 按用户个人时区重置 | 项目没有可信用户时区来源，且会破坏租户统一的“今日”统计口径 |
| 租户管理员查看单个用户用量页面 | 本需求只要求终端用户查看本人额度；管理后台仍为 Deferred，个人用量查询还需要独立权限与隐私目的定义 |
| SSE 建流后的中途限流 | 本需求只调整建流前 QPM 与日限额准入；`REQ-LMT-002` 继续保持 Deferred，不改变已建立流的生成行为 |
| 对每次超限写安全审计 | 超限是高频资源治理事件而非安全管理动作，使用脱敏运行观测更符合审计边界 |

## 10. 状态与枚举

### 10.1 租户状态

| 状态 | 进入条件 | 可执行操作 | 对外行为 |
|---|---|---|---|
| draft | 创建后默认 | 编辑、配置、校验、启用 | 站点级 404 |
| enabled | 启用校验通过 | 正常使用、暂停 | 正常服务 |
| suspended | 平台管理员暂停 | 查看、整改、恢复 | 站点级 403 |
| archived | 终止且完成数据处置 | 仅平台审计查看 | 站点级 404，不可恢复 |

### 10.2 配置状态

`draft → published → archived`

- `draft`：可编辑，不影响线上。
- `published`：不可变，可供线上使用；仅一个当前版本。
- `archived`：不可用于新绑定，只保留审计与历史引用。

### 10.3 Agent 运行状态

| 状态 | 业务行为 |
|---|---|
| enabled | 有发布版本，允许新建和继续对话 |
| disabled | 不允许新建或继续对话，历史只读 |
| deleted | 仅无引用草稿可软删除，不向终端展示 |

### 10.4 会话状态

| 状态 | 进入条件 | 退出条件 |
|---|---|---|
| active | 首条用户消息保存成功 | 删除或 Agent 停用/归档 |
| readOnly | Agent 停用/归档 | Agent 恢复时可回 active；不可恢复则保持只读 |
| deleted | 用户确认删除 | 30 天后物理清除 |

### 10.5 其他状态

- 助手消息：`queued/streaming/completed/stopped/failed`
- 工具调用：`pending/awaitingConfirmation/running/succeeded/failed/timedOut/cancelled/denied`
- MCP 健康：`unchecked/healthy/unhealthy`
- 租户成员：`active/disabled`

## 13. 产品级接口约定

> 详细接口、请求字段、流式事件与错误码最终登记表由 @架构设计师维护在 `docs/api-spec.md`。本章只定义产品行为基线。

### 13.1 路由概要

| 方法 | 路径 | 用途 | 权限语义 |
|---|---|---|---|
| GET | `/api/v1/site/config` | 当前租户公开站点配置 | `NO` |
| GET | `/api/v1/agents` | 当前租户可用 Agent | `NO`，不返回敏感字段 |

| POST | `/api/v1/conversations/{id}/messages` | 发送消息并建立流式响应 | `USER` + 本人 |
| POST | `/api/v1/messages/{id}/stop` | 停止生成 | `USER` + 本人 |
| POST | `/api/v1/messages/{id}/regenerate` | 重新生成 | `USER` + 本人 |

| POST | M2-min MCP 连接测试/工具发现 API（路径由架构契约定义） | 无 UI 的连接测试、工具发现与逐项授权校验 | `USER` + `@TenantRole` |

| 多方法 | `/api/v1/admin/**` 管理 API | 二期租户管理能力；一期不提供对应页面 | `USER` + 本地租户角色 |
| 多方法 | 平台管理 API | 二期平台管理能力；一期仅保留 M2-min 后端接口 | `ADMIN` + 受控访问规则 |

**认证入口裁决：**

- 登录、注册与鉴权失效均由前端整页跳转耶瞳 SSO。
- 授权 Token 由原业务页面接收、保存并立即从 URL 清除。
- 退出仅清除前端 Token 后整页跳转耶瞳 SSO。
- 产品不提供站内认证中转页面或认证辅助业务接口。

### 13.2 统一响应格式

所有 `/api/v1/**` 业务接口，无论成功或业务失败，一律返回 HTTP 200。业务结果由响应体表达：

```json
{
  "code": 0,
  "message": "success",
  "data": null,
  "timestamp": 1704067200000
}
```

规则：

1. `code=0` 是唯一成功值。
2. 所有响应必须包含服务端毫秒时间戳 `timestamp`。
3. 分页统一为 `data: { list, total, page, pageSize }`。
4. 对外 JSON 字段统一 camelCase。
5. 禁止用 HTTP 201/400/401/403/404/409/429/500/503 表达 `/api/v1/**` 的业务语义。
6. **唯一边界例外**：未知 Host 404 页、租户暂停 403 页、无可用配置 503 页属于站点级页面响应，不属于 `/api/v1/**` 业务接口，可保留非 200。
7. 已建立的流式响应须以架构契约定义的业务事件传达最终成功或错误；业务码仍遵循本章分段，不得自定义字符串码。

`20000~20999` 为耶瞳 SSO 保留段，业务严禁占用。前端对 `20000~20005` 执行清 Token + SSO 整页跳转；最终错误码登记表由 @架构设计师维护于 `docs/api-spec.md`。

## 14. 非功能需求

### 14.1 安全

1. 生产全站 HTTPS 并启用 HSTS；Token 仅存于 `localStorage.authorization`，仅通过 Header `authorization` 传输。
2. SSO 回跳后必须立即用 `history.replaceState` 从 URL 清除 Token；Token 不得出现在 URL、日志、埋点、审计、错误信息或页面中。
3. 本项目鉴权不依赖 Cookie，因而不以 Cookie 自动携带身份，不存在传统 Cookie 会话型 CSRF 风险；仍须防止任何新增能力绕过 Header 鉴权规则。
4. `localStorage` Token 面临 XSS 风险；所有可展示内容、Markdown、配置文案和外部工具结果必须经过安全处理，禁止脚本、事件属性和危险 URL。
5. MCP endpoint 必须防 SSRF，禁止云元数据地址、环回地址和未授权内网地址；连接测试、工具发现及每次实际调用前均重新校验 HTTPS、解析结果与目标地址。
6. MCP 凭据必须使用 AES-GCM 加密入库；仅允许离线加密工具接收明文并输出供 SQL 使用的密文，数据库查询、页面、接口、标准输出日志与审计均不得返回明文。
7. 每次请求重新校验租户上下文和权限，不依赖前端角色或租户传值；M3 新增接口必须全部纳入 `@TenantRole` 或平台管理员后端准入。
8. Agent/Skill/MCP/Tool 在独立入口与运行时均校验配置合法性；非法配置使用 code=30060 失败，禁止 NPE 或未分类 500。
9. 缓存失效接口仅平台管理员可调用，调用结果与作用域必须写运行时安全审计。
10. 上线前必须通过跨租户 ID 枚举、缓存污染、Host 伪造、水平越权、开放重定向、XSS、Token URL/日志泄露、SSRF 测试。
11. 开发 Host 映射生产关闭为上线阻断项。

### 14.2 性能与容量

- 租户识别与配置读取 P95 ≤20ms。
- 非 AI 管理/查询接口 P95 ≤500ms，P99 ≤1s。
- AI 首字响应 P95 ≤5s；停止生成前端反馈 ≤1s。
- 会话列表首屏 P95 ≤1s。
- 容量基线：单租户 10 万用户、100 万会话、1000 万消息；扩容不得改变隔离语义。
- 分页使用稳定排序，禁止无界查询和全量无约束导出。

### 14.3 可用性与一致性

- 核心服务月可用性目标 ≥99.9%。
- 配置发布原子切换，失败继续使用上一版本。
- 消息保存具备幂等语义；模型或工具失败不破坏已保存用户消息。
- 外部服务故障不得扩散到其他租户或其他 Agent。
- `auth-type=1` Token 续期回写失败不得导致请求风暴。

### 14.4 兼容性与可访问性

- 支持 Chrome、Edge、Safari 最新两个大版本。
- 支持桌面、平板与移动端核心流程；具体断点和布局由 UI 定义。
- 关键操作可通过键盘完成；焦点可见；图标按钮有无障碍名称。
- 对比度满足 WCAG 2.1 AA，不只用颜色表达状态。
- 流式更新不抢夺屏幕阅读器焦点。

### 14.5 数据保留与删除

- 用户会话：用户删除后软删除 30 天，再物理清除。
- 运行日志：默认保留 30 天并脱敏。
- 审计日志：默认保留 180 天，不随业务对象删除。
- 模型用量与工具摘要：默认保留 180 天，不保存不必要正文副本。
- Token：只保留于浏览器当前本地存储，不进入业务数据留存体系。

## 15. 审计与埋点

### 15.1 审计事件

**一期 M2-min 运行时安全事件审计范围**：工具授权被拒、高风险工具用户确认、高风险工具用户拒绝、跨租户资源探测、MCP 连接测试、MCP 凭据变更、平台管理员排障票据签发、缓存失效接口调用。上述事件必须记录成功、失败或拒绝结果；安全动作应审计而审计失败时按 EX-024 失败关闭。

**二期 Deferred 管理操作审计范围**：租户创建/启停/归档、Host 变更、站点配置发布/回滚、Agent/Skill 发布与停用、MCP 创建与工具授权、本地 Tool 注册与授权、成员角色变更、成员禁用、审计导出及其他管理后台操作。二期补做，不得因一期未实现而标记为 Cancelled。

| 字段 | 语义 |
|---|---|
| eventId | 全局唯一事件标识 |
| tenantId/scope | 租户事件必填 tenantId；平台事件显式标记 platform |
| requestId | 请求链路标识 |
| actorType/actorId | 操作者类型与脱敏标识 |
| action | 标准动作枚举 |
| objectType/objectId | 被操作对象 |
| beforeDigest/afterDigest | 变更前后摘要；敏感值只记录是否变化 |
| result | `success/failed/denied` |
| reason/errorCode | 操作原因或失败分类 |
| ip/userAgent | 按隐私规则脱敏 |
| occurredAt | UTC 时间 |

|---|---|---|
| tenantSiteView | 站点成功加载 | tenantId、configVersion、loginState |

**隐私优先配置规则：**

1. `analytics_enabled` 或 `analytics_sample_rate` 缺失、不可解析、类型错误或越界时，运行期必须 fail-closed：全部埋点计为丢弃，不得回退为全量采集。
2. 启动阶段可将上述必填配置错误作为启动失败处理；运行期检测到异常时还必须告警。运营接受配置误删期间形成数据缺口，禁止以“保证报表连续”为由采集未经明确授权的数据。
3. 一期用量接口的 `rateLimitedCount` 固定如实返回 0，因为限流仅在 Redis 计数且发生在建消息/埋点之前；不得根据请求量估算或伪造。
4. 二期由后端在限流拒绝点侧写白名单事件 `messageRateLimited` 至 `analytics_events`，作为 `rateLimitedCount` 的唯一权威数据源；不采用前端上报。侧写失败不得改变既有限流结果，且配置异常时仍遵循 fail-closed。

8. **AC-CHAT-007**：每次 Skill/MCP/Tool 调用均校验租户授权、当前状态、配置合法性与风险确认；Agent 能力绑定按生成开始时快照确定，解绑下一次提问生效；进入 invoke 前撤权必须拒绝，进入 invoke 后的本次可在本地毫秒级或 MCP 30 秒超时内完成，后续调用拒绝；调用摘要可追溯。
9. **AC-CHAT-008**：system 提示组装总长小于或等于 `chat.system_prompt_max_chars` 时完整进入模型；默认上限 100,000 字符，超出 1 字符即在模型调用前以 code=30060 拒绝，且不得截断任何片段后放行。
10. **AC-OBS-001**：埋点包含租户维度，不含正文、凭据和 Token；开关与采样率合法时按配置采集。
11. **AC-OBS-002**：`analytics_enabled`、`analytics_sample_rate` 缺失、不可解析或越界时，运行期 `accepted=0` 且全部丢弃，不得 fail-open 全量采集；主对话和 SSE 不因埋点写入失败而失败。
12. **AC-OBS-003**：一期用量接口 series 与 total 的 `rateLimitedCount` 均固定返回 0 且无伪造事件；二期由后端限流拒绝点侧写 `messageRateLimited` 后，才按服务端权威事件聚合非零值。
13. **AC-LMT-001**：历史 M3 基线为单用户单租户 30 次/分钟、120 次/小时；自新增需求交付后由 AC-LMT-003 与 AC-QUOTA-* 替代，历史测试结论保留但不作为当前阈值验收标准。

### 16.5 用户维度限流与每日限额（新增）

1. **AC-LMT-003**：平台数据库默认 QPM 配置为 3 且租户无覆盖时，同一 `tenantId + uid` 在一个固定分钟窗内前三次有效生成请求可继续，第 4 次在建立 SSE 前返回 HTTP 200、code=10005、`retryAfterSeconds≥1`；不调用模型。等待服务端给出的时间后可再次发送，前端不自动重发。
2. **AC-LMT-004**：gift 将 QPM 覆盖为 5、redbook 继承平台默认 3 时，同一 uid 在 gift 第 4 次仍可发送，在 redbook 第 4 次被限流；任一租户的请求不改变另一租户分钟计数。
3. **AC-LMT-005**：新规则生效后不存在小时窗业务拒绝；在未命中 QPM 且日额度可用时，不因历史 `ratelimit.message_per_hour=120` 产生拒绝。建流后仍不追加 QPM 或日限额中途拒绝。
4. **AC-QUOTA-001**：平台数据库默认每日限额为 50 且租户无覆盖时，同一租户同一 uid 前 50 次达到生成资源消耗边界的尝试均结算成功；第 51 次在模型调用前返回 HTTP 200、独立 `DAILY_QUOTA_EXHAUSTED` 数字业务码，快照为 `used=50, limit=50, remaining=0, status=exhausted`，且不调用模型。
5. **AC-QUOTA-002**：同一 uid 在 gift 已用 50 次后，gift 第 51 次被拒绝；redbook 仍按自身配置和用量可发送。额度查询、拒绝响应、缓存、日志及页面均不返回另一租户快照。
6. **AC-QUOTA-003**：在租户 `Asia/Shanghai` 时区，当地 23:59:59 前达到 50 次后为用尽；跨至次日 00:00 后新尝试可用，快照切换到新的 `periodStart/resetsAt` 且已用量从新日计算。再以包含夏令时切换的 IANA 时区验证相邻当地零点边界，不以固定 24 小时替代。
7. **AC-QUOTA-004**：本地 `50003` 且模型未调用、上游在开始生成前返回 400、SSE 在模型开始前断开时，日额度占用被释放且 `used` 不增加；对应请求已经通过频率准入时，其 QPM 次数不回退。
8. **AC-QUOTA-005**：模型已经产生助手文本、工具调用、可归属 token 用量或其他生成开始证据后，无论最终 completed、模型报错、SSE 断流，日 `used` 均增加 1，消息状态按真实结果保存。
9. **AC-QUOTA-006**：用户在已产生部分内容后主动停止，助手消息保存为 stopped 且日 `used` 增加 1；如在任何生成资源消耗前成功取消，则释放占用、不增加 `used`。
10. **AC-QUOTA-007**：使用相同 `Idempotency-Key` 重放同一发送请求 2 次及以上，只产生一个用户消息、一个生成尝试和至多一次日额度结算；响应返回同一结算结果。不同租户或不同 uid 使用相同键不得命中该结果。
11. **AC-QUOTA-008**：点击失败重试或重新生成时不重复创建用户消息；每个新的助手生成尝试若达到资源消耗边界各增加 1 次，生成前失败的尝试不增加。旧助手尝试保留并可追溯。
12. **AC-QUOTA-009**：当仅剩 1 次额度时并发发起至少 2 个有效请求，最多 1 个请求取得生成资格，其余返回用尽；最终 `remaining=0`、`used≤limit`，不存在负数剩余或超额生成。
13. **AC-QUOTA-010**：登录用户进入首页和会话详情时，Composer 附近展示当前租户的“剩余、已用/总量、重置时间”；页面初次加载从受保护接口获取，生成结算后通过发送链路更新，页面恢复前台或到达 resetsAt 后重新查询并与权威快照一致。
14. **AC-QUOTA-011**：额度用尽后输入框仍可编辑、草稿保留，发送按钮与 Enter 发送禁用；页面持续展示明日租户零点重置和联系当前租户管理员语义。停止生成、复制和编辑不被禁用；管理员上调额度并生效后，重新查询恢复发送。
15. **AC-QUOTA-012**：QPM 命中时沿用现有 Composer 内联倒计时，文案语义为“发送太频繁，请 N 秒后重试”；日限额命中不进入该倒计时 store，文案语义为“今日额度已用完，明日 00:00（租户时区）重置”。构造两者同时满足拒绝条件时，只返回日限额错误，不增加本次 QPM 计数；日额度可用但 QPM 超限时不占用日额度。
16. **AC-QUOTA-013**：匿名用户不调用个人额度接口、不显示额度数值，发送仍进入现有 SSO；登录回原租户后才加载额度。同一浏览器从 gift 切换 redbook 或切换用户时，旧额度快照在新主体数据返回前已清除。
17. **AC-QUOTA-014**：平台数据库默认 QPM/日限额配置缺失、不可解析或越界时，系统不得使用代码中的 3/50 继续生成；租户覆盖非法时不得静默继承平台值。错误响应不泄露表名、键名、内部值或其他租户信息。
18. **AC-QUOTA-015**：租户分别覆盖 QPM、日限额、启停或生效时间时，只影响该租户生效后的新尝试；降低日限额至不高于已用量立即显示 exhausted，提高后按新总量恢复，历史 `used` 不被重算或清零。
19. **AC-QUOTA-016**：额度相关接口只依据可信 Host 和认证 uid，构造 `tenantId`/目标 `uid` 参数、跨租户会话 ID 或缓存探测均无法读取他人额度；响应与观测不含消息正文、Token、系统提示、Skill 正文和工具输入输出。

### 16.6 非功能验收

1. **AC-NFR-001**：达到第 14 章性能目标，压力测试期间跨租户泄露为 0。
2. **AC-NFR-002**：通过 Host 伪造、水平越权、缓存污染、开放重定向、XSS、Token URL/日志泄露、SSRF 安全测试。
3. **AC-NFR-003**：桌面、平板、移动端及目标浏览器完成兼容性验收。
4. **AC-NFR-004**：未知 Host 404、租户暂停 403、配置异常 503 仅用于站点级页面；业务 API 无违规非 200。

**里程碑通过条件**：M3 必须同时覆盖全部 M2-min 与 M3 REQ，关联验收项无失败，P0/P1 安全与异常场景通过，不存在未处理高危安全问题，并由六位专家完成签署。M2 Deferred 条目不计入一期 M3 缺陷或通过率，待二期恢复后独立验收与签署。

### 19.2 给 @架构师的需求交底摘要

@架构师 📋 架构审查请求
- **待审查内容**：第 8.11、12、13、16.5、17.2 章及 `docs/requirements.md` 中 REQ-LMT-003、REQ-QUOTA-001～005。
- **审查要点**：计数边界是否能原子落地；平台默认与租户覆盖是否彻底脱离平台 `sys_config` 单作用域限制；租户时区跨日与 DST；接口/SSE 快照；并发、幂等、隐私与故障恢复。
- **紧迫程度**：P0

**硬业务规则，不可因技术实现调整：**

1. 计数主体固定为可信 Host 对应 `tenantId + 当前 uid`，跨租户、跨用户绝不共享配置、计数或快照。
2. QPM 和日限额独立；QPM 使用 `10005 + retryAfterSeconds`，日限额使用独立业务码与 `resetsAt`，小时窗废弃。
3. 数据库平台默认 QPM=3、日限额=50；租户可覆盖。代码不得硬编码业务默认值，缺失/非法配置不得静默兜底。
4. 日额度按租户 IANA 时区当地零点重置，不得改成 UTC 零点或固定 24 小时窗口。
5. 日额度按“已开始消耗生成资源的有效生成尝试”结算：生成前失败释放；开始后的完成、停止、断流、失败均计；同幂等键不重复；主动重试/重新生成是新尝试。
6. 并发下不得超出剩余额度、不得重复扣减、不得出现负数 remaining。
7. 登录用户在 Composer 附近看到剩余、已用/总量、重置时间；用尽保留输入和草稿但禁用发送；匿名不显示个人额度。
8. 额度接口只返回当前租户当前用户数据；日志、埋点和审计不得记录消息正文、Token、提示词或工具输入输出。

**留给 @架构师裁决的技术选择：**

1. 新表、新配置分层或其他数据模型的具体结构、索引与迁移方式。
2. QPM 使用 Redis 的具体窗口实现，以及日额度用量由数据库、Redis 或组合机制承载的职责划分。
3. 预占、释放、结算状态机及其事务/原子性、宕机恢复、对账和缓存一致性方案。
4. 生成资源消耗证据在现有模型/SSE 链路中的可靠识别点。
5. 当前用户额度接口的最终路径、响应 schema，以及发送 JSON/SSE 如何携带最新快照。
6. 租户时区到 UTC 边界的库与实现方式、配置变更后的缓存传播方式。
7. `DAILY_QUOTA_EXHAUSTED` 的具体 30000 段数字码；不得使用 20000～20999 或复用 10005。
