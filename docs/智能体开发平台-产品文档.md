## 1. 产品概述

### 1.0 文档目的与阅读方式

本文档以当前可交互原型为产品基线，完整描述 albedo 的产品目标、信息架构、页面功能、字段规则、状态流转、运行时行为、安全要求、日志规范和验收标准。

- 产品与设计人员：重点阅读第 1～5 章，确认用户场景、页面结构与交互闭环；界面视觉基线见 `docs/原型截图索引.md`。
- 研发人员：重点阅读第 3～8 章，确认数据关系、接口、状态约束、安全与日志要求。
- 测试人员：重点阅读各模块的「规则与验收」以及第 12 章验收清单。
- 运维或平台维护者：重点阅读第 7～10 章，确认日志、密钥、存储与非功能要求。

文档中的功能分为两类：

- **原型已体现**：当前原型中已有页面、字段或交互，可直接操作验证。
- **产品化要求**：由原型设计自然推导出的后端校验、异常处理、安全或性能要求，正式实现时必须补齐，但原型可能仅以静态数据或模拟反馈展示。

### 1.1 产品名称
**albedo**（中文可简称「智能体开发平台」）

### 1.2 产品定位
albedo 是一个面向 **个人用户** 的 **智能体（Agent）开发与使用平台**，定位于「个人 AI 能力工作台」。它将大语言模型、外部工具（MCP）、自定义技能（Skills）、内置工具等异构能力进行统一接入与标准化封装，使用户无需编写代码即可完成智能体的创建、配置、调试与发布，同时向上提供标准协议接口（AGUI、OpenAI 兼容 API），便于与前端应用、第三方系统无缝集成。

一句话概括：**「资源接入 → 智能体编排 → 标准化发布」的个人一站式 Agent 工作台**。

> 说明：平台当前仅服务单一个人用户，不涉及多租户、多成员协作与组织管理，管理界面不包含租户、成员、角色分配等设计。

### 1.3 核心价值

| 价值点 | 说明 |
|---|---|
| 低代码构建 | 通过表单化配置「提示词 + 工具 + 模型」，分钟级产出可用智能体 |
| 能力可插拔 | MCP 工具、Skills、内置工具、模型均为平台级资源池，创建一次、多处复用 |
| 模型可治理 | 统一录入、测试、管理各类 OpenAI 协议兼容模型，避免密钥散落、调用口径不一 |
| 标准化对外发布 | 智能体可发布为 AGUI 协议接口；模型可按多个版本发布为 OpenAI 兼容 API，并为每个版本独立配置调用标识、API Key、生成参数与限流，降低集成成本 |
| 轻量易用 | 面向个人用户设计，登录与使用流程极简，无团队协作与权限管理负担 |

### 1.4 目标用户

| 角色 | 诉求 |
|---|---|
| 个人开发者 | 独立搭建、调试、使用自己的智能体，解决个人工作/生活中的具体问题 |
| AI 效率工具爱好者 | 希望以低代码方式组合模型与工具能力，打造个性化 AI 助手 |
| 下游系统/脚本开发者 | 希望以熟悉的 OpenAI SDK 方式直接调用平台内治理好的模型资源，或通过 AGUI/API 集成自己搭建的智能体 |

### 1.5 产品目标

#### 1.5.1 核心目标

1. **统一资源接入**：在一个工作区内治理模型、MCP、Skills 和内置工具，避免重复配置和凭证散落。
2. **低代码 Agent 编排**：用户通过表单和资源选择完成智能体配置，不依赖手写编排代码。
3. **配置与调试一体化**：编辑智能体时即可进行多轮测试，快速验证提示词、模型和工具组合。
4. **标准化能力输出**：智能体通过标准对话 API 或 AGUI 输出；模型通过 OpenAI 兼容 API 输出。
5. **可观测、可追溯**：通过统一日志关联会话、模型和工具调用，支持定位错误与复盘效果。
6. **适合个人部署**：保持部署、登录、配置和维护成本足够低，不引入不必要的组织治理复杂度。

#### 1.5.2 成功标准

- 新用户在完成模型接入后，可以在 10 分钟内创建并跑通一个带工具的智能体。
- 用户可以不阅读后端源码，仅通过管理界面完成资源接入、测试、挂载和发布。
- 任意一次 Agent 运行都能通过 `runId` 找到对应模型和工具调用记录。
- 发布后的智能体或模型可以直接通过标准 HTTP/SDK 调用，无需额外编写协议适配层。
- 密钥在界面和日志中均不以明文泄露，资源禁用或版本停用后能立即阻断对应调用。

### 1.6 一期范围与非目标

#### 1.6.1 一期范围

- 单个本机/个人工作区。
- 基于访问 Key 的轻量登录。
- Agent 创建、编辑、测试、历史记录与发布。
- OpenAI 兼容模型接入、测试、备注管理与多版本发布。
- MCP 服务器接入、工具发现、启停与调用配额。
- Skill 压缩包上传与资源池管理。
- 平台内置工具查看和启停。
- 全链路调用日志、筛选、详情和导出。
- 工作区、访问安全和日志保留设置。

#### 1.6.2 明确非目标

- 不提供租户、组织、项目空间、成员邀请、角色权限或审批流。
- 不提供模型自动路由、负载均衡、故障转移或供应商成本优化。
- 不提供复杂工作流/DAG、多 Agent 协作或人工节点编排。
- 不提供知识库/RAG 的完整管理能力。
- 不提供计费、套餐、充值、账单和商业化配额管理。
- 不在管理界面中开发或修改内置工具代码。

### 1.7 产品设计原则

- **先资源、后编排**：模型与工具先进入资源池，再由 Agent 组合使用。
- **配置就近**：资源级配置放在资源管理；Agent 级配置放在 Agent 编辑器；发布级配置放在发布版本。
- **默认安全**：密钥默认脱敏，日志默认过滤敏感字段，停用状态优先阻断调用。
- **渐进式复杂度**：高频基础配置前置，运行限制、重试和协议细节收纳在高级区域。
- **所见即所得**：编辑页直接提供测试会话，配置修改对测试环境实时生效。
- **状态可解释**：连接、启用、发布、运行结果均使用明确状态标签，并提供失败原因。

│   ├─ Skills 管理
│   ├─ 内置工具管理

│       └─ 多版本发布配置：调用标识 / API Key / 请求头 / 生成参数 / QPM
├─ 运营与治理

### 2.1 页面与路由

| 页面 | 路由 | 访问条件 | 页面职责 |
|---|---|---|---|
| 登录 | `/login` | 未登录 | 校验工作区访问 Key；已登录用户访问时自动跳转概览 |
| 概览 | `/` | 已登录 | 展示核心指标、资源状态、调用趋势、最近活动与快捷入口 |
| 智能体列表 | `/agents` | 已登录 | 搜索、筛选、创建和进入智能体 |
| 智能体详情 | `/agents/{agentId}` | 已登录且 Agent 存在 | 配置、测试、查看历史和发布 Agent |
| MCP 管理 | `/resources/mcp` | 已登录 | 接入、测试、启停 MCP 服务并管理其工具 |
| Skills 管理 | `/resources/skills` | 已登录 | 上传、查看和管理 Skill 能力包 |
| 内置工具 | `/resources/tools` | 已登录 | 查看平台工具并控制全局启停 |
| 模型管理 | `/resources/models` | 已登录 | 接入、测试、备注、启停模型并管理发布版本 |
| 调用日志 | `/logs` | 已登录 | 查询、筛选、查看和导出运行日志 |
| 系统设置 | `/settings` | 已登录 | 管理工作区信息、访问 Key 与日志策略 |

未匹配的路由统一跳转概览；未登录访问受保护页面时跳转登录页。

### 2.2 全局页面框架

#### 2.2.1 左侧导航

- 桌面端固定宽度侧栏，分为「工作台」「能力资源」「运营与治理」三个分组。
- 当前页面使用高亮背景、左侧色条和高亮图标标识。
- 调用日志菜单可展示未处理异常提示点。
- 底部固定展示当前个人工作区头像、用户名称和工作区类型。
- 点击退出登录后清除当前认证状态并返回登录页。
- 移动端侧栏改为抽屉，通过顶部菜单按钮打开，点击遮罩或导航项后关闭。

#### 2.2.2 顶部栏

- 面包屑结构为 `albedo / 当前页面`；进入 Agent 详情时显示「智能体配置」。
- 提供全局搜索入口，桌面端展示快捷键提示 `⌘ K`；原型已注册全局监听（`⌘/Ctrl + K` 在任意页面唤起搜索）。
- 提供帮助入口，打开「帮助与快捷键」弹窗，展示 `⌘ K`、`Esc`、`Enter`、`Shift + Enter` 的用法与原型环境说明。
- 提供通知入口，红点表示存在未读或异常通知。
- 顶部栏保持吸顶（sticky），页面内容滚动时仍可访问。
- 移动端隐藏搜索框，仅保留菜单、帮助与通知按钮。

#### 2.2.3 全局搜索

- 搜索范围：智能体名称、模型展示名称。
- 搜索结果展示名称、资源类型；模型结果附带厂商信息。
- 最多优先展示 7 条匹配结果。
- 点击 Agent 结果进入对应详情；点击模型结果进入模型管理。
- 搜索不区分大小写。
- 无匹配项时应展示明确空状态，不保留上一次搜索的错误结果。
- 关闭弹窗或完成跳转后清空搜索词。

#### 2.2.4 通知

- 通知面板为顶部下拉卡片，包含标题栏、「全部已读」按钮和通知列表。
- 通知内容至少包括图标类型、标题、摘要、时间和关联对象；当前原型重点展示「DeepSeek API 调用失败」（摘要：请求频率超出限制，请检查上游配额）一条未读通知。
- 点击通知进入关联日志或资源详情；原型中点击通知直接跳转 `/logs`。
- 「全部已读」只改变通知阅读状态并清除红点，不删除历史通知；已全部读完后按钮变为「已全部读完」并禁用。
- 点击面板外部或按 `Esc` 关闭面板。
- 产品化补齐：通知数据源、未读数持久化、按资源类型聚合、实时推送与跳转携带筛选条件。

#### 2.2.5 通用反馈

- 保存、创建、上传、测试、复制、启停、发布、导出等操作通过右上角 Toast 反馈结果。
- 成功反馈默认自动消失；失败反馈需包含可行动的原因，重要失败不可仅显示“操作失败”。
- 弹窗点击遮罩可关闭；存在未保存编辑时，正式实现应二次确认。
- 危险操作使用红色视觉语义，并要求用户确认影响范围。

### 2.3 核心领域对象与关系

| 对象 | 唯一标识 | 核心关系 | 生命周期 |
|---|---|---|---|
| Agent | `agentId` | 关联 1 个默认模型，可挂载多个 MCP、Skill、内置工具 | 草稿 → 已发布；可独立启用标准 API/AGUI |
| Model | `modelId`（平台内部 ID） | 可被多个 Agent 引用，可拥有多个发布版本 | 未测试/已连接；启用/停用 |
| Model Publication | `publicationId` | 从属 1 个 Model，拥有独立版本号、调用标识和 API Key | 已发布 ↔ 已停用 |
| MCP Server | `mcpId` | 暴露多个 Tool，可被多个 Agent 挂载 | 连接正常/异常；启用/停用 |
| Skill | `skillId` | 可被多个 Agent 挂载 | 上传校验 → 可用；支持版本演进 |
| Built-in Tool | `toolId` / Tool Key | 平台代码注册，可被多个 Agent 挂载 | 启用/停用 |
| Run | `runId` | 关联一次 Agent 或模型运行及其全部子调用 | 运行中 → 成功/失败/超时 |
| Thread | `threadId` | 聚合一组连续对话和多个 Run | 活跃/归档 |
| Log Entry | `logId` | 关联 runId、threadId 和资源对象 | 写入后只读，按保留周期清理 |

#### 2.3.1 关键关系规则

- 删除或停用资源时，必须先识别其被哪些 Agent 或发布版本引用。
- 模型停用后：不可用于新 Agent 配置；已有 Agent 运行时应明确报错；该模型全部对外发布版本停止接受调用。
- MCP 或内置工具停用后：不可新增挂载；已有 Agent 中保留配置引用并显示失效提示，运行时不得调用。
- Skill 更新版本时：已有 Agent 默认继续使用原版本，除非用户显式升级；若采用自动升级策略，需在操作前说明。
- 停用单个模型发布版本不影响同模型其他版本，也不影响 Agent 内部使用模型资源。
- Agent 的资源挂载保存的是平台内部资源 ID，不直接复制资源连接信息或密钥。

### 2.4 全局状态语义

| 状态类别 | 状态值 | 含义 |
|---|---|---|
| 资源启用状态 | 启用 / 停用 | 是否允许被新配置选择及在运行时调用 |
| 连接状态 | 正常 / 未测试 / 异常 | 最近一次连通性检查结果 |
| Agent 发布状态 | 草稿 / 已发布 | 是否至少开放一种对外接口 |
| 模型版本状态 | 已发布 / 已停用 | 特定发布版本是否允许外部调用 |
| 运行状态 | 运行中 / 成功 / 失败 / 超时 | 单次 Run 或子调用结果 |
| 日志状态 | 可查询 / 已归档 / 已清理 | 日志在保留策略下的存储阶段 |

## 3. 核心模块详解

### 3.0 登录与概览

#### 3.0.1 登录页

**页面目标**：用最低操作成本完成个人工作区身份校验，同时说明产品定位和核心价值。

**页面结构**

- 品牌展示区：产品名称、版本、核心标语、产品简介，以及「可插拔能力」「全链路调试」「标准化发布」三个价值标签。
- 登录表单区：访问 Key 输入框、明文显示切换、错误提示和「进入工作台」按钮。
- 安全提示：个人工作区无需注册账号，访问 Key 仅保存在当前设备。

**字段与规则**

| 字段 | 必填 | 原型默认值 | 校验与行为 |
|---|---|---|---|
| 访问 Key | 是 | 演示环境预填 `albedo-demo-2026` | 原型要求去除首尾空格后不少于 6 个字符；产品化要求不少于 12 个字符并由服务端恒定时间校验 |
| 显示 Key | 否 | 关闭 | 仅改变输入框显示方式，不改变 Key 内容 |

**交互规则**

1. 登录成功后进入概览页。
2. 登录失败时在输入框下展示原因，用户再次输入后清除旧错误。
3. 已登录用户访问 `/login` 时直接跳转概览。
4. 未登录用户访问任意受保护页面时跳转登录，并建议产品化实现记录原目标地址，登录后返回。
5. 连续失败达到阈值时应触发短时限流，避免暴力尝试。

#### 3.0.2 概览页

**页面目标**：让用户快速判断工作区是否健康，并进入高频管理任务。

**指标卡**

| 指标 | 展示内容 | 统计口径 |
|---|---|---|
| 智能体 | Agent 总数、已发布数量 | 包含草稿与已发布 Agent |
| 今日调用 | 今日调用次数、较昨日变化 | 汇总 Agent、模型和工具运行；需明确去重口径 |
| 模型资源 | 模型总数、启用数量 | 资源层模型，不按发布版本重复计数 |
| 成功率 | 最近 24 小时成功率 | `成功 Run 数 / 已结束 Run 数`，运行中不计入分母 |

**调用趋势**

- 默认展示最近 14 天能力调用次数，可切换最近 30 天。
- 折线图按自然日聚合，悬停时应展示日期、调用量和同比/环比信息。
- 无调用数据时展示零状态，不应绘制误导性趋势。

**资源状态**

- 模型服务：启用数/总数及平均延迟。
- MCP 服务：启用数/总数及可用工具数量。
- Skills：资源总数及最近更新时间。
- 内置工具：启用数/总数及今日调用次数。
- 「全部正常」仅在所有启用资源最近健康检查均正常时展示；否则应按异常等级显示；原型中为固定文案，不随异常变化（见附录 C）。

**最近活动**

- 展示最近 5 条调用记录。
- 每条包含结果状态、调用对象、摘要、类型和时间。
- 点击记录或「查看全部」进入调用日志；产品化实现应携带当前日志 ID 或筛选条件。

**快捷入口**

- 「创建你的下一个智能体」卡片中的「开始创建」进入智能体列表/创建流程。
- 「接入模型」进入模型管理。
- 「连接 MCP」进入 MCP 管理。
- 概览页顶部不设置单独的「创建智能体」按钮，避免与内容区入口重复。

### 3.1 智能体管理

#### 3.1.1 智能体列表

**页面目标**：集中查看 Agent 资产、识别发布状态，并快速进入创建或编辑。

**搜索与筛选**

- 关键词搜索范围：智能体名称、功能介绍；不区分大小写。
- 状态快捷筛选：全部、已发布、草稿（分段控件，选中态白底投影）。
- 「筛选」按钮展开筛选面板，当前支持按**默认模型**筛选（下拉列出全部模型），面板内展示「当前共 N 个结果」并提供「重置筛选」；筛选生效时按钮上显示标记点。
- 重置筛选一次性清空关键词、状态与默认模型条件；无任何条件时按钮禁用。
- 关键词、状态与默认模型三组条件同时生效；无结果时展示空状态并建议调整条件。
- 产品化可继续扩展：挂载能力、更新时间、创建来源等条件。

**Agent 卡片**

| 展示项 | 说明 |
|---|---|
| 头像/主题色 | 由 Agent 的主题色生成渐变标识 |
| 名称 | Agent 展示名称，过长时截断 |
| 状态 | 已发布或草稿 |
| 功能介绍 | 最多展示两行 |
| 默认模型 | 展示模型名称；模型不存在时显示“未选择模型” |
| 能力数量 | MCP、Skill、内置工具挂载数量之和 |
| AGUI 标识 | AGUI 已启用时展示 |
| 会话量 | 累计会话次数 |
| 更新时间 | 最近保存时间 |

点击卡片进入 Agent 详情。列表中的更多操作入口可扩展复制、重命名、导出和删除；删除前必须检查发布状态并二次确认。

**创建入口**

- 页面右上角提供「创建智能体」按钮。
- 创建弹窗完成基础信息后直接进入新 Agent 的编辑页。
- Agent 创建成功但尚未发布时状态为草稿。

**列表验收**

- 搜索词命中名称或简介时返回正确卡片。
- 已发布/草稿筛选结果与 Agent 发布状态一致。
- 禁用或删除的模型不导致列表崩溃，应显示资源异常提示。
- 新建 Agent 保存后立即出现在列表顶部。

#### 3.1.2 创建与配置智能体

##### 3.1.2.1 创建智能体

**基础信息**

| 字段 | 必填 | 说明 |
|---|---|---|
| 名称 | 是 | 展示名称；去除首尾空格后不可为空，建议 1～50 个字符 |
| 功能介绍 | 否 | 展示在列表卡片；为空时生成“一个全新的智能体，等待进一步配置” |
| 默认模型 | 是 | 仅可选择启用且适用于对话的模型 |
| System Prompt | 否 | 为空时按“你是{名称}……”模板自动生成 |

**创建约束**

- 「创建并配置」按钮在名称为空或未选择默认模型时禁用。
- 默认模型下拉仅列出**已启用**模型；工作区内没有任何启用模型时，字段下方提示「当前没有已启用的模型，请先在「模型管理」中启用」，此时无法创建。

**创建默认值**

- 变量、MCP、Skill 和内置工具列表均为空。
- 最大工具调用次数为 10。
- 发布状态为草稿，标准 API 和 AGUI 默认关闭。
- 会话数量为 0。
- 主题色按现有 Agent 数量循环分配。
- 创建成功后自动进入 `/agents/{agentId}` 继续配置。

##### 3.1.2.2 编辑器整体结构

- 顶部：返回列表、Agent 头像、名称、发布状态（已发布/草稿）、`更新于 … · ID: agt-xxx`、运行与保存按钮。
- 「运行」按钮：切换到「编排与调试」Tab 与「基础信息」分区，并自动聚焦测试会话输入框，提示「已进入测试会话，可直接提问验证配置」；它不触发一次真实运行，运行由用户在测试会话中发送消息发起。
- 一级 Tab：编排与调试、对话历史（带当前 Agent 日志条数）、发布。
- 「编排与调试」采用三栏布局：左侧配置导航（基础信息/提示词/模型设置/能力挂载/高级设置），中间配置表单，右侧测试会话；窄屏下配置导航转为横向滚动条，测试会话下移。
- 点击「保存配置」后统一持久化当前草稿，更新时间为「刚刚」并 Toast 提示。
- Agent 不存在时展示「未找到该智能体」与返回列表入口。
- 未保存修改应在离开页面时提示；原型当前未实现，产品化必须补齐。

##### 3.1.2.3 基础信息配置

| 字段 | 必填 | 规则 |
|---|---|---|
| 智能体名称 | 是 | 1～50 字符；列表、对话、发布文档统一使用 |
| 功能介绍 | 否 | 建议不超过 200 字符 |
| 头像与主题色 | 是 | 原型支持 violet、blue、mint、orange 四种渐变主题 |

主题色变更仅影响展示，不影响 Agent ID、API 地址或历史日志。

##### 3.1.2.4 提示词配置

- System Prompt 为 Agent 的核心系统指令，保存前不可为空。
- 编辑区展示字符数，建议限制为 20,000 字符并在接近上限时提示。
- 「AI 辅助生成」可根据名称、简介和已挂载能力生成草稿；生成结果必须由用户确认后保存。
- 变量使用双花括号插值格式，例如 `{{businessContext}}`。
- 变量名不允许包含空格，建议限制为字母、数字和下划线，且不能以数字开头。
- 重复变量不可再次添加。
- 删除变量不会自动删除 Prompt 中的引用，应提示存在未解析引用。

**提示词变量**

- 系统变量（平台自动注入，无需配置）：`{{currentTime}}`
- 自定义变量：用户自行添加变量名，运行时由调用方传值替换

变量解析顺序建议为：系统变量 → 请求变量 → 缺失值校验。缺失的必需变量应在运行前返回可读错误，不应将原始占位符直接发送给模型。

##### 3.1.2.5 模型设置

| 字段 | 原型默认值 | 说明 |
|---|---|---|
| 默认模型 | 创建时所选模型 | 仅展示启用模型；模型停用时保留原选择并标记异常 |
| 温度 | 0.7 | Agent 级生成随机性，建议范围 0～2 |
| Top P | 0.9 | Agent 级核采样参数，建议范围 0～1 |
| 最大输出 Token | 4096 | 单次模型生成上限，不能超过模型能力上限 |

- 测试会话可临时切换模型进行效果对比。
- 临时切换只影响当前测试，不应覆盖默认模型；当前原型为共用选择状态，正式实现需拆分「默认模型」与「测试模型」。
- 模型资源层不再设置默认温度，避免与 Agent 级参数和模型发布版本参数冲突。

##### 3.1.2.6 能力挂载

**能力挂载（资源组合）**

| 挂载项 | 来源 | 作用 |
|---|---|---|
| 模型 | 模型管理资源池 | 指定智能体运行所用的底层 LLM |
| MCP 服务器 | MCP 管理资源池 | 调用外部系统/API 的工具能力 |
| Skills | Skills 管理资源池 | 挂载打包好的专项技能 |
| 内置工具 | 内置工具管理资源池 | 挂载平台代码内置的通用工具（联网搜索、代码执行、文件解析等） |

**交互与规则**

- MCP、Skill、内置工具分别通过资源选择弹窗添加，可一次勾选多个。
- 已选资源在配置页展示名称和摘要，可单独移除。
- 内置工具选择器仅展示全局启用的工具。
- 资源搜索应覆盖名称与描述。
- 挂载 MCP 代表 Agent 可访问该服务器中已启用的工具；单个 Tool 的可用性仍由 MCP 管理控制。
- 同一资源不可重复挂载。
- 移除挂载只影响当前 Agent，不删除平台资源。
- 保存前应检测失效资源，并在测试或发布时阻止带有关键失效资源的配置。

##### 3.1.2.7 高级设置

**高级设置**

| 字段 | 默认值 | 说明 |
|---|---|---|
| 保留会话上下文 | 开启 | 同一 `threadId` 中携带历史消息 |
| 自动重试工具调用 | 开启 | 工具返回临时错误时最多重试 2 次；不可重试业务校验错误 |
| 输出思考摘要 | 关闭 | 调试面板展示阶段性摘要，不得输出模型私有推理链 |
| 最大工具调用次数 | 10 次 | 限制单次 Agent 运行可发起的工具调用总数，最小 1 次、最大 100 次；达到上限后停止继续调用工具并进入结果整理 |
| 单次运行最大时长 | 120 秒 | 超时后终止本次运行并记录超时日志 |

**工具调用计数口径**

- 每次实际向 MCP 或内置工具发出请求计 1 次。
- 同一次调用的自动重试是否计入上限需统一：建议每次实际请求都计数，以避免重试绕过限制。
- Skill 的加载不计入工具调用次数；Skill 内部再次调用工具时按实际工具请求计数。
- 达到上限后模型可基于已有结果生成最终回答，但不得继续发起工具调用。
- 终止原因写入 Run 日志，并在调试面板提示“已达到最大工具调用次数”。

##### 3.1.2.8 即时调试

**即时调试**

- 配置页右侧内置测试会话，头部显示「测试会话 · 配置实时生效」、可临时切换模型、清空对话按钮；草稿配置实时生效，无需先发布。
- 支持多轮消息、Enter 发送、Shift+Enter 换行；输入框下方提示「Enter 发送 · Shift + Enter 换行」。
- 发送中展示三点呼吸动画的思考状态，并禁用发送按钮，避免重复提交。
- 回复展示时间；工具调用型消息应展示工具名称、参数、执行状态和结果摘要（原型为纯文本模拟回复，见附录 C）。
- 测试运行必须生成 `runId` 并进入调用日志，名称形如 `{Agent 名称} / 测试会话`，来源标记为「测试会话」。
- 清空对话只清除当前调试面板内容，不删除已写入的历史日志；清空后展示「开始一组测试对话」空态。
- 附件按钮为文件输入能力预留，原型提示「原型环境暂不支持附件上传」；正式实现需限制类型、大小并执行安全扫描。
- 产品化补齐：停止生成、重新生成、多测试会话并列对比、真实流式输出。

##### 3.1.2.9 对话历史

- 默认仅展示当前 Agent 的运行记录（Tab 标题带条数）。
- 筛选条件：搜索会话内容（名称、摘要、runId）、来源（全部来源/测试会话/标准 API/AGUI）、时间范围（最近 7 天/最近 30 天/最近 1 年），并展示「共 N 条」。
- 列表字段：会话/摘要、运行标识（runId）、耗时、Token、状态；无记录时展示「暂无对话历史」空态。
- 点击记录后应进入完整运行详情或联动全局日志。
- 无记录时展示空状态。
- 历史内容遵循全局日志保留周期；清理后列表不再可见。

**来源判定规则（正式实现口径）**

| 来源 | 判定方式 |
|---|---|
| 测试会话 | 运行来源为编辑器测试面板；原型以日志名称包含「测试会话」判定 |
| 标准 API | 调用 `/v1/agents/{agentId}/chat`；原型以 `runId` 前缀 `run_api` 判定 |
| AGUI | 调用 `/api/agui/v1/agents/{agentId}/run`；原型以名称或摘要包含 `AGUI` 判定 |

> 正式实现必须以日志结构化字段 `source` 判定，不能依赖名称文本或 runId 前缀匹配；Agent 维度关联应使用不可变 `agentId` 而非 Agent 名称。

#### 3.1.3 智能体发布

智能体配置完成并通过测试后，可在「使用配置」/「发布」入口将其发布为对外可调用的标准接口，当前支持两种发布形态：

**① 标准对话 API**

标准对话 API 是面向后端服务、业务系统、自动化脚本等调用方提供的简化 HTTP 对话接口。调用方提交消息并获得 Agent 的最终回答，无需理解 Agent 内部的模型推理、工具调用或状态同步过程。

**适用场景**

- 业务系统需要获得一段最终文本或结构化回答。
- 后端任务、脚本、机器人需要发起单轮或多轮 Agent 对话。
- 接入方只关心结果，不需要在界面实时展示工具调用过程。

**接口**

```http
POST /v1/agents/{agentId}/chat
Authorization: Bearer <Agent API Key>
Content-Type: application/json
Accept: application/json
```

使用流式响应时，`Accept` 应设置为 `text/event-stream`，请求体中的 `stream` 设置为 `true`。

**请求字段**

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `messages` | array | 是 | — | 对话消息列表，至少包含一条消息 |
| `messages[].role` | enum | 是 | — | `system`、`user`、`assistant`、`tool`；普通调用方通常只传 `user`/历史 `assistant` |
| `messages[].content` | string | 是 | — | 消息正文，不允许为空 |
| `threadId` | string | 否 | 服务端生成 | 会话标识；后续请求复用可延续平台保存的上下文 |
| `runId` | string | 否 | 服务端生成 | 本次运行标识；调用方提供时必须在当前工作区唯一 |
| `variables` | object | 视配置而定 | `{}` | Agent 自定义提示词变量，如 `{ "businessContext": "电商" }` |
| `stream` | boolean | 否 | `false` | 是否通过 SSE 流式返回文本 |
| `includeUsage` | boolean | 否 | `true` | 是否返回 Token 用量 |
| `metadata` | object | 否 | `{}` | 调用方自定义追踪信息；仅用于日志检索，不注入 Prompt |

平台已配置的 System Prompt、模型和工具由服务端自动加载，调用方不需要重复提交。请求中的 `system` 消息只能作为附加上下文，不能覆盖平台安全指令。

**非流式请求示例**

```json
{
  "threadId": "thd_order_20261028_001",
  "messages": [
    {
      "role": "user",
      "content": "请分析订单下降的可能原因，并给出排查顺序。"
    }
  ],
  "variables": {
    "businessContext": "跨境电商"
  },
  "stream": false,
  "metadata": {
    "source": "operations-console",
    "requestUser": "user_1024"
  }
}
```

```bash
curl https://api.albedo.local/v1/agents/agt-research/chat \
  -H "Authorization: Bearer $ALBEDO_AGENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [
      {"role": "user", "content": "请分析订单下降的原因"}
    ],
    "stream": false
  }'
```

**非流式响应字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 本次响应 ID |
| `object` | string | 固定为 `agent.chat.completion` |
| `created` | integer | Unix 秒级时间戳 |
| `agentId` | string | 被调用的 Agent ID |
| `threadId` | string | 会话标识 |
| `runId` | string | 本次运行标识，可用于查询日志 |
| `status` | enum | `completed`、`failed`、`timeout`、`cancelled` |
| `message` | object | Agent 最终回复，包含 `id`、`role`、`content` |
| `usage` | object | 可选；包含 `inputTokens`、`outputTokens`、`totalTokens` |
| `finishReason` | enum | `stop`、`length`、`tool_limit`、`timeout`、`error` |
| `metadata` | object | 平台返回的运行摘要，如耗时和工具调用次数；不包含敏感工具参数 |

**非流式响应示例**

```json
{
  "id": "chatcmpl_8fk2m1",
  "object": "agent.chat.completion",
  "created": 1793174123,
  "agentId": "agt-research",
  "threadId": "thd_order_20261028_001",
  "runId": "run_8fk2m1",
  "status": "completed",
  "message": {
    "id": "msg_a_01",
    "role": "assistant",
    "content": "建议先确认流量、转化率和客单价三个指标的变化，再依次排查渠道、库存与履约问题……"
  },
  "usage": {
    "inputTokens": 1260,
    "outputTokens": 842,
    "totalTokens": 2102
  },
  "finishReason": "stop",
  "metadata": {
    "durationMs": 3840,
    "toolCallCount": 2
  }
}
```

**流式响应**

流式模式使用 SSE，只推送对话结果相关的最小事件，不暴露完整 Agent 运行生命周期。响应头：

```http
HTTP/1.1 200 OK
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache
Connection: keep-alive
```

| 事件 | 说明 |
|---|---|
| `message.start` | 返回 `threadId`、`runId`、消息 ID |
| `message.delta` | 返回文本增量 `delta` |
| `message.end` | 返回 `finishReason`、完整用量和运行摘要 |
| `error` | 流建立后发生的错误；包含错误码和可读信息 |

```text
event: message.start
data: {"threadId":"thd_order_20261028_001","runId":"run_8fk2m1","messageId":"msg_a_01"}

event: message.delta
data: {"messageId":"msg_a_01","delta":"建议先确认流量、"}

event: message.delta
data: {"messageId":"msg_a_01","delta":"转化率和客单价三个指标。"}

event: message.end
data: {"messageId":"msg_a_01","finishReason":"stop","usage":{"inputTokens":1260,"outputTokens":842,"totalTokens":2102}}
```

工具调用默认在服务端内部执行。标准对话 API 只返回最终回复、结束原因和工具调用次数；如需实时呈现工具名称、参数、结果和 Agent 状态，应使用 AGUI。

**② AGUI 协议接口（新增重点能力）**

- **概念**：AGUI（Agent-User Interaction Protocol，智能体-用户交互协议）是面向「Agent 与前端 UI 实时交互」场景设计的标准化事件流协议。相较于普通文本流式 API，AGUI 传递的是结构化的「智能体运行生命周期事件」，使前端可以精细地渲染对话过程、工具调用过程与状态变化，而不仅仅是一段纯文本。
- **发布方式**：在智能体「发布」Tab 勾选「发布为 AGUI 接口」，系统自动生成：
  - Endpoint 地址，例如：`https://albedo.example.com/api/agui/v1/agents/{agentId}/run`
  - 鉴权凭证（API Key / Bearer Token）
  - 协议版本与接入文档（含 SDK/示例代码）

**适用场景**

- 对话前端需要逐字渲染 Agent 回复。
- 页面需要展示“正在调用哪个工具”、工具参数和结果。
- Agent 与前端需要共享任务进度、表单、列表等结构化状态。
- 前端需要根据 Run 的开始、结束、失败等生命周期事件更新 UI。

**接口**

```http
POST /api/agui/v1/agents/{agentId}/run
Authorization: Bearer <Agent API Key>
Content-Type: application/json
Accept: text/event-stream
X-AGUI-Version: 1
```

AGUI 始终使用 SSE 返回结构化事件，不提供一次性 JSON 响应。

**请求字段（RunAgentInput）**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `threadId` | string | 是 | 会话标识；同一前端会话保持不变 |
| `runId` | string | 是 | 本次运行标识；SDK 可自动生成，原始 HTTP 调用方必须提供 |
| `messages` | array | 是 | 当前历史消息，至少包含触发本次运行的用户消息 |
| `messages[].id` | string | 是 | 消息唯一 ID |
| `messages[].role` | enum | 是 | `system`、`user`、`assistant`、`tool` |
| `messages[].content` | string/object | 是 | 文本或协议支持的结构化内容 |
| `tools` | array | 否 | 前端临时提供的工具定义；不会自动获得平台资源权限 |
| `context` | array/object | 否 | 页面、用户和业务上下文；Agent 自定义变量可放在 `variables` 子项 |
| `state` | object | 否 | 前端当前共享状态快照 |
| `forwardedProps` | object | 否 | 需要透传给运行时、但不属于标准字段的扩展属性 |

平台将请求中的 `tools` 与 Agent 已授权能力隔离校验；前端声明工具不等于平台自动允许执行该工具。

**请求示例**

```json
{
  "threadId": "thd_research_001",
  "runId": "run_research_008",
  "messages": [
    {
      "id": "msg_u_008",
      "role": "user",
      "content": "研究 2026 年新能源汽车市场，并实时展示执行进度。"
    }
  ],
  "tools": [],
  "context": {
    "page": "market-research",
    "variables": {
      "researchDepth": "deep",
      "outputLanguage": "zh-CN"
    }
  },
  "state": {
    "progress": 0,
    "sources": []
  }
}
```

```bash
curl -N https://api.albedo.local/api/agui/v1/agents/agt-research/run \
  -H "Authorization: Bearer $ALBEDO_AGENT_KEY" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -H "X-AGUI-Version: 1" \
  -d '{
    "threadId": "thd_research_001",
    "runId": "run_research_008",
    "messages": [
      {
        "id": "msg_u_008",
        "role": "user",
        "content": "研究 2026 年新能源汽车市场"
      }
    ]
  }'
```

**SSE 事件通用结构**

每条事件的 `data` 为 JSON，并至少包含：

| 字段 | 说明 |
|---|---|
| `type` | 事件类型 |
| `threadId` | 所属会话 |
| `runId` | 所属运行 |
| `timestamp` | ISO 8601 事件时间 |
| `sequence` | 本次 Run 内单调递增的事件序号，用于排序和断线恢复 |

**输出事件类型**

| 事件 | 关键载荷 | 说明 |
|---|---|---|
| `RUN_STARTED` | Agent ID、开始时间 | 本次运行已创建并开始执行 |
| `TEXT_MESSAGE_START` | `messageId`、`role` | 开始输出一条 Agent 文本消息 |
| `TEXT_MESSAGE_CONTENT` | `messageId`、`delta` | 文本增量分片 |
| `TEXT_MESSAGE_END` | `messageId` | 文本消息输出完成 |
| `TOOL_CALL_START` | `toolCallId`、`toolCallName` | Agent 决定调用工具 |
| `TOOL_CALL_ARGS` | `toolCallId`、`delta`/`args` | 工具参数增量或完整参数 |
| `TOOL_CALL_END` | `toolCallId` | 工具参数组装完成并开始执行 |
| `TOOL_CALL_RESULT` | `toolCallId`、`content`、`status` | 工具返回结果或错误摘要 |
| `STATE_SNAPSHOT` | `snapshot` | 下发完整共享状态 |
| `STATE_DELTA` | `delta` | 下发 JSON Patch 或协议定义的增量状态 |
| `RUN_FINISHED` | 状态、Token、耗时 | Run 正常结束 |
| `RUN_ERROR` | `code`、`message`、`retryable` | Run 失败或超时 |

**典型事件序列**

```text
event: RUN_STARTED
data: {"type":"RUN_STARTED","threadId":"thd_research_001","runId":"run_research_008","sequence":1,"timestamp":"2026-10-28T09:10:00.000Z"}

event: STATE_DELTA
data: {"type":"STATE_DELTA","threadId":"thd_research_001","runId":"run_research_008","sequence":2,"delta":[{"op":"replace","path":"/progress","value":10}]}

event: TOOL_CALL_START
data: {"type":"TOOL_CALL_START","threadId":"thd_research_001","runId":"run_research_008","sequence":3,"toolCallId":"call_01","toolCallName":"tavily_search"}

event: TOOL_CALL_ARGS
data: {"type":"TOOL_CALL_ARGS","threadId":"thd_research_001","runId":"run_research_008","sequence":4,"toolCallId":"call_01","args":{"query":"2026 新能源汽车市场趋势"}}

event: TOOL_CALL_END
data: {"type":"TOOL_CALL_END","threadId":"thd_research_001","runId":"run_research_008","sequence":5,"toolCallId":"call_01"}

event: TOOL_CALL_RESULT
data: {"type":"TOOL_CALL_RESULT","threadId":"thd_research_001","runId":"run_research_008","sequence":6,"toolCallId":"call_01","status":"success","content":{"resultCount":8}}

event: TEXT_MESSAGE_START
data: {"type":"TEXT_MESSAGE_START","threadId":"thd_research_001","runId":"run_research_008","sequence":7,"messageId":"msg_a_008","role":"assistant"}

event: TEXT_MESSAGE_CONTENT
data: {"type":"TEXT_MESSAGE_CONTENT","threadId":"thd_research_001","runId":"run_research_008","sequence":8,"messageId":"msg_a_008","delta":"2026 年新能源汽车市场将呈现以下趋势："}

event: TEXT_MESSAGE_END
data: {"type":"TEXT_MESSAGE_END","threadId":"thd_research_001","runId":"run_research_008","sequence":9,"messageId":"msg_a_008"}

event: RUN_FINISHED
data: {"type":"RUN_FINISHED","threadId":"thd_research_001","runId":"run_research_008","sequence":10,"status":"completed","usage":{"inputTokens":1820,"outputTokens":1360,"totalTokens":3180},"durationMs":8420}
```

**事件顺序与处理要求**

- `RUN_STARTED` 必须是首个业务事件。
- 文本消息必须按 START → CONTENT（0～N 条）→ END 配对。
- 工具调用必须按 START → ARGS（1～N 条）→ END → RESULT 排列。
- `RUN_FINISHED` 或 `RUN_ERROR` 是终止事件，同一 Run 只能出现一个。
- 客户端按 `sequence` 去重和排序，不应仅依赖网络到达时间。
- 工具结果可能包含敏感或大体积内容；默认事件只返回安全摘要，完整值在权限允许时通过日志详情查看。
- 客户端断开连接时，服务端应停止或按运行策略继续任务；若支持恢复，可通过 `Last-Event-ID`/最后 `sequence` 继续读取未消费事件。

**价值**：任何实现了 AGUI 协议的前端框架或自研 Agent UI，都可以直接接入 albedo 发布的智能体，获得统一的流式文本、工具调用可视化、状态同步和运行生命周期事件，实现 Agent 后端与交互式前端解耦。

**两种接口对比**

| 对比项 | 标准对话 API | AGUI 协议接口 |
|---|---|---|
| 主要调用方 | 后端服务、脚本、普通业务系统 | Agent 对话前端、交互式应用 |
| 响应形式 | JSON 或最小文本 SSE | 结构化 SSE 事件流 |
| 最终文本 | 支持 | 支持 |
| 工具调用过程 | 默认不返回 | 完整事件化返回 |
| 共享状态同步 | 不支持 | 支持 Snapshot/Delta |
| 接入复杂度 | 低 | 较高，需要事件状态机 |
| 推荐场景 | 只关心最终答案 | 需要可视化 Agent 执行过程 |

**共同错误响应**

若错误发生在 SSE 建立前，使用标准 HTTP 状态和 JSON 错误体：

```json
{
  "error": {
    "code": "agent_not_published",
    "message": "该智能体未启用当前调用接口。",
    "requestId": "req_01HXYZ"
  }
}
```

| HTTP 状态 | 错误码示例 | 场景 |
|---|---|---|
| 400 | `invalid_request` | JSON、消息、变量或 ID 格式错误 |
| 401 | `invalid_api_key` | Agent Key 缺失、无效或已失效 |
| 403 | `agent_access_denied` | Key 无权调用目标 Agent |
| 404 | `agent_not_found` | Agent 不存在 |
| 409 | `agent_not_published` / `duplicate_run_id` | 接口未开启或 runId 冲突 |
| 422 | `missing_variable` | 缺少 Prompt 必需变量 |
| 429 | `rate_limit_exceeded` | 超过 Agent 调用额度 |
| 500 | `agent_run_failed` | Agent 内部运行失败 |
| 504 | `agent_run_timeout` | 超过最大运行时长 |

SSE 建立后发生错误时，标准对话 API 发送 `error` 事件，AGUI 发送 `RUN_ERROR`，随后关闭连接。所有错误均返回 `runId` 或 `requestId`，便于在调用日志中定位。

#### 3.1.4 发布页详细规则

**页面结构**

发布 Tab 自上而下由四部分组成：

1. 左列两张协议卡片：标准对话 API、AGUI 协议接口（带「推荐」标记）。
2. 左列访问凭证卡片：展示脱敏 Token 与「重置密钥」。
3. 右列「快速接入」卡片：协议切换（标准对话 API / AGUI 协议接口）+ 语言切换（curl / Python / JavaScript）+ 请求行 + 代码块 + 复制。
4. 底部完整接口文档卡片：请求行、请求头、请求参数、响应参数；AGUI 额外展示「响应事件」表。

切换协议或语言时，Endpoint、请求头说明与示例代码同步切换；接口文档顶部展示当前协议的开启状态（接口已开启 / 接口未开启）。

**发布开关**

- 标准对话 API 与 AGUI 分别由独立开关控制，可同时开启。
- 开启 AGUI 时 Agent 总体发布状态同步变为已发布（`published = aguiEnabled || published`）。
- 关闭其中一种协议不影响另一种已开启协议；关闭 AGUI 不会自动关闭标准 API。
- 当两种协议均关闭时，Agent 状态回到草稿/未发布。
- 协议卡片仅在开启后才展示对应 Endpoint；AGUI 开启后额外展示 `TEXT MESSAGE` / `TOOL CALL` / `STATE DELTA` 能力标记。
- Agent 存在未保存配置、模型不可用或关键资源失效时，应阻止首次发布并列出问题（原型未实现该检查）。

**接口地址**

| 类型 | 示例 |
|---|---|
| 标准对话 API | `POST https://api.albedo.local/v1/agents/{agentId}/chat` |
| AGUI | `POST https://api.albedo.local/api/agui/v1/agents/{agentId}/run` |

**访问凭证**

- 每个 Agent 使用独立 Bearer Token，与管理访问 Key、模型上游 Key、模型发布 Key 隔离。
- 页面默认仅展示脱敏值，形如 `alb_agt_••••••••••••7K2m`；创建或重置时只允许完整值出现一次。
- 「重置密钥」随机生成 4 位后缀并 Toast 提示「访问凭证已重置，旧密钥立即失效」；操作写入系统操作日志。
- 复制操作不应将密钥写入浏览器日志或埋点。

**快速接入**

- 提供 cURL、Python、JavaScript 示例。
- 示例应使用当前 Agent ID、实际 Endpoint、认证头和最小请求体。
- 标准 API 示例需说明同步/流式差异；AGUI 示例需说明 SSE 事件消费方式。
- 示例中的密钥默认使用环境变量占位，不直接嵌入明文。

**Agent 发布前检查**

1. 名称、Prompt、默认模型已配置。
2. 默认模型处于启用且连接正常状态。
3. 挂载资源不存在停用或丢失。
4. 最大工具调用次数和运行时长在合法范围。
5. 至少完成一次成功测试运行；建议项，不强制阻断草稿调试。

**Agent 发布验收**

- 标准 API 开启后 Endpoint 可调用，关闭后返回明确的未发布错误。
- AGUI 输出事件顺序符合协议，同一运行的事件使用一致的 `runId` 和 `threadId`。
- 重置凭证后旧凭证不可用，新凭证可用。
- Agent 配置更新后，后续新 Run 使用新配置；进行中的 Run 不被中途修改。
- API 与测试会话产生的运行记录均可在对话历史和全局日志中检索。

### 3.2 MCP 管理

MCP（Model Context Protocol）用于将外部系统、工具以标准协议接入智能体，使智能体具备调用外部 API、执行外部动作的能力。

**创建 MCP 服务器**

| Tab | 字段/内容 |
|---|---|
| 通用配置 | 名称、描述、类型（SSE / Streamable HTTP / stdio 等）、URL（远程服务地址）、请求头（自定义 Header，如 Authorization）、超时时间（默认 60s，最小 3s）、高级设置 |
| 工具管理 | 查看/勾选该 MCP 服务暴露的工具（Tools）清单，供智能体选择性挂载使用 |
| 使用配置 | 调用额度、启用状态等运营参数 |

接入后的 MCP 服务器作为资源池条目，可被任意数量的智能体挂载复用。

#### 3.2.1 MCP 列表

**搜索与筛选**

- 按服务器名称和描述搜索。
- 按连接类型筛选：SSE、Streamable HTTP、stdio。
- 产品化可增加启用状态和连接健康筛选。

**资源卡片**

| 展示项 | 说明 |
|---|---|
| 名称与类型 | 展示服务器名称及传输类型 |
| 启用状态 | 运行中/已停用 |
| 描述 | 服务器用途 |
| 服务地址/命令 | 远程 URL 或 stdio 启动命令，过长时截断 |
| 可用工具 | 当前启用 Tool 数量 |
| 调用次数 | 累计调用量 |
| 成功率 | 成功调用占已结束调用比例 |
| 连接健康 | 最近一次健康检查结果（连接正常 / 已停用） |

卡片操作入口：

- 「查看配置」打开详情抽屉的「通用配置」Tab。
- 右上角「更多（…）」直接打开详情抽屉的「工具管理」Tab，便于快速调整工具启停。

#### 3.2.2 添加 MCP 服务器

| 字段 | 必填 | 默认值/校验 |
|---|---|---|
| 名称 | 是 | 去除首尾空格后不可为空 |
| 连接类型 | 是 | 默认 Streamable HTTP；可选 SSE、stdio |
| 服务地址/命令 | 是 | HTTP 类型要求合法 URL；stdio 要求合法命令配置 |
| 描述 | 否 | 为空时使用“自定义 MCP 服务” |
| 自定义请求头 | 否 | 产品化建议使用 JSON 对象编辑器并对敏感值加密 |
| 超时时间 | 是 | 原型默认 60 秒；建议范围 3～600 秒 |

**连接测试**

1. 使用当前未保存表单发起握手。
2. 验证地址/命令可达、协议兼容和鉴权有效。
3. 成功后返回发现的 Tool 数量，并记录测试时间。
4. 失败时区分网络错误、鉴权失败、协议不兼容和超时。
5. 测试不自动保存；保存后才进入资源池。

**工具发现**

- 新建成功后读取服务端工具清单，保存 Tool 名称、描述和输入 Schema。
- 工具默认启用策略应可配置；建议首次发现默认启用，用户可随后关闭高风险工具。
- 服务端工具清单变化时，重新发现不得静默删除已挂载引用，应标记“已下线”。

#### 3.2.3 MCP 详情

详情抽屉包含四个 Tab：

1. **通用配置**
   - 编辑名称、描述、服务地址与启用状态；「保存更改」校验名称与服务地址均不能为空，为空时提示「名称与服务地址不能为空」。
   - 连接类型创建后不可直接编辑（字段置灰）；如允许切换，必须重新测试。
   - 「测试连接」使用已保存的地址与请求头发起真实工具发现，成功后同步工具清单并刷新连接状态与测试时间，结果展示工具数与延迟。
   - 停用后，所有已挂载 Agent 无法调用该 MCP，并 Toast 提示停/启用结果。
2. **工具管理**
   - 展示 Tool 名称、描述和启用开关（Tab 标题带工具总数）。
   - 停用单个 Tool 后，仅该 Tool 不可调用，其他 Tool 不受影响。
   - 每个 Tool 提供「调用测试」：按工具入参 Schema 展示参数名、类型、必填与说明，并预填 JSON（必填项自动带上，可选参数可一键插入）；真实调用后展示成功/失败、耗时、输出或错误。测试调用计入该 MCP 的调用次数与成功率，并写入调用记录。
   - Tool Key 在同一 MCP 内唯一。
3. **使用配置**
   - 每分钟调用额度，原型示例为 60。
   - 最大并发数，原型示例为 5。
   - 超额请求进入短队列；超过服务超时时间后返回限流/超时错误，并在页面给出橙色提示。
4. **调用记录**
   - 展示最近调用的 Tool、状态（成功/超时）与时间。
   - 点击记录进入全局日志对应详情。

#### 3.2.4 MCP 运行规则

- Agent 运行前同时检查 MCP 服务器和目标 Tool 的启用状态。
- 自定义 Header 在调用前由平台注入，不暴露给模型。
- MCP 响应超过体积限制时截断传给模型，但完整内容可按安全策略保存在日志或对象存储。
- MCP 返回临时错误时遵循 Agent 的自动重试配置；鉴权失败、参数错误等不可重试错误直接返回。
- 每次实际请求计入 Agent 最大工具调用次数和 MCP 调用额度。
- stdio 服务必须在受控进程和文件系统权限下运行，禁止任意 Shell 注入。

#### 3.2.5 MCP 验收标准

- 三种连接类型可正确保存并在列表展示。
- 测试成功和失败均有明确反馈，不产生重复资源。
- Tool 启停能影响 Agent 运行，且在 Agent 编辑页显示失效状态。
- MCP 停用不会删除 Agent 挂载关系，恢复后可继续使用。
- 调用额度、超时和并发限制生效，并生成对应状态日志。
- Header、Token 等敏感信息不出现在明文日志中。

### 3.3 Skills 管理

Skills 是以「打包上传」方式接入的本地化能力插件，适用于需要自定义逻辑/脚本能力、且不便通过远程 MCP 服务提供的场景。

**上传 Skill**

| 字段 | 必填 | 说明 |
|---|---|---|
| 展示名称 | 是 | Skill 名称 |
| Skill 包 | 是 | `.zip` 格式，最大 100MB |
| 使用说明 | 是 | 功能介绍、使用步骤、系统要求等 |

Skills 上传后进入资源池，供智能体配置页「Skills」挂载项选用。

#### 3.3.1 Skill 列表

- 支持按名称、说明搜索，并在工具栏展示「共 N 个结果」。
- 卡片展示图标、名称、版本号、功能说明、包文件名（`skill-package.zip`）、文件大小、被多少 Agent 使用以及更新时间。
- 卡片右上角「更多（…）」打开 Skill 详情抽屉。
- 「版本记录」入口用于查看历史上传版本、发布时间和升级情况；原型仅 Toast 汇总版本数量与最近更新时间，正式实现需提供版本列表与升级入口。
- Skill 图标由名称首字母生成，并按序轮换三种配色。

**Skill 详情抽屉**

- 顶部汇总：图标、名称、版本、包体积与「已校验」状态标记。
- 功能说明：只读展示上传时填写的使用说明。
- 双卡片统计：被引用 Agent 数、最近更新时间与 Skill ID。
- 底部「复制 Skill ID」按钮，复制后 Toast 提示。

#### 3.3.2 上传流程

1. 点击「上传 Skill」打开弹窗。
2. 填写展示名称、选择 Skill 包、填写使用说明（功能、使用步骤与系统要求）。
3. 通过点击或拖拽选择 `.zip` 文件；拖拽经过时上传区高亮，选中后展示文件名。
4. 前端先校验扩展名和大小，后端再进行内容安全与结构校验。
5. 校验通过后创建 Skill 资源并分配初始版本 `v1.0.0`、体积 `1.2 MB`、被引用数 0、更新时间「刚刚」。
6. 上传结果通过 Toast 反馈，成功后资源出现在列表顶部。

**提交约束**：展示名称与 Skill 包均为必填；「上传并校验」按钮在两者缺失时禁用。正式实现必须同时强制校验使用说明（原型仅标注必填但未拦截，见附录 C）。

**包校验要求**

- 文件格式必须为 ZIP，原型限制最大 100 MB。
- 解压后总大小、文件数量和目录深度必须有限制，防止 Zip Bomb。
- 禁止绝对路径、`../` 路径穿越和危险符号链接。
- 必须包含 Skill 清单文件，定义名称、版本、入口、运行环境与权限。
- 包内脚本在隔离环境运行，不得默认访问宿主机凭证和敏感目录。
- 同一 Skill 的版本号不可重复，上传新版本不覆盖历史包。

#### 3.3.3 版本与引用规则

- Skill 资源与 Skill 版本分离；Agent 挂载时应明确使用的版本。
- 新版本上传后，已有 Agent 不自动升级，避免行为变化。
- 删除被 Agent 引用的版本前必须阻止操作或要求先迁移引用。
- Skill 更新、启用、停用和删除均写入系统操作日志。

#### 3.3.4 Skill 验收标准

- 点击选择和拖拽上传均可正常工作。
- 非 ZIP、超大文件、结构不合法和存在路径穿越时拒绝上传并说明原因。
- 上传成功后名称、版本、大小、说明和更新时间正确。
- Agent 能挂载可用 Skill，重复挂载被阻止。
- Skill 加载和运行可在调用日志中追踪到 Agent、runId 和版本。

### 3.4 内置工具管理（新增模块）

内置工具是在平台代码中预先开发、随平台版本发布的通用工具能力（如联网搜索、代码执行、文件解析、时间获取等），无需用户额外接入配置，开箱即用。

#### 3.4.1 内置工具列表

| 字段 | 说明 |
|---|---|
| 工具名称 | 工具的展示名称（如「联网搜索」「代码执行器」） |
| 工具标识 Key | 代码中注册的唯一标识，供智能体挂载引用 |
| 功能说明 | 工具用途、输入输出参数说明 |
| 启用状态 | 启用/禁用，禁用后智能体不可挂载使用，已挂载的智能体同步提示失效 |
| 版本/来源 | 标识该工具随平台哪个版本引入，便于追踪变更 |

#### 3.4.2 能力边界

- 内置工具由平台研发人员在代码层开发、注册、维护；管理界面仅提供「查看、启用/禁用」等运营操作，不支持用户自行新增或编辑工具逻辑。
- 内置工具上线后自动进入资源池，供智能体配置页「内置工具」挂载项勾选使用，与 MCP、Skills 共同构成智能体的工具能力集合。

#### 3.4.3 列表与交互

- 页面标题右侧展示「平台内置」标记，说明该模块只支持查看与启停。
- 支持按工具名称、Tool Key 或功能说明搜索。
- 支持按启用状态筛选（全部状态 / 已启用 / 已停用）。
- 卡片展示图标、名称、Tool Key、功能说明、版本、累计调用次数和可挂载状态（可挂载 / 不可用）；停用工具卡片整体置灰。
- 启用开关为全局开关，变更后立即影响所有 Agent，并 Toast 提示「{工具名}已启用/已停用」。
- 页面底部固定说明卡：「内置工具由平台统一维护」，明确禁用后所有已挂载该工具的智能体同步失效且工具逻辑不可在管理界面编辑。
- 停用工具前应展示被引用 Agent 数量和影响清单；用户确认后执行。
- 被停用工具仍保留在已有 Agent 配置中并显示“不可用”，便于后续恢复。

#### 3.4.4 内置工具注册规范

每个内置工具至少需要注册：

- 唯一 Tool Key。
- 展示名称、功能说明和语义化版本号。
- 输入/输出 JSON Schema。
- 超时时间、权限声明和资源限制。
- 日志脱敏规则。
- 是否允许自动重试以及幂等性声明。

#### 3.4.5 运行与安全

- 代码执行器必须运行在隔离沙箱中，限制 CPU、内存、运行时间、网络和文件系统访问。
- 文件解析器必须限制文件类型、大小并进行恶意文件扫描。
- HTTP 请求工具必须使用域名白名单或明确授权，阻止访问本地元数据地址和内网敏感服务。
- 联网搜索应保留来源链接和检索时间，便于回答引用与审计。
- 每次调用记录输入、输出摘要、耗时、状态与关联 Agent；敏感字段按工具规则脱敏。

#### 3.4.6 验收标准

- 工具启停状态在列表和 Agent 资源选择器中一致。
- 停用工具后新 Agent 不可挂载，已有 Agent 调用返回明确错误。
- 恢复启用后原挂载关系无需重新配置即可使用。
- Tool Key 全局唯一，重复注册时应用启动失败或拒绝加载。
- 工具超时、异常和权限拒绝均生成结构化日志。

### 3.5 模型管理

模型管理统一承载平台内所有可用的大模型资源，提供接入、测试、备注、分组与多版本发布功能。模型既可供智能体挂载使用，也可直接在本模块中按多个版本发布为标准 OpenAI 兼容接口；同一上游模型的各发布版本可以拥有不同的调用标识、鉴权、生成参数和限流配置，无需单独的服务管理模块。

#### 3.5.1 模型接入（录入 OpenAI 规范接口）

albedo 支持录入任意 **兼容 OpenAI API 规范** 的模型服务，包括但不限于 OpenAI 官方、Azure OpenAI、DeepSeek、通义千问、月之暗面、自建 vLLM/Ollama 推理服务等，只要其接口形态遵循 OpenAI 协议（`/v1/chat/completions`、`/v1/embeddings` 等），均可一键接入。

**录入字段**

| 字段 | 必填 | 说明 |
|---|---|---|
| 模型展示名称 | 是 | 平台内展示用名称 |
| 模型标识 Model ID | 是 | 调用上游接口时实际传入的 `model` 参数，如 `gpt-4o`、`deepseek-chat` |
| 模型类型 | 是 | Chat（对话） / Embedding（向量化） / Rerank（重排序） / 多模态（图片/语音）等 |
| 所属渠道/厂商 | 否 | 便于分类管理，如 OpenAI / Azure / DeepSeek / 自建等 |
| Base URL | 是 | 上游服务地址，如 `https://api.openai.com/v1` |
| API Key | 是 | 上游鉴权密钥，加密存储，页面脱敏展示 |
| 自定义请求头 | 否 | 适配需要额外 Header 的上游服务或代理场景 |
| 超时时间 | 是 | 默认 60 秒 |
| 备注 | 否 | 记录模型用途、适用场景、成本说明或维护信息，可在模型详情中随时修改 |
| 启用状态 | 是 | 启用/禁用，禁用后不可被新建配置选用 |

**连通性测试**：保存前支持「测试连接」，发起一次真实调用验证 Base URL、API Key、Model ID 的正确性，避免无效配置流入生产。

模型资源本身不设置默认温度。Agent 内部调用所需的生成参数在智能体配置中管理；模型对外发布所需的温度、最大输出 Tokens 等参数在具体发布版本中管理。

##### 3.5.1.1 模型列表

**搜索与筛选**

- 搜索范围：模型展示名称、上游 Model ID 与备注；不区分大小写。
- 类型筛选：全部类型、Chat、Embedding、Rerank、多模态（四类在原型中均已可选）。
- 厂商筛选：根据已有模型动态生成，原型展示 OpenAI、DeepSeek、阿里云。
- 列表底部固定展示平台统一调用地址 `https://api.albedo.local/v1` 并提供复制入口。
- 产品化可增加连接状态、启用状态和发布状态筛选。

**列表字段**

| 字段 | 说明 |
|---|---|
| 模型 | 图标、展示名称、上游 Model ID、备注摘要 |
| 类型/厂商 | 模型能力类型和渠道 |
| 连接状态 | 正常、未测试或异常 |
| 发布版本 | 生效版本数和版本总数；无版本时显示未发布 |
| 平均延迟 | 最近统计窗口的平均上游响应时间 |
| 启用 | 模型资源全局开关 |
| 操作 | 配置、首次发布或发布新版本 |

**操作约束**

- 未启用或未通过连接测试的模型不能发布版本：「发布 / 发布新版本」按钮禁用（`enabled && connected` 为前置条件）。
- 模型停用前需提示将影响的 Agent 数和生效发布版本数。
- 模型启用不代表连接正常；选择或发布时必须同时检查两种状态。
- 停用模型后其全部发布版本不可调用，但版本记录与配置保留。

##### 3.5.1.2 接入弹窗

- 展示名称、Model ID、类型、厂商、Base URL、API Key 和备注均可在保存前编辑。
- API Key 支持显示/隐藏切换，默认密码模式。
- 连接测试使用当前表单值，不要求先落库。
- 原型允许未测试直接保存并标记“未测试”；正式生产建议允许保存草稿，但不得被 Agent 选择或发布，直至测试成功。
- 保存成功后 Key 仅保留脱敏后缀用于定位，不可再次读取完整明文。

##### 3.5.1.3 模型配置抽屉

- 顶部汇总：名称、Model ID 与连接状态标记（连接正常 / 未测试）。
- 可查看/修改 Base URL 与备注；「保存更改」校验 Base URL 不能为空，为空时提示「Base URL 不能为空」。
- 上游 API Key 只读展示脱敏值 `sk-••••••••{后缀}`，不可在抽屉内编辑；超时时间原型为占位（60 秒）。
- 不提供资源级默认温度。
- 备注用于记录用途、适用场景、成本、配额、负责人或维护注意事项。
- 下方「发布版本」区：标题旁提供「发布新版本」入口（同样受启用 + 已连接约束）；每个版本以卡片展示版本号、状态标记（已发布/已停用）、调用标识、独立启停开关、温度 / 输出 Tokens / QPM / Key 后缀四宫格，以及「发布于 … · 请求头 未配置/已配置」。
- 每个版本卡片提供「轮换密钥」与「删除版本」两个操作；删除需二次确认，并明确列出失效的调用标识、Key 后缀及对同模型其他版本无影响。
- 无发布版本时展示「尚未发布任何版本」虚线空态。
- 保存连接配置后应将连接状态置为待复测，避免沿用旧测试结果（原型未实现，见附录 C）。

##### 3.5.1.4 连接测试规范

| 模型类型 | 最小测试方式 |
|---|---|
| Chat | 发送最短对话请求并验证返回结构 |
| Embedding | 对固定短文本生成向量并验证维度 |
| Rerank | 对固定查询和文档列表执行排序 |
| 多模态 | 根据声明能力执行最小文本或图片请求 |

测试结果应记录测试时间、延迟、HTTP 状态、错误分类和响应摘要；不得记录完整 API Key。

#### 3.5.2 模型资源池的复用场景

接入后的模型将作为平台级资源，可在以下场景中被统一选用：
- 智能体配置页「模型」挂载项（Chat 类模型）
- 在模型管理中发布为对外可调用的 OpenAI 兼容 API（见 3.5.4）

#### 3.5.3 模型分组（产品化预留）

- 当前原型仅支持按模型类型和厂商筛选，尚未提供自定义分组。
- 产品化后可按用途或场景添加标签（如通用、代码、长文本、低成本），便于筛选管理。
- 个人单用户版本不引入组织/业务线层级，标签仅作为轻量分类，不承担权限隔离。

#### 3.5.4 模型发布（P0）

模型发布是「模型管理」内的功能，不设置独立导航或模块。用户可为一个已启用且通过连通性测试的模型创建多个发布版本，每个版本拥有独立的调用标识、API Key、请求头、生成参数和 QPM。各版本共用平台统一调用地址，但可分别启停和演进。

**发布操作**

1. 在模型列表或详情页点击「发布 / 发布新版本」。
2. 弹窗顶部展示平台统一调用地址与该模型已有版本数；版本号默认 `v{N}.0.0`（N = 已有版本数 + 1），模型调用标识默认为上游 Model ID，已有版本时默认 `{Model ID}-{版本号}`。
3. 设置该版本的自定义 API Key，按需填写自定义请求头（JSON），并配置温度（默认 0.7）、最大输出 Tokens（默认 4096）和 QPM（默认 60）。
4. 「确认发布」在版本号为空、调用标识为空、Key 少于 12 字符、温度越界、输出 Tokens 或 QPM 小于 1 时禁用。
5. 冲突时给出明确提示：版本号重复提示「该版本号已存在，请使用新的版本号」；调用标识被其他版本占用提示「模型调用标识已被占用，请更换」；请求头非法 JSON 提示「自定义请求头必须是合法的 JSON 对象」。
6. 确认发布后，该版本进入模型详情的「发布版本」列表；用户可继续为同一模型发布其他版本，或独立停用、删除已有版本。
7. 发布成功弹窗展示一次性的完整密钥，并提供已填入该密钥的 **curl 调用示例**（Chat 模型指向 `/v1/chat/completions`，Embedding 模型指向 `/v1/embeddings`），用户可直接复制执行，无需额外拼装请求。
8. 弹窗底部提示密钥需妥善保存，各版本鉴权、参数与限流相互独立，日志不记录明文密钥。

**发布配置与结果**

| 字段 | 说明 |
|---|---|
| 统一调用地址（Base URL） | 发布成功后提供平台统一地址，例如 `https://albedo.example.com/v1`；所有已发布模型及其版本共用该地址，通过 `model` 参数区分，不为每个模型或版本生成独立地址 |
| 版本号 | 同一模型内唯一的发布配置版本，如 `v1.0.0`、`v1.1.0`；用于管理与审计，不改变上游 Model ID |
| 模型调用标识 | 下游调用时传入的 `model` 值，在全部发布版本（含已停用版本）中全局唯一；与模型接入配置关联，上游实际 Model ID 不变 |
| 自定义 API Key | 用户可自行设置的对外调用密钥，与上游 API Key、管理界面登录用访问 Key 相互独立；仅授权调用当前发布版本 |
| 自定义请求头（JSON） | 转发到上游模型服务时附加的 Header；必须为合法 JSON 对象，适用于网关路由、环境标识或额外鉴权 |
| 温度 | 当前发布版本的默认 `temperature`，取值范围 `0–2` |
| 最大输出 Tokens | 当前发布版本允许的最大输出 Token 数；作为默认值及安全上限 |
| QPM | 当前发布版本每分钟允许的请求数；超限请求返回限流错误 |
| 发布状态 | 每个版本独立处于已发布/已停用状态；模型列表展示生效版本数，详情页支持逐版本启停 |

**多版本规则**

- 同一模型可同时存在多个生效发布版本，例如稳定版、创意版和低成本版；各版本可使用不同的调用标识和参数。
- 版本号在同一模型内唯一，模型调用标识在整个平台全部发布版本中唯一；已停用版本仍保留标识，避免恢复启用时发生路由冲突。
- 新版本发布不覆盖旧版本；停用某一版本不影响同一模型的其他版本，也不影响智能体内部挂载该模型。
- 发布版本支持删除：删除后该版本的调用标识与自定义 Key 立即失效并释放，后续可用同一调用标识重新发布；删除操作写入系统日志，模型资源本身与其他版本不受影响。

**字段校验**

| 字段 | 校验规则 |
|---|---|
| 版本号 | 必填；同一模型内唯一；建议使用 SemVer 格式 |
| 模型调用标识 | 必填；平台内唯一；建议仅允许字母、数字、点、下划线和连字符 |
| 自定义 API Key | 必填；原型最少 12 个字符；产品化建议至少 24 个高熵字符 |
| 自定义请求头 | 可空；非空时必须是 JSON 对象，不能是数组或基础类型 |
| 温度 | 数字，范围 0～2 |
| 最大输出 Tokens | 正整数，且不超过上游模型上下文/输出能力 |
| QPM | 正整数；为 0 不表示不限流，应提供显式“不限流”配置 |

**请求参数优先级**

1. 平台安全上限和上游模型硬限制。
2. 发布版本配置。
3. 下游请求参数。

推荐策略：温度允许下游覆盖，但仍受 0～2 范围限制；最大输出 Tokens 允许下游请求更小值，不允许超过发布版本上限；QPM 不允许请求覆盖。

**请求头合并规则**

- 平台固定头（如追踪 ID）优先保留，不允许被自定义头覆盖。
- `Authorization` 默认由模型上游 Key 生成；如允许版本自定义鉴权头，必须定义清晰优先级。
- 禁止自定义 `Host`、`Content-Length`、连接控制类 Header。
- Header 名称大小写不敏感，重复项按规范合并或拒绝。
- 请求头值按敏感配置加密，详情页仅展示是否配置或脱敏内容。

**QPM 限流规则**

- 限流维度为发布版本，可采用固定窗口或令牌桶，但接口返回行为必须稳定。
- 超限返回 HTTP 429，并包含机器可读错误码和建议重试时间。
- 流式连接在成功建立时计一次请求，不按输出分片重复计数。
- 鉴权失败请求不消耗模型 QPM，但可纳入安全防刷限流。

**接口形态**

| Endpoint | 说明 |
|---|---|
| `POST /v1/chat/completions` | 调用已发布的 Chat 模型，支持流式（`stream=true`）与非流式 |
| `POST /v1/embeddings` | 调用已发布的 Embedding 模型 |
| `GET /v1/models` | 查询当前 API Key 有权调用且已发布、启用的模型标识 |

请求/响应体结构与 OpenAI API 保持一致，仅开放对应模型类型支持的接口。下游系统可复用 OpenAI SDK，将 `base_url` 设置为统一调用地址、`api_key` 设置为目标版本的自定义密钥、`model` 设置为该版本的模型调用标识即可接入。HTTP 请求通过 `Authorization: Bearer <API Key>` 鉴权。平台在转发时合并该版本配置的自定义请求头，并应用温度、最大输出 Tokens 与 QPM 约束。

一期仅允许 Chat 和 Embedding 类型创建对外发布版本。Rerank 与多模态模型可以接入资源池并完成连通性测试，但在对应请求/响应协议和 Endpoint 明确前，不开放对外发布；Agent 默认模型仅允许选择已启用、连接正常的 Chat 模型。

**Chat 调用示例**

```http
POST /v1/chat/completions
Authorization: Bearer alb_sk_live_xxx
Content-Type: application/json
```

```json
{
  "model": "albedo-gpt-4.1",
  "messages": [
    {
      "role": "user",
      "content": "请总结这段内容"
    }
  ],
  "stream": true,
  "temperature": 0.5,
  "max_tokens": 2048
}
```

**鉴权与路由顺序**

1. 解析 Bearer Token，定位其授权的发布版本。
2. 校验请求中的 `model` 是否等于该版本调用标识。
3. 校验发布版本、模型资源均处于启用状态。
4. 执行 QPM 限流。
5. 合并并校验生成参数和自定义 Header。
6. 将调用标识映射为上游真实 Model ID 后转发。
7. 流式透传或组装响应，并写入模型调用日志。

**标准错误**

| HTTP 状态 | 错误码示例 | 场景 |
|---|---|---|
| 400 | `invalid_request` | 参数缺失、JSON 非法、参数越界 |
| 401 | `invalid_api_key` | Key 缺失、无效或已失效 |
| 403 | `model_not_allowed` | 标识存在，但当前 Key 无权调用（属于其他发布版本） |
| 404 | `model_not_found` | 调用标识不存在或版本已删除 |
| 409 | `model_version_disabled` | 版本或模型已停用 |
| 429 | `rate_limit_exceeded` | 超过版本 QPM |
| 502 | `upstream_error` | 上游返回异常 |
| 502 | `upstream_not_configured` | 模型未配置上游凭证，无法转发 |
| 504 | `upstream_timeout` | 上游请求超时 |

**管理与安全要求**

- 上游 API Key 不对外暴露；各发布版本的自定义 API Key 安全存储、默认脱敏展示，不在调用日志中记录明文。
- 支持逐版本修改自定义 API Key，保存后该版本的旧 Key 立即失效；不允许使用空值或明显弱密钥。
- 自定义请求头中包含的鉴权信息按敏感配置存储，日志中仅记录是否配置，不记录明文。
- 停用发布版本后仅停止该版本的对外调用；模型整体禁用后，其全部发布版本均不可用。
- 对外调用按发布版本执行 QPM 限流并记录版本信息，不引入多模型负载均衡、故障转移或灰度切流等额外能力。

**验收标准**

- 一个模型可连续创建两个及以上发布版本，版本号、调用标识、API Key、请求头、温度、最大输出 Tokens 与 QPM 均可独立配置。
- 发布成功后可使用统一地址、目标版本的自定义 API Key 和模型调用标识完成 SDK 调用，并按该版本配置转发与限流。
- 不同模型和版本共用同一 Base URL；未发布/已停用版本、无效 Key 或 Key 无权访问的模型标识均不可调用。
- 修改 Key、停用单个版本或禁用模型后，相关访问凭证或调用按规则失效，其他发布版本不受影响。

调用日志是平台统一运行观测入口，页面侧重“查询与定位”，日志数据规范详见第 7 章。

#### 3.6.1 顶部指标

| 指标 | 说明 |
|---|---|
| 今日调用 | 当日全部 Run/调用数量及较昨日变化 |
| 成功率 | 最近 24 小时成功调用比例 |
| 平均耗时 | 最近统计窗口的平均耗时及变化 |

指标卡与概览页使用同一统计口径和数据源，避免同一指标显示不一致。

#### 3.6.2 类型快捷筛选

- 全部
- 会话
- MCP
- Skill
- 内置工具
- 模型
- 系统操作

类型标签旁展示当前数据范围内的记录数。类型、状态、时间和关键词筛选同时生效。

#### 3.6.3 查询条件

| 条件 | 规则 |
|---|---|
| 关键词 | 搜索对象名称、摘要、Agent 名称、runId；产品化可增加 threadId |
| 状态 | 全部、成功、失败、超时；运行中状态仅在实时日志中展示 |
| 时间 | 最近 7 天（默认）、今天、最近 30 天、最近 1 年；自定义时间范围为一期后补 |
| 更多筛选 | 展开后按「智能体」筛选（选项来自日志中出现的 Agent），并展示「共 N 条匹配记录」；产品化继续扩展资源 ID、调用来源、模型版本、API Key 后缀等 |
| 重置 | 一键清空关键词，恢复全部类型、全部状态、默认时间与全部智能体 |

#### 3.6.4 列表

- 字段：时间（时间 + 日期）、类型（彩色图标）、调用对象/摘要、Agent、Run ID、耗时、状态、详情入口（右箭头）。
- 默认按时间倒序；点击任意行打开调用详情抽屉。
- 支持分页，原型每页 8 条，底部展示「共 N 条记录 · 第 X / Y 页」并提供上一页、页码与下一页；任何筛选条件变化后回到第 1 页。
- 正式实现应支持服务端分页与更大的单页条数（见 9.1），筛选条件随分页请求提交。
- 无结果时展示空状态「没有找到匹配的日志」，不隐藏当前筛选条件。
- 顶部「导出日志」使用当前筛选条件生成异步任务，避免大数据量阻塞页面；原型仅 Toast 提示「日志导出任务已创建」。

#### 3.6.5 调用详情

详情抽屉包含：

- 头部：类型图标、日志对象名称、状态标记、发生时间与耗时。
- 四宫格摘要：Run ID、Thread ID、智能体、Token 用量（无数据显示 `—`）。
- 「执行链路」：同 `runId` 的全部日志按真实时间排序组成时间线，节点带成功/失败圆点、类型图标、名称、摘要与相对偏移；无关联日志时仅展示当前记录。
- 「请求参数 / 输入」与「响应结果 / 输出」代码块；失败时输出区使用深色告警配色。
- 失败或超时时额外展示「调用异常」卡片，给出错误摘要与排查建议（如「请检查上游服务状态与配额配置」）。

输入和输出过长时在页面内滚动，完整内容可下载；敏感字段必须脱敏。

### 3.7 系统设置

#### 3.7.1 常规设置

| 字段 | 原型值 | 说明 |
|---|---|---|
| 工作区名称 | 于继钊的 AI 工作台 | 用于管理界面和发布文档展示 |
| 默认语言 | 简体中文 | 可切换 English；影响界面与默认生成语言 |
| 默认时区 | Asia/Shanghai (UTC+8) | 影响日志时间、统计日期和系统变量 |
| 平台域名 | `https://api.albedo.local` | 用于生成 Agent 与模型发布地址 |

使用体验开关：

- 产品使用数据：发送匿名统计，默认开启；不得包含 Prompt、密钥或用户内容。
- 自动归档历史会话：超过日志保留周期后自动归档，默认开启。

#### 3.7.2 访问与安全

- 展示管理界面访问 Key 的脱敏值（原型为 `alb_access_••••••••••••K9P4`）与「有效」状态标记，提供复制按钮与「修改 Key」。
- 修改表单包含当前访问 Key（密码模式，原型预填 `albedo-demo-2026`）、新访问 Key（可切换明文）、确认新 Key。
- 校验与提示：新 Key 少于 12 字符提示「新 Key 至少需要 12 个字符」；两次输入不一致提示「两次输入的新 Key 不一致」；「确认修改」在两者均不足 12 字符时禁用。
- 字段说明：「至少 12 个字符，建议混合字母、数字与符号」；页面同时提示修改后当前会话仍有效，其他会话将在下次验证时失效。
- 保存后旧 Key 立即失效并 Toast 提示；正式实现还需服务端校验复杂度与历史重复。
- 「密钥安全状态」卡汇总三类凭证数量与加密状态：上游模型密钥（4 个，全部已加密）、发布 API Key（5 个，相互隔离）、MCP 鉴权配置（2 个，Header 已脱敏）。

#### 3.7.3 日志与存储

| 设置 | 可选值/行为 |
|---|---|
| 日志保留周期 | 30、60、90（推荐，默认）、180、365 天；选择后立即生效并持久化 |
| 存储估算 | 展示当前占用与按当前策略预计清理量，文案随所选周期联动（原型：当前 284 MB，每月清理约 96 MB） |
| 保存策略 | 更新后对后续清理任务生效，Toast 提示「日志保留策略已更新」 |
| 重置演示数据 | 危险卡片（红色语义），清除本地创建/修改数据并恢复预置 Agent、资源、日志与设置 |

重置数据为危险操作，正式实现必须二次确认并清楚说明不会/会影响哪些外部资源。生产环境不应提供无鉴权的一键全量重置。

#### 3.7.4 设置验收

- 常规设置保存后刷新页面仍然有效。
- 平台域名变化后新生成的发布地址同步更新，既有外部地址的迁移策略明确。
- 修改访问 Key 时错误当前 Key、弱 Key、两次输入不一致均被拒绝。
- 日志保留周期变化后存储估算更新，清理任务可审计。
- 重置演示数据恢复所有预置 Agent、资源和设置，但不影响登录安全配置，除非用户明确确认。

## 4. 智能体能力组合模型（全景图）

```
                         ┌───────────────────────────┐
                         │        模型管理资源池       │
                         │ (OpenAI 规范模型统一接入)   │
                         └─────────────┬─────────────┘
                     ┌─────────────────┴─────────────┐
                     ▼                                ▼
              智能体对话模型                      模型发布
                     │                      (统一地址 + 多版本配置)
         ┌───────────┼───────────┐
         ▼           ▼           ▼
    ┌──────────┐ ┌───────────┐ ┌──────────┐
    │ MCP 服务器 │ │  Skills   │ │ 内置工具  │
    │  资源池    │ │  资源池   │ │  资源池   │
    └─────┬─────┘ └─────┬─────┘ └────┬─────┘
          │             │            │
          └──────┬──────┴────────────┘
                 ▼
          ┌─────────────┐
          │   智能体     │  （提示词 + 变量 + 挂载资源组合）
          │   Agent     │
          └──────┬──────┘
                  │ 发布
          ┌───────┴────────┐
          ▼                ▼
   标准对话 API      AGUI 协议接口
 （文本流式问答）   （结构化事件流，
                     支持前端对话式 UI
                     工具调用可视化/状态同步）
```

**设计要点**：模型、MCP、Skills、内置工具四类资源均为平台级资源池，彼此解耦、独立治理、可被多个智能体复用；智能体是对上述资源的编排产物，向外发布时可根据接入方技术栈选择「标准 API」或「AGUI 协议」两种形态；模型除了被智能体消费外，还可在模型管理中直接创建多个发布版本，通过统一调用地址与版本级调用标识、API Key、请求参数及 QPM 对外提供服务，一套模型资源支撑两类对外输出（Agent 能力 / 模型能力）。

### 4.1 Agent 单次运行时序

1. 接收测试会话、标准 API 或 AGUI 请求。
2. 完成 Agent 发布状态、调用凭证和请求参数校验。
3. 生成 `runId`，解析或创建 `threadId`，写入 `RUN_STARTED`。
4. 读取 Agent 的不可变配置快照：Prompt、变量、模型、生成参数、挂载能力与高级限制。
5. 注入系统变量和请求变量，组装历史上下文。
6. 调用默认模型生成回复或工具调用计划。
7. 如模型请求工具：
   - 校验资源和 Tool 启用状态；
   - 校验最大工具调用次数、运行时长、MCP 配额；
   - 执行工具并记录输入、输出、耗时和状态；
   - 将工具结果返回模型继续推理。
8. 生成最终回复；标准 API 返回文本，AGUI 输出结构化事件流。
9. 汇总 Token、耗时、工具次数和运行状态，写入 `RUN_FINISHED` 或 `RUN_ERROR`。
10. 会话、模型、工具日志通过同一 `runId`/`threadId` 关联。

### 4.2 配置归属边界

| 配置 | 归属层级 | 原因 |
|---|---|---|
| 上游 Base URL、Model ID、上游 API Key | 模型资源 | 描述真实上游连接 |
| Agent 温度、Top P、最大输出 Token | Agent | 控制该 Agent 的内部生成行为 |
| 模型发布温度、输出上限、QPM、外部 Key | 模型发布版本 | 控制特定外部调用入口 |
| Tool 启用、MCP 地址 | 工具资源 | 平台全局能力状态 |
| Agent 最大工具调用次数、运行时长 | Agent | 控制单次编排运行 |
| 日志保留周期 | 工作区 | 对全部日志统一生效 |

同一个含义不得在多个层级重复设置默认值；若必须存在覆盖关系，界面和文档必须说明优先级。

### 4.3 配置快照与一致性

- 每次 Run 启动时读取并冻结一份配置快照，运行途中保存的新配置只影响后续 Run。
- 日志保存关键配置版本或摘要，保证历史运行可解释。
- 资源停用属于安全状态变更，可立即阻断尚未执行的后续工具调用；已经完成的结果不回滚。
- Agent 保存和发布应使用乐观并发控制，防止多个页面覆盖彼此修改。
- 多资源保存失败时不允许只写入部分挂载关系；应采用事务或可恢复机制。

## 5. 典型用户流程

### 流程一：接入模型并用于智能体
1. 进入「模型管理」→「新增模型」，填写 Base URL、API Key、Model ID 等信息，测试连接成功后保存。
2. 进入「智能体」→ 创建/编辑智能体，在「模型」挂载项中选择已接入的模型。
3. 右侧测试会话中验证对话效果。

### 流程二：接入外部工具能力
1. 「MCP 管理」→ 创建 MCP 服务器，配置 URL、鉴权请求头。
2. 在「工具管理」中勾选需要开放的工具。
3. 智能体配置页挂载该 MCP 服务器并测试工具调用。

### 流程三：扩展自定义 Skill
1. 将自定义能力打包为 zip。
2. 「Skills 管理」→ 上传 Skill，填写使用说明。
3. 智能体配置页挂载该 Skill。

### 流程四：使用内置工具
1. 进入「内置工具管理」查看平台已内置的工具列表及功能说明。
2. 确认所需工具处于「启用」状态。
3. 智能体配置页「内置工具」挂载项中勾选该工具，测试会话验证调用效果。

### 流程五：将智能体发布为 AGUI 接口供前端集成
1. 智能体配置完成并通过测试会话验证。
2. 进入「发布」入口，勾选「AGUI 接口」，生成 Endpoint 与 API Key。
3. 前端（支持 AGUI 协议的对话式 UI 框架）配置该 Endpoint 与密钥，即可直接获得流式文本、工具调用可视化、状态同步等完整交互体验，无需额外开发适配层。

### 流程六：在模型管理中发布模型供外部调用
1. 「模型管理」中选中已启用且通过连通性测试的模型，点击「发布」。
2. 填写版本号、模型调用标识和自定义 API Key，按需配置自定义请求头（JSON）、温度、最大输出 Tokens 与 QPM。
3. 发布成功弹窗一次性展示该版本密钥，并给出已填入密钥的 curl 示例；复制后即可调用。
4. 如需不同参数或限流策略，可继续为同一模型发布新版本；不再需要的版本可在配置抽屉中删除，删除后其 Key 立即失效。

### 流程七：排查一次 Agent 调用失败
1. 从通知、Agent 对话历史或调用日志进入失败记录。
2. 通过 `runId` 展开执行链路，定位失败发生在模型、MCP、Skill 还是内置工具。
3. 查看请求参数、响应/错误摘要、耗时和资源状态。
4. 若为模型 429，检查上游配额或模型发布版本 QPM；若为工具超时，检查 MCP 超时和 Agent 运行时长。
5. 调整资源或 Agent 配置后，在测试会话复现并确认成功。

### 流程八：轮换模型发布版本密钥
1. 进入模型详情，定位目标发布版本。
2. 生成或填写新的自定义 API Key。
3. 保存后复制新 Key，并在下游应用中完成切换。
4. 旧 Key 立即失效；系统操作日志记录轮换时间和 Key 后缀。
5. 若需要无中断轮换，后续版本可支持短时双 Key 过渡，但一期不包含。

### 流程九：停用被 Agent 使用的资源
1. 在模型、MCP 或内置工具页面关闭启用状态。
2. 系统展示受影响 Agent 和发布版本数量。
3. 用户确认后资源停用，相关 Agent 配置保留引用并显示异常。
4. 新运行在调用该资源前失败并返回明确原因。
5. 资源恢复后，原挂载关系自动恢复可用，无需重新选择。

## 6. 访问与安全

| 维度 | 说明 |
|---|---|
| 登录方式 | 面向个人用户，登录界面仅需填写固定的访问 Key（在「系统设置」中预先配置）即可登录，无需注册账号、无需选择租户/组织 |
| 密钥安全 | 模型上游 API Key 加密存储、页面脱敏展示；每个模型发布版本使用独立的自定义 API Key，与上游密钥、管理界面访问 Key 相互隔离，支持逐版本修改并使旧 Key 失效 |
| 调用审计 | 智能体对话历史、MCP/Skill/内置工具调用、模型对外调用等均完整留存日志并可追溯，日志不记录明文密钥，支撑问题排查，详见第 7 章「运行时日志与审计」 |
| 限流保护 | 模型对外发布版本可独立配置 QPM，MCP 调用可配置调用额度，防止资源滥用 |

### 6.1 凭证分类与隔离

| 凭证 | 用途 | 可访问范围 | 轮换影响 |
|---|---|---|---|
| 管理访问 Key | 登录管理界面 | 整个个人工作区 | 旧 Key 失效，管理会话按策略重新认证 |
| 模型上游 API Key | 平台调用模型供应商 | 单个模型连接 | 影响 Agent 内部调用及该模型全部发布版本 |
| 模型发布 API Key | 外部调用某一模型发布版本 | 单个发布版本 | 仅影响目标版本 |
| Agent API Token | 外部调用某一 Agent | 单个 Agent | 仅影响目标 Agent 的发布接口 |
| MCP 鉴权 Header | 平台调用 MCP 服务 | 单个 MCP 连接 | 影响该 MCP 的全部 Tool |

不同凭证不得复用同一存储字段或通过界面互相读取。

### 6.2 存储与展示

- 服务端使用密钥管理服务或主密钥加密敏感值，数据库不存明文。
- 前端只在创建/重置成功时一次性展示完整新密钥，此后仅显示固定长度后缀。
- 复制密钥为显式用户动作；禁止进入埋点、错误上报、URL、浏览器历史和服务日志。
- 自定义请求头按敏感配置处理，即使字段名不叫 Authorization 也需检测常见秘密。
- 配置导出默认不包含密钥；如提供加密备份，需单独密码和明确风险提示。

### 6.3 传输与会话

- 管理界面和所有 API 仅允许 HTTPS；本机开发环境可例外。
- 登录成功后使用受保护会话，不在每个页面 URL 中携带访问 Key。
- 会话 Cookie 应使用 `HttpOnly`、`Secure`、`SameSite`；若使用 Token，则存储和刷新策略需防 XSS。
- 管理会话需有空闲超时和绝对有效期。
- 退出登录立即清除本地认证状态和服务端会话。

### 6.4 输入与运行安全

- 所有 JSON、URL、文件和数值字段在前后端双重校验。
- Prompt 与工具输出视为不可信内容，不能覆盖平台安全指令或直接触发未授权工具。
- 文件上传执行类型、大小、病毒、路径穿越和压缩炸弹检查。
- HTTP/MCP 请求防止 SSRF，阻断云元数据地址、回环地址和未经授权的内网网段。
- 代码执行、Skill 脚本、stdio MCP 均在最小权限沙箱运行。
- 富文本或 Markdown 输出进行 XSS 清理。

### 6.5 安全审计事件

以下事件必须写入系统操作日志：

- 登录成功、失败、退出和访问 Key 修改。
- 上游模型 Key、发布 Key、Agent Token、MCP 鉴权配置创建或轮换。
- 资源启用/停用、发布/取消发布、日志导出和保留策略修改。
- 失败登录、异常频率调用、敏感配置读取或复制可按风险策略记录。

审计日志只记录操作者、对象、动作、结果、时间和脱敏后缀，不记录秘密值。

## 7. 运行时日志与审计（新增重点能力）

为保障系统可观测性、问题排查效率与调用合规追溯，平台需对运行时产生的各类调用行为进行完善的结构化日志记录，覆盖智能体会话、MCP 调用、Skill 加载与访问、内置工具调用、模型调用、系统操作等维度，并在「运营与治理」分组下的「调用日志」模块统一查询。

### 7.1 日志体系总览

| 日志类型 | 记录范围 | 核心字段 | 查看入口 |
|---|---|---|---|
| 智能体会话记录 | 智能体每一轮对话的完整生命周期（用户输入、Agent 回复、期间触发的工具/模型调用链路） | 会话标识（threadId）、运行标识（runId）、智能体 ID/名称、消息角色与内容、来源（测试会话/标准 API/AGUI）、发起时间、总耗时、Token 用量、运行状态 | 智能体配置页「对话历史」Tab；「调用日志」→会话维度 |
| MCP 调用记录 | 智能体挂载的 MCP 工具每一次被调用的过程 | 关联 runId/threadId、MCP 服务器 ID/名称、工具名称、请求参数（入参原文）、响应结果（出参原文/错误信息）、调用耗时、调用状态（成功/失败/超时）、发起智能体 | 「调用日志」→MCP 维度；MCP 详情页「调用记录」Tab |
| Skill 加载/访问记录 | Skill 资源被智能体挂载、加载、调用的情况 | 关联 runId/threadId、Skill ID/名称、触发动作（挂载加载/运行时调用）、加载或调用结果、发生时间、发起智能体 | 「调用日志」→Skill 维度；Skill 详情页「访问记录」Tab |
| 内置工具调用记录 | 内置工具每一次被调用的过程 | 关联 runId/threadId、工具标识 Key、输入参数（原文）、输出结果（原文/错误信息）、调用耗时、调用状态、发起智能体 | 「调用日志」→内置工具维度；内置工具详情页「调用记录」Tab |
| 模型调用日志 | 智能体内部的模型调用，以及模型管理中对外发布后被下游调用 | 关联 runId/threadId（若有）、模型 ID、发布版本/调用标识、调用来源（智能体内部/对外发布 API）、是否流式、请求与响应摘要、输入/输出 Token 用量、耗时、状态码或错误信息、调用方标识（API Key 后缀，脱敏） | 「调用日志」→模型维度；模型详情页「调用日志」Tab |
| 系统操作日志 | 管理侧配置类操作，如资源的创建/编辑/删除/启用禁用、模型版本发布/停用、密钥变更、访问 Key 修改等 | 操作时间、操作人（个人用户场景下可固定为本机）、操作对象类型与 ID、操作类型、变更前后关键字段摘要、操作结果 | 「调用日志」→系统操作维度（即「系统操作日志」） |

### 7.2 关键设计要求

- **全链路关联**：同一轮智能体运行产生的会话记录、MCP/Skill/内置工具调用记录、模型调用日志，均通过统一的 `runId`/`threadId` 关联；在「对话历史」详情中可一键展开查看该轮对话内部触发的全部工具调用与模型调用明细，还原完整执行链路（例如：用户提问 → 模型推理 → 调用某 MCP 工具（含入参/出参）→ 模型二次推理 → 最终回复）。
- **调用参数与响应全量留存**：MCP 调用记录、内置工具调用记录须完整记录「请求参数」与「返回结果/错误」原文（而非仅记录「调用了某工具」这一动作），便于复现问题、评估工具效果与排查异常；参数/结果过大时列表中可截断展示，但保留完整原文供展开或下载查看。
- **模型调用留痕但可控脱敏**：模型调用日志记录请求/响应摘要、Token 用量、耗时等，避免无谓占用存储与泄露风险的同时，支持按需查看完整 Prompt 与回复内容用于调试。
- **失败与异常可见**：调用失败、超时、工具报错、模型报错等均需记录错误详情（错误码/错误信息摘要），日志列表以状态标识区分成功/失败/超时，支持按状态筛选定位问题。
- **敏感信息脱敏**：日志中不得记录任何明文密钥（上游模型 API Key、模型对外发布的自定义 API Key、系统访问 Key、MCP 鉴权 Header 等）；涉及密钥的字段默认脱敏展示，仅保留必要后缀用于定位来源。
- **保留周期与清理**：日志按可配置的保留周期（默认建议 90 天）滚动清理或归档，避免数据无限增长，保留策略可在「系统设置」中配置。
- **统一查询与筛选**：「运营与治理」→「调用日志」支持按时间范围、智能体、日志类型（会话/MCP/Skill/内置工具/模型/系统操作）、调用状态、关键字（工具名/模型名/操作对象）组合筛选，并支持导出，便于审计与问题排查。

### 7.3 通用日志字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `logId` | string | 是 | 日志唯一 ID |
| `timestamp` | datetime | 是 | UTC 存储，按工作区时区展示 |
| `type` | enum | 是 | 会话、MCP、Skill、内置工具、模型、系统操作 |
| `status` | enum | 是 | running、success、failed、timeout |
| `runId` | string | 运行日志必填 | 单次运行关联 ID |
| `threadId` | string | 会话相关必填 | 多轮会话关联 ID |
| `agentId` | string | Agent 运行时必填 | 发起 Agent |
| `resourceId` | string | 资源调用时必填 | 模型/MCP/Skill/工具 ID |
| `source` | enum | 是 | 测试会话、标准 API、AGUI、模型发布 API、系统操作 |
| `durationMs` | number | 已结束必填 | 调用耗时 |
| `inputSummary` | string | 否 | 脱敏后的输入摘要 |
| `outputSummary` | string | 否 | 脱敏后的输出或错误摘要 |
| `tokenUsage` | object | 模型调用可选 | 输入、输出与总 Token |
| `errorCode` | string | 失败时必填 | 机器可读错误码 |
| `errorMessage` | string | 失败时必填 | 可读错误信息 |
| `credentialSuffix` | string | 否 | 调用凭证后缀，仅用于定位 |

### 7.4 执行链路排序

- 链路按真实时间排序，不使用页面索引模拟时间。
- 父 Run 记录总状态，子调用记录各自状态。
- 同一 Run 可包含多次模型调用和多次工具调用。
- 父 Run 成功不代表所有可选子调用都成功；被容错处理的子错误仍需记录。
- Run 超时后，未完成子调用标记取消或超时，不应长期保持 running。

### 7.5 日志导出

- 导出范围默认为当前筛选结果。
- 支持 CSV（摘要字段）和 JSON（完整结构化字段）；大文件异步生成。
- 导出任务记录创建时间、条件、记录数、文件大小、过期时间和下载状态。
- 导出文件继续执行脱敏规则。
- 导出属于敏感操作，写入系统操作日志。

### 7.6 保留与清理

- 默认保留 90 天，可选 30、60、180、365 天。
- 以日志时间为准执行每日清理；时区边界需一致。
- 若开启自动归档，可先压缩归档再删除在线索引。
- 清理任务失败需重试并产生系统告警。
- 系统操作/安全审计日志可采用独立、更长保留策略；若一期统一保留，需在界面明确。
- 清理日志不影响业务资源，但历史会话页面可能无法再展开被清理的执行详情。

### 7.7 可观测指标与告警建议

- Agent Run 成功率、P50/P95/P99 耗时。
- 模型按资源/发布版本统计请求量、Token、错误率和 429 比例。
- MCP/工具调用量、成功率、超时率和平均耗时。
- 最大工具调用次数触顶比例。
- 上游鉴权失败、连续连接测试失败和资源异常数量。
- 存储使用量、日志写入延迟和清理任务失败。

一期界面以查询为主，自动告警可作为后续能力，但数据结构需预留。

## 8. 通用交互、状态与异常规范

### 8.1 加载状态

- 页面首次加载使用骨架屏，避免空白和布局跳动。
- 按钮提交后进入 loading 并禁止重复点击。
- 测试连接、Agent 回复、日志导出等长任务显示阶段性状态。
- 超过 10 秒的任务应允许取消或转为后台任务。

### 8.2 空状态

| 场景 | 建议文案与动作 |
|---|---|
| 无 Agent | 说明用途并提供「创建智能体」 |
| 搜索无结果 | 提示调整关键词或清除筛选 |
| 无模型 | 提供「接入模型」，并说明 Agent 依赖模型 |
| 无 MCP/Skill | 提供相应接入入口 |
| 无对话历史 | 提示先进行测试或发布调用 |
| 无调用日志 | 说明当前时间范围内没有记录 |
| 无模型发布版本 | 提供「发布新版本」 |

空状态不能与加载状态混淆；只有请求成功且确认数据为空后才展示。

### 8.3 错误状态

- 表单错误就近展示在字段下方，并将焦点移动到第一个错误字段。
- 网络错误保留用户已填写内容，提供重试。
- 资源冲突错误明确指出冲突对象，例如“模型调用标识已被 GPT-4.1 v1.0.0 使用”。
- 权限/鉴权错误不暴露敏感实现细节。
- 页面级不可恢复错误提供返回列表和重试入口。

### 8.4 保存与未保存修改

- 编辑表单采用显式保存；未保存内容标记为草稿状态。
- 离开页面、关闭抽屉或切换资源前，如有未保存修改，弹窗确认。
- 保存成功更新时间；保存失败不覆盖本地草稿。
- 多标签页编辑同一资源时，检测版本冲突并提示刷新或比较。

### 8.5 复制与密钥展示

- Endpoint、ID、Key 后缀和示例代码提供复制按钮。
- 复制成功给予短 Toast。
- 完整秘密仅在创建/重置后展示一次，关闭后不可再次恢复。
- 密钥输入框默认密码模式，可按住或点击图标临时显示。

### 8.6 响应式要求

- 桌面端：固定侧栏，Agent 编辑器为配置区+调试区双栏。
- 平板端：侧栏可折叠，Agent 调试区可切换为下方或独立 Tab。
- 移动端：导航抽屉化，表格横向滚动，弹窗接近全屏。
- 任何屏幕宽度下不得丢失主要保存、返回和关闭操作。

### 8.7 无障碍

- 所有输入框有可访问标签，图标按钮提供 `aria-label` 或 title。
- 状态不仅依赖颜色，同时展示文字或图标。
- 键盘可完成导航、弹窗关闭、表单提交和主要列表操作。
- 焦点在弹窗打开时进入弹窗，关闭后返回触发按钮。
- 正文和关键控件满足 WCAG AA 对比度。

## 9. 非功能性要求

### 9.1 性能

- 管理页面首屏在常规本地部署环境下 2 秒内可交互。
- 搜索输入 300ms 防抖；常用列表筛选反馈小于 500ms。
- 日志列表使用服务端分页；单页建议 20～100 条（原型为客户端分页、每页 8 条，见附录 C）。
- SSE 首个事件目标小于 2 秒（不含上游模型本身明显排队）。
- 大响应、日志和文件采用流式/分页方式，避免一次性载入内存。

### 9.2 可用性与恢复

- 核心配置写入需具备事务性。
- 服务重启后资源配置、发布状态和日志不丢失。
- 运行中的 SSE 断开时客户端可根据协议决定重连；不得重复执行非幂等工具。
- 外部依赖失败时隔离影响范围，不导致整个管理界面不可用。
- 定期备份配置数据库；密钥备份保持加密。

### 9.3 兼容性

- 管理界面支持最新两个主版本的 Chrome、Edge、Safari。
- 模型 API 对齐主流 OpenAI SDK 的 `base_url`、`api_key`、`model` 使用方式。
- MCP 协议支持 SSE、Streamable HTTP、stdio，并记录具体协议版本。
- AGUI 输出需声明协议版本，破坏性升级使用新路径或协商机制。

### 9.4 可维护性

- 资源 ID 与展示名称分离，重命名不改变引用关系。
- 配置结构包含 schema version，升级时可迁移。
- 错误码稳定且可文档化，界面文案不作为程序判断依据。
- Tool、模型类型和协议通过可扩展注册机制管理，避免硬编码散落。

### 9.5 隐私

- 匿名产品统计默认不得包含用户 Prompt、文件内容、工具参数、模型回复和任何 Key。
- 用户可在设置中关闭统计。
- 日志完整内容查看与导出需明确风险提示。
- 删除或清理数据后，备份中的保留和最终删除周期需有说明。

## 14. 后续可规划方向（Roadmap 建议）

2. 可视化工作流：条件、并行、循环、人工确认等节点编排。
3. 多 Agent 协作：Agent 间委派、路由和共享状态。
4. 模型评测：数据集、批量回放、效果评分、成本和延迟对比。
5. Prompt/Skill 市场：可导入导出、模板复用和版本依赖管理。

4. 高可用模型网关：负载均衡、故障转移、灰度和路由策略。
5. 外部存储与合规：日志长期归档、数据驻留和合规审计。

Roadmap 排期应以一期真实使用数据为依据，优先解决创建成功率、运行稳定性和问题定位效率，不为低频团队场景提前增加核心流程复杂度。

> 以下条目为 2026-10-29 按当前前端原型逐项复核的结果，已移除历史版本中「未实现」但实际已实现的描述（如 `⌘ K`、帮助弹窗、通知已读、日志时间/智能体筛选与分页、模型搜索与筛选等）。

### 全局与概览

- 概览的今日调用（1,284）、成功率（98.7%）、平均耗时（1.84s）、趋势序列以及资源状态副标题（「平均延迟 732ms」「8 个可用工具」「今日调用 486 次」「最近更新于 4 天前」）均为固定 Mock；“全部正常”不会随异常自动变化。

- 温度（0.7）、Top P（0.9）、最大输出 Token、单次运行最大时长以及三个高级开关未进入 Agent 持久化结构，刷新后回到默认值；仅最大工具调用次数可保存。

- 连接测试固定成功并返回固定延迟（782 ms），不调用上游；API Key 未强制必填，未测试也可保存（标记为「未测试」，但发布入口会被禁用）。
