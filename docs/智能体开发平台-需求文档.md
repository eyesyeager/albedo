## 修订说明（v0.2 → v0.3）

本版依据多轮澄清结论修订，核心变更如下：

| 模块 | 变更 |
|------|------|
| 应用生命周期 | 已发布应用可直接编辑、保存即线上生效；删除灰度发布，保留历史快照回滚；新增「启用/停用」开关 |
| 对外 API | JWT 由业务方自签、平台仅验签；会话完全匿名（不维护 user_id）；按应用 QPM 限流；MVP 对话接口不支持传文件 |
| 权限与隔离 | 取消工作空间，资源纯私有、按用户隔离；取消管理员角色，权限等级只用 NO / USER |
| 模型管理 | LLM / Embedding / Reranker 三类统一纳入模型管理；Embedding 走 OpenAI 兼容接口；Reranker 由用户接入主流提供商（填入 API Key 即可使用，支持自定义 OpenAI 兼容服务） |
| 知识库/检索引擎 | 知识库仅提供检索技术支持，**不内置向量数据库与 Elasticsearch 实例**；新增「检索引擎配置」管理界面，用户自行配置向量数据库（预置主流向量库）与 Elasticsearch 连接信息 |
| 工具抽象 | MCP Server 级接入 + 可禁用单个工具；检索服务并入知识库；Skill 与 MCP 隔离，定位为独立的指令与资料包 |
| 可观测 | 新增会话记录与工具调用 trace 回放 |

## 1. 文档概述

### 1.1 背景

企业智能化落地过程中，存在以下共性痛点：

- 各业务部门重复建设智能体，缺乏统一的技术底座与能力复用；
- 知识分散在不同系统（文档、数据库、表格、网页），难以被 AI 高效检索；
- 外部工具/系统集成缺乏统一协议，接入成本高；
- 缺少从「配置 → 开发 → 调试 → 发布 → 运营」的全生命周期管理手段。

### 1.2 目标

构建一个 **通用企业智能体开发平台（Albedo）**，让业务团队与技术人员能够：

1. **零代码 / 低代码** 快速搭建并发布 Agent 应用；
2. 通过统一机制接入 **知识库、MCP** 等能力；
3. 覆盖应用**全生命周期**，支撑从试点到规模化落地；
4. 通过标准的 **AGUI 协议 API** 对外提供 Agent 能力，与任意前端/业务系统解耦。

### 1.3 范围

- **本期（MVP）**：总览、应用管理（含 AGUI 协议对外接口、JWT 验签、QPM 限流、会话记录与 trace 回放）、模型管理（LLM / Embedding / Reranker 用户接入）、知识库管理、MCP 管理（含工具级禁用）、Skill（指令与资料包，与 MCP 隔离）、操作日志、登录认证（接入耶瞳用户中心）。
- **后续迭代**：多智能体协作、长期记忆、Text2SQL、数据连接器、开放 API 与 SDK、对话内文件上传、Reranker 高级策略（自训练/领域精调）、独立 Skill 模块。

## 2. 产品定位与目标

### 2.1 定位

面向企业的 **AI 智能体应用开发与运营平台**，以 **AgentOps** 为核心，提供：

- 统一的知识、工具、模型接入底座；
- 多种应用范式（单智能体、RAG，多智能体为后续迭代）；
- 企业级的安全、监控与可观测能力。

### 2.2 核心设计原则

| 原则 | 说明 |
|------|------|
| **能力统一为工具** | 知识库、MCP 等能力在智能体侧统一抽象为「工具」，由模型自主规划调用（参考阿里百炼 Agent 2.0） |
| **全生命周期** | 配置 → 开发 → 调试 → 发布 → 运营 全链路覆盖 |
| **零代码优先，低代码兜底** | 默认可视化配置，保留代码/插件扩展能力 |
| **过程可解释** | 完整呈现「规划 - 执行 - 反思」链路，而非只给最终结果 |
| **标准对外协议** | 以 AGUI 协议统一对外交互，前端与业务系统解耦 |
| **开放生态** | 以 MCP 协议为统一外部集成标准，提供 RESTful API / SDK |

## 3. 目标用户与核心场景

### 3.1 目标用户

> 平台**无管理员角色**，每位用户独立管理自己的资源（应用、知识库、模型、MCP），资源纯私有、互不可见。

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| **业务人员** | 无技术背景的运营/客服/产品 | 零代码配置智能体，接入现成知识库与工具 |
| **应用开发者** | 有技术背景，负责应用落地 | 接入 MCP、调试与发布 |

### 3.2 核心场景

1. **企业知识助手**：接入内部文档库，实现自然语言问答，支持引用溯源。
2. **智能客服**：知识库 + 工单系统（MCP）+ 多轮对话，通过 AGUI 协议接入前端。
3. **数据分析智能体**：自然语言查询数据库（Text2SQL），生成分析报告（后续迭代）。
4. **多专家协作**：多智能体分工（后续迭代）。

## 5. 核心概念与名词定义

| 名词 | 定义 |
|------|------|
| **应用（Application）** | 面向用户的可发布智能体单元，保存即线上生效，可启用/停用 |
| **智能体（Agent）** | 具备规划、工具调用、记忆能力的 LLM 应用实例 |
| **知识库（Knowledge Base）** | 文档/数据的集合，提供检索（RAG）能力；多库联合检索作为知识库的内置能力，不单独暴露「检索服务」实体 |
| **工具（Tool）** | 智能体可调用的能力单元，统一抽象（含 MCP 工具、Skill 模板） |
| **MCP** | Model Context Protocol，外部工具/服务的标准接入协议 |
| **Skill（技能）** | 一份以文件夹组织的**指令与资料包**（入口 Markdown 指令 + 参考文档 + 可选脚本/资源），与 MCP **完全隔离**：不绑定、不依赖、不产出 MCP 工具，运行时注入上下文；本期不单独建模块 |
| **记忆（Memory）** | 智能体跨轮/跨会话保留的上下文状态（短期记忆本期支持，长期记忆后续迭代） |
| **AGUI 协议** | Agent-User Interaction Protocol，Agent 与前端/业务系统的标准交互协议，以事件流方式传输消息、状态与工具调用 |
| **eyesUser（耶瞳用户中心）** | 统一账号中心，平台登录认证统一接入其单点登录（SSO），通过浏览器重定向 + JWT + 后端 Thrift 校验实现 |

## 6. 功能需求

### 6.1 总览

**目标**：提供平台级资源与运行概览，帮助用户快速掌握自身资源与运行状况。

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| OV-01 | 资源概览 | P1 | 展示当前用户的应用、模型、知识库、MCP 的数量统计 |
| OV-02 | 运行指标 | P1 | 展示调用量、Token 用量、错误率等关键指标与趋势 |
| OV-03 | 快捷入口 | P2 | 提供创建应用、接入模型、新建知识库等快捷入口 |

### 6.2 应用管理

**目标**：核心的智能体应用创建、配置、调试、对外提供 AGUI API 能力。

#### 6.2.1 应用创建

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| APP-01 | 创建应用 | P0 | 创建智能体应用 |
| APP-02 | 基础信息 | P0 | 名称、描述、图标、标签 |
| APP-03 | 历史快照与回滚 | P1 | 每次保存自动生成配置快照，支持历史对比与一键回滚（回滚本身也是保存即生效） |

#### 6.2.2 智能体配置

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| APP-10 | 模型选择 | P0 | 绑定 LLM 或智能模式档位 |
| APP-11 | 系统提示词（Prompt） | P0 | 角色设定、行为约束、输出格式 |
| APP-12 | 工具装配 | P0 | 挂载知识库（多库联合）、MCP（Server 级，可禁用单个工具） |
| APP-13 | 工具调用策略 | P1 | 智能调用（模型判断）vs 必定调用 |
| APP-14 | ReAct 轮次控制 | P1 | 限制单次会话工具调用最大轮次（1–50） |
| APP-15 | 记忆配置 | P1 | 短期记忆轮数（0–30），长期记忆开关（后续迭代） |
| APP-16 | 环境变量/鉴权 | P1 | 为 MCP 配置密钥与变量，避免硬编码 |
| APP-18 | 知识检索配置 | P0 | 多轮改写、标签过滤、来源展示、召回数量 |

> 已删除 v0.2 的 APP-17「预解析文件」对话内上传能力，本期文件仅通过知识库管理上传。

#### 6.2.3 调试

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| APP-20 | 对话调试台 | P0 | 实时对话测试，支持多轮 |
| APP-21 | 运行过程可视化 | P0 | 卡片流展示「思考 / 工具调用」步骤与入参返回 |
| APP-22 | 调试上下文 | P1 | 查看完整 token、工具调用明细、检索结果 |

#### 6.2.4 启用停用与 AGUI API

**目标**：应用创建后默认启用，保存即对外生效，可随时停用禁止外部调用。

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| APP-30 | 启用/停用 | P0 | 应用创建后默认启用可被调用，可随时停用禁止调用，删除才彻底移除 |
| APP-32 | 发布为组件 | P2 | 后续迭代：将应用发布为可复用的工具组件（多智能体基础） |
| APP-33 | AGUI 协议服务 | P0 | 启用状态下对外暴露符合 AGUI 协议的事件流接口 |
| APP-34 | 会话生命周期 | P0 | 创建会话、发送消息、中断运行 |
| APP-35 | 事件流传输 | P0 | 以 SSE 推送消息、状态、工具调用等标准事件 |
| APP-36 | 流式输出 | P0 | 支持 token 级流式输出与中间过程事件 |
| APP-37 | JWT 验签 | P0 | 对外 API 采用 JWT 验签，JWT 由业务方使用应用 Jwt Key 自行签发，平台仅验证签名 |
| APP-38 | 状态同步 | P1 | 运行状态、工具调用进度、快照事件同步给前端 |
| APP-39 | 兼容性 | P1 | 事件定义与 AGUI 规范对齐，保证前端组件开箱即用 |

#### 6.2.5 会话记录与 Trace 回放

**目标**：线上会话可回溯完整工具调用链路，支撑问题排查。

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| OBS-01 | 对话记录 | P0 | 存储线上会话的完整消息内容 |
| OBS-02 | 工具调用 trace | P0 | 记录每次工具调用的入参、返回、耗时、状态 |
| OBS-03 | 会话回放 | P1 | 按会话回放完整运行链路（规划 / 工具调用 / 输出） |
| OBS-04 | trace 关联 | P0 | 通过 trace_id 关联消息与工具调用，贯穿全链路 |

### 6.3 模型管理

**目标**：统一接入与管理 LLM / Embedding / Reranker 三类模型。

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| MD-01 | 模型接入 | P0 | 通过 base_url + API Key + 模型名 + 类型（LLM/Embedding/Reranker）统一配置，覆盖 OpenAI 及各 OpenAI 兼容服务/私有化模型 |
| MD-02 | 模型配置 | P0 | 温度、Top-P、最大 Token、上下文长度等参数 |
| MD-03 | 智能路由（智能模式） | P1 | AUTO / 性能 / 均衡 / 经济 四档，按任务复杂度动态路由（仅针对 LLM） |
| MD-04 | 模型可用性 | P1 | 模型上下架、版本管理与健康检查：列表页可对单个模型发起健康检查，按类型发送对应的模拟探测请求（LLM → `/chat/completions`、Embedding → `/embeddings`、Reranker → `/rerank`），弹窗展示请求方法与 Endpoint、请求体、HTTP 状态、耗时及模型响应原文；未接入或密钥无效等异常给出明确错误原因；请求期间显示进行中状态与加载反馈，卡片上留存最近一次检查结论与耗时 |
| MD-05 | 用量统计 | P1 | 按模型/应用统计输入输出 Token |
| MD-06 | Embedding 接入 | P0 | Embedding 走 OpenAI 兼容 `/embeddings` 接口 |
| MD-07 | Reranker 接入 | P0 | 提供主流 Reranker 提供商接入入口（BAAI 智源 / Jina AI / Cohere / 阿里云百炼 / 火山引擎方舟 / 腾讯云混元 / 硅基流动 / sentence-transformers·HuggingFace 等），用户选择提供商并填入 API Key 即可使用；支持自定义 OpenAI 兼容 `/rerank` 服务；平台不内置 Reranker 模型 |
| MD-08 | 模型删除 | P0 | 列表页支持删除已接入模型，删除前二次确认并按类型提示影响面（LLM 用于应用配置与智能路由、Embedding 用于知识库向量化、Reranker 用于检索重排）；已被应用/知识库引用的模型需先在对应处改绑其他模型，删除操作记入操作日志 |

### 6.4 知识库管理

**目标**：企业级文档理解与检索能力。多库联合检索作为知识库内置能力，不单独暴露「检索服务」实体。**知识库仅提供检索技术支持，不包含真实的向量数据库与 Elasticsearch 实例**；用户需在管理界面的「检索引擎配置」中自行配置向量数据库（预置主流向量库）与 Elasticsearch 连接信息。

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| KB-01 | 知识库 CRUD | P0 | 创建、编辑、删除知识库 |
| KB-02 | 文档上传 | P0 | 支持 10+ 类型：PDF/Word/PPT/Excel/Markdown/TXT/图片等 |
| KB-03 | 文档解析 | P0 | OCR、图文混排、表格、公式识别，结构化解析 |
| KB-04 | 大文件支持 | P1 | 单文档 ≥ 200MB |
| KB-05 | 切片策略 | P0 | 分块大小、重叠、按标题/段落切分，自定义 |
| KB-06 | 向量化 | P0 | 绑定 Embedding 模型（来自模型管理），支持自定义向量模型 |
| KB-07 | 检索方式 | P0 | 向量检索、混合检索、Reranker 重排（Reranker 来自模型管理中用户接入的模型） |
| KB-08 | 多库联合检索 | P0 | 应用可挂载多个知识库联合检索，智能/必定调用 |
| KB-09 | 多轮改写 | P1 | 结合上下文生成更优检索 Query |
| KB-10 | 标签过滤 | P1 | 文件标签 + 检索范围过滤 |
| KB-11 | 来源溯源 | P0 | 回答带角标引用来源与原文 |
| KB-12 | 检索测试 | P0 | 知识库内提供检索测试入口，可视化查看召回结果 |
| KB-13 | 同步与更新 | P1 | 文档增删改增量同步，索引重建 |
| KB-14 | 知识库删除 | P0 | 列表页支持删除知识库，删除前二次确认并展示影响面（文档数）；级联删除其下文档、切片与向量索引，遵循「先删向量再删元数据」，并从已挂载应用解绑，删除操作记入操作日志 |
| KB-15 | 删除前置校验 | P0 | 若知识库正被任一应用在「工具装配」中挂载，则**不允许删除**：列表页展示「被 N 个应用使用」标识，点击删除弹出占用提示并列出引用该知识库的应用，需先在应用解绑后再删除 |

### 6.6 Skill 管理（指令与资料包，与 MCP 隔离）

**目标**：Skill 是与 MCP **完全隔离**的独立资源——一份以文件夹组织的**指令与资料包**（入口 Markdown 指令 + 参考文档 + 可选脚本/资源），**不绑定、不依赖、不产出 MCP 工具**；MCP 提供可调用工具，Skill 提供注入上下文的指令与资料。本期不单独建模块：除预置模板外，支持上传技能包导入，点击 Skill 可在文件夹树中浏览、直接编辑保存并下载，同时支持删除管理。

### 6.8 登录认证

**目标**：平台登录认证统一接入耶瞳用户中心（eyesUser）单点登录，实现一次登录、免登访问。**权限等级仅使用 NO / USER，不使用 ADMIN。**

**接入模式**：浏览器重定向 + JWT Token + 后端 Thrift 校验。

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| AUTH-01 | SSO 接入 | P0 | 必须接入 eyesUser 单点登录，未登录访问受保护页面时 302 跳转 eyesUser 授权页 |
| AUTH-02 | 前端接入 | P0 | 回跳后解析 authorization token 并存入 localStorage，清理 URL；后续请求通过 authorization Header 携带 token |
| AUTH-03 | 后端鉴权 | P0 | 后端引入 eyesAuth-spring-boot-starter，通过 @Permission 注解校验 token，权限等级仅 NO / USER |
| AUTH-04 | 用户上下文 | P0 | 校验通过后从 UserInfoHolder 获取 uid，供业务层做资源归属隔离 |
| AUTH-05 | Token 续期 | P1 | type=1（单 token）模式下，前端从响应头回写续期 token |
| AUTH-06 | 鉴权失效处理 | P0 | 错误码 20000~20005 统一处理为清 token + 跳登录 |
| AUTH-07 | 环境要求 | P1 | 生产环境 HTTPS；后端到 eyesUser Thrift 端口内网互通 |

## 7. 非功能需求

### 7.1 性能

| 指标 | 目标值 |
|------|--------|
| 流式响应首字延迟（平台侧开销） | < 1s（不含第三方模型推理耗时） |
| 知识库检索延迟 | < 500ms（P95） |
| 并发支持 | 水平扩展，按应用 QPM 限流防滥用 |
| 大文档解析 | 200MB 文档可解析 |

### 7.2 安全

- 登录认证必须接入耶瞳用户中心（eyesUser）单点登录，平台不自行维护账号密码体系；
- 传输加密（HTTPS/TLS）、敏感信息加密存储（密钥不落库明文）；
- 内容安全审核（输入/输出）；
- 对外 API 采用 JWT 验签，JWT 由业务方用应用 Jwt Key 自行签发，平台仅验证签名；
- 密钥/环境变量安全注入，禁止硬编码；
- 资源纯私有、按用户隔离，无跨用户共享。

### 7.3 可用性与可靠性

- 核心服务高可用（99.9%）；
- 数据备份与灾备；
- 优雅降级（模型不可用时切换备用模型）。

### 7.4 可扩展性

- 模块化微服务架构；
- 插件式接入模型/工具/知识源；
- 支持私有化部署与云托管两种形态。

### 7.5 可观测性

- 全链路 Trace（请求 ID 贯穿）；
- 结构化日志、指标采集、告警；
- 会话记录与工具调用 trace 回放。

## 10. 开放 API 设计概要

### 10.1 对外运行时接口（AGUI 协议）

应用启用后，对外仅暴露 AGUI 协议的事件流接口（JWT 验签）：

```
POST /agui/apps/{app_id}/chat          # 发起对话（SSE 事件流）
POST /agui/apps/{app_id}/sessions      # 创建会话
GET  /agui/apps/{app_id}/sessions/{sid}/messages   # 历史消息
POST /agui/apps/{app_id}/sessions/{sid}/interrupt  # 中断运行
```

**JWT 验签约定**：

- JWT 由业务方使用应用 Jwt Key 自行签发，平台仅验证签名；
- 算法：HS256；
- 不强校验 claim，验签通过即可；若携带 `exp` 则校验过期时间；
- 会话完全匿名，平台不读取/不维护终端用户身份，以 `app_id + session_id` 为隔离与统计单位；
- 每个应用独立 Jwt Key，Key 轮换需支持新旧 Key 过渡。

**限流约定**：

- 按应用 QPM（每分钟请求数）限流，防滥用，不做计费配额；
- 超限返回统一限流错误码。

**AGUI 事件清单（参考，需对齐具体协议版本）**：

| 事件类型 | 说明 |
|----------|------|
| RUN_STARTED / RUN_FINISHED / RUN_ERROR | 运行生命周期 |
| TEXT_MESSAGE_START / TEXT_MESSAGE_CONTENT / TEXT_MESSAGE_END | 文本消息流 |
| TOOL_CALL_START / TOOL_CALL_ARGS / TOOL_CALL_END | 工具调用 |
| STATE_SNAPSHOT / STATE_DELTA | 状态快照 |
| STEP_STARTED / STEP_FINISHED | 规划步骤 |

### 10.2 管理侧 API（供管理台）

```
# 应用
POST /v1/apps            # 创建应用
GET  /v1/apps/{id}       # 查询
PUT  /v1/apps/{id}       # 更新（保存即生效）
POST /v1/apps/{id}/enable / disable
POST /v1/apps/{id}/rollback   # 回滚到历史快照

# 模型
POST /v1/models          # 接入模型（含 type 枚举）

# 知识库
POST /v1/knowledge-bases
POST /v1/knowledge-bases/{id}/documents
POST /v1/knowledge-bases/{id}/retrieve   # 检索测试

# MCP
POST /v1/mcp-servers
POST /v1/mcp-servers/{id}/tools/{tool}/disable   # 工具级禁用

# 会话与 trace
GET  /v1/apps/{id}/sessions            # 会话列表
GET  /v1/sessions/{sid}/trace          # 运行链路回放

# 操作日志
GET  /v1/operation-logs
```

### 10.3 统一约定

- 对外 API 鉴权：`Authorization: Bearer <JWT>`（业务方用应用 Jwt Key 自签）；
- 管理侧鉴权：管理台登录认证接入 eyesUser 单点登录，请求通过 `authorization` Header 携带 token，权限等级 NO / USER；
- 错误码统一结构：`{ code, message, request_id }`；
- 对外事件流遵循 AGUI 协议事件定义；
- 所有请求响应携带 `trace_id` 用于全链路排查。

| 文档解析准确率不足 | 知识库效果差 | 引入 OCR/版面分析，支持人工纠偏 |

### 12.2 待确认开放问题
