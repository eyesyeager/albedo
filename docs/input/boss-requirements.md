## 1. 背景与目标

### 1.1 业务背景

Albedo 需要以统一产品底座服务多个独立业务租户。租户通过三级域名访问各自站点，例如：

- `albedo-gift.eyescode.top` → 租户号 `gift`
- `albedo-redbook.eyescode.top` → 租户号 `redbook`

不同租户需要独立的 logo、网站品牌文案、用户关系、Agent、Skill、MCP、会话和消息数据，同时共享系统能力与运维底座。系统一期需要完成从租户识别、耶瞳用户中心认证、租户配置加载、Agent 能力编排到 AI 流式对话的完整闭环。

### 1.2 业务目标

1. 建立可扩展的多租户 AI 问答底座，使新增租户无需发布代码即可完成站点启用和能力配置。
2. 确保租户间用户关系、会话、配置、AI 资源及运行数据严格隔离。
3. 通过数据库配置实现网站标题、界面文案、Agent、Skill、MCP 和本地 Tool 的租户差异化。
4. 接入耶瞳用户中心，形成登录、注册、用户资料获取、退出登录的完整认证链路。
5. 提供接近参考图的信息架构和低学习成本的对话体验。

## 2. 范围与非范围

### 2.1 一期纳入范围（全部交付）

1. **租户基础能力**：租户创建、域名绑定、启停、配置版本发布、域名识别和请求上下文注入。
2. **耶瞳用户中心接入**：登录、注册、回调、用户信息同步、退出登录、登录态校验。
3. **租户站点配置**：网站标题、Logo/Favicon 地址、欢迎语、输入框提示、按钮文案、页脚声明等数据库配置。
4. **多 Agent 管理**：创建、编辑、复制、发布、启停、版本管理、排序、默认 Agent 设置。
5. **能力资源管理**：Skill、MCP Server、本地 Tool 的配置、测试、启停及 Agent 绑定。
6. **会话管理**：新建、列表、打开、重命名、删除、分页、按更新时间排序。
7. **AI 对话**：文本输入、流式响应、停止生成、重新生成、Markdown/代码展示、工具调用状态、错误重试。
8. **权限、审计与埋点**：平台管理员、租户管理员、租户运营、终端用户的访问控制及关键操作留痕。

### 2.2 一期不纳入范围

| 非范围项 | 原因及产品边界 |
|---|---|
| 图片、文件、音频上传及知识库问答 | 一期产品定位为文本 AI 问答与能力编排；上传入口不展示，避免形成不可用预期 |
| 语音输入、语音输出 | 属于多模态交互产品能力，不属于本期文本问答边界 |
| 用户自建 Agent、Skill 或 MCP | 一期仅由租户管理角色配置，终端用户只使用已发布能力 |
| 计费、套餐、额度购买 | 属于商业化系统；本期仅保留可观测用量，不展示付费入口 |
| 租户自定义域名 | 一期仅支持 `*.eyescode.top` 体系内三级域名；自定义域名属于域名托管产品能力 |
| 跨租户会话共享或迁移 | 与强隔离原则冲突 |
| 任意代码上传并作为本地 Tool 执行 | 存在远程代码执行风险；本地 Tool 必须由平台预注册，租户仅可授权和配置 |

> P0/P1/P2 仅表示业务价值和逻辑依赖顺序，所有纳入范围均须在一期实现。

## 3. 术语与角色

### 3.1 术语

| 术语 | 定义 |
|---|---|
| 租户（Tenant） | 独立业务空间，拥有唯一 `tenant_id`、域名、配置、用户关系和业务数据 |
| 租户号（tenant_id） | 租户稳定唯一标识，如 `gift`、`redbook`；创建后不可修改 |
| 租户上下文 | 服务端依据可信 Host 解析并贯穿一次请求的 `tenant_id`、域名、配置版本等上下文 |
| Agent | 面向用户提供对话的 AI 助手配置，包含模型参数、系统提示词及可用能力集合 |
| Agent 版本 | Agent 每次发布形成的不可变快照；会话绑定创建时的已发布版本 |
| Skill | 注入 Agent 的可复用提示、知识说明或流程指令，不直接执行任意代码 |
| MCP | Model Context Protocol 服务，向 Agent 暴露经授权的远程工具 |
| 本地 Tool | 由平台代码预注册、在受控运行环境执行的工具；租户不能上传执行代码 |
| 会话（Conversation） | 某租户用户与特定 Agent 版本的连续对话容器 |
| 耶瞳用户中心 | 外部统一身份系统，提供注册、登录和基础用户资料 |
| 发布 | 将草稿配置原子化生成可供线上读取的不可变版本 |

### 3.2 用户角色

| 角色 | 说明 |
|---|---|
| 平台管理员 | 管理全部租户、域名和平台级本地 Tool 注册；可进行受控排障，但默认不可查看用户消息正文 |
| 租户管理员 | 管理本租户站点配置、成员角色、Agent、Skill、MCP、Tool 授权和审计记录 |
| 租户运营 | 管理本租户站点文案、Agent、Skill、MCP 及查看审计；不可管理成员角色和敏感凭据 |
| 终端用户 | 通过耶瞳用户中心登录，在当前租户使用已发布 Agent 和管理本人会话 |
| 匿名访客 | 仅查看租户站点首页、公开品牌文案及登录/注册入口，不可发起 AI 对话 |
| 系统服务账号 | 执行异步任务、配置刷新和审计归档；必须绑定明确租户或声明平台级任务类型 |

## 4. 总体业务规则

1. 一个有效 Host 只能绑定一个租户；一个租户一期仅绑定一个主域名。
2. `tenant_id` 格式为小写字母开头、长度 2～32，仅允许小写字母、数字和连字符，正则：`^[a-z][a-z0-9-]{1,31}$`。
3. `tenant_id`、主域名创建后不可直接修改；如需更换域名，必须新增绑定、完成校验后切换主域名，并形成审计记录。
4. 服务端只信任经网关清洗后的 Host。业务 API 不接受客户端传入 `tenant_id` 作为数据权限依据；即使请求体中出现也必须忽略并记录异常。
5. 匿名访客可以加载启用租户的公开站点配置和 Agent 展示列表，但发送消息、读取会话及进入管理后台必须登录。
6. 同一耶瞳用户可以加入多个租户，各租户分别形成 `tenant_user` 关系；租户角色、状态和业务数据互不继承。
7. 用户首次在某启用租户登录成功后，默认自动创建该租户的终端用户关系；若该用户在该租户被禁用，则拒绝登录且不得自动恢复。
8. 站点配置、Agent、Skill 和 MCP 的线上变更均通过“草稿保存→校验→发布”生效。发布必须原子化，失败时继续使用上一已发布版本。
9. Agent 发布版本不可修改；再次编辑从最新版本生成新草稿，再次发布形成新版本。
10. 新会话绑定创建时选定 Agent 的最新已发布版本；已存在会话保持原版本，确保上下文行为可复现。发现新版本时提示用户新建会话，不在原会话静默切换。
11. Agent 被停用后不可新建会话或继续发送消息；历史会话仍可只读查看和删除。
12. Skill、MCP 或本地 Tool 被停用后，新请求不得调用；已在执行的调用立即取消或在 10 秒内终止，并以可理解错误结束该次回答。
13. 所有删除默认采用软删除。用户删除会话后立即不可见，30 天后物理清除；审计记录按独立保留规则保存。
14. 所有面向用户的时间按租户时区展示，数据库统一存储 UTC ISO 8601 时间。
15. 对外错误信息不得暴露数据库、内部地址、堆栈、密钥、其他租户标识或资源存在性。

## 5. 租户识别与强制隔离

### 5.1 域名识别规则

1. 网关接收 HTTPS 请求，规范化 Host：去端口、转小写、去末尾点。
2. Host 必须与数据库中状态为 `enabled` 的精确域名记录匹配；不得仅依赖字符串截取猜测租户。
3. 示例映射：
   - `albedo-gift.eyescode.top` → `gift`
   - `albedo-redbook.eyescode.top` → `redbook`
4. 未知域名返回统一“站点不存在”页和 HTTP 404。
5. 已禁用租户返回“站点暂停服务”页和 HTTP 403；不得展示登录入口、Agent 或任何租户业务数据。
6. 配置加载失败时使用该租户最后一个成功发布版本；不存在可用版本则返回“站点配置异常”页和 HTTP 503，并告警。
7. 本地开发可通过环境配置建立 `localhost:<port> → tenant_id` 映射；仅在非生产环境开启。生产环境禁止使用自定义 Header 模拟租户。

### 5.2 数据隔离强制规则

| 层级 | 强制规则 | 验收要求 |
|---|---|---|
| 数据库 | 所有租户业务表必须含非空 `tenant_id`；查询、更新、删除必须带租户条件 | 代码扫描、集成测试均通过 |
| 唯一约束 | 所有业务唯一性必须将 `tenant_id` 纳入联合唯一键，如 `(tenant_id, agent_key)` | 不同租户可创建同名/同 key 资源 |
| 关联关系 | 外键或应用层关联必须校验两侧 `tenant_id` 一致 | 构造跨租户 ID 时操作失败且不泄露资源信息 |
| 缓存 | 键格式：`albedo:{env}:{tenant_id}:{module}:{resource}:{id_or_version}` | 不存在无租户维度的业务缓存键 |
| 对象存储 | 路径格式：`tenants/{tenant_id}/{module}/{yyyy}/{mm}/{uuid}` | 不允许租户间共用业务对象路径 |
| 搜索/向量索引 | 索引文档必须带 `tenant_id`，每次检索强制过滤 | 跨租户检索结果为 0 |
| 异步任务 | 消息体、幂等键、重试键必须包含 `tenant_id` | 无租户任务拒绝消费并告警 |
| 日志 | 每条业务日志必须有 `tenant_id`、`request_id`；用户操作增加 `actor_id` | 日志抽检字段完整率 100% |
| 审计 | 审计事件必须包含租户、操作者、对象、动作、结果和前后版本摘要 | 不可由租户角色修改或删除 |
| 指标 | 业务指标标签含 `tenant_id`，对外展示时按权限过滤 | 租户管理员仅见本租户指标 |

### 5.3 同库同表默认方案 D

- 一期默认同库同表，所有租户业务实体以 `tenant_id` 作为必填分区字段。
- 建议由数据访问层自动注入租户条件，并对缺失租户上下文的业务访问直接抛错；是否叠加数据库行级安全由 @架构师裁决。
- 平台级表必须显式标记为 `scope=platform`，不得通过空 `tenant_id` 混入租户业务表。
- 平台管理员进行租户排障时必须选择目标租户、填写原因、获得短时授权，并生成不可删除的审计事件。

## 6. 核心流程

### 6.1 访问与配置加载流程

1. 用户访问租户三级域名。
2. 网关校验 HTTPS、规范化 Host，并传入可信 Host。
3. 服务端精确匹配租户域名并建立只读租户上下文。
4. 校验租户状态；未知、禁用、配置异常分别进入 404、403、503 分支。
5. 读取租户已发布站点配置和可展示 Agent 列表，缓存键必须含 `tenant_id + config_version`。
6. 返回租户化页面；前端页面标题、Logo、欢迎语、输入提示和页脚均来自配置，不得硬编码租户文案。

### 6.2 登录/注册流程

1. 匿名访客点击“登录”或“免费注册”。
2. 系统生成包含 `tenant_id`、原访问地址、随机数、过期时间的签名 `state`，保存一次性校验信息。
3. 浏览器跳转耶瞳用户中心对应入口。
4. 用户中心完成认证后回调当前租户的 `/auth/callback`。
5. 服务端校验 `state` 签名、有效期、一次性、回调 Host 与原租户一致，再交换令牌并获取用户信息。
6. 创建或更新平台身份映射及当前租户 `tenant_user`；租户用户被禁用时终止登录。
7. 建立仅当前 Host 有效的安全会话 Cookie，并跳回原访问地址。
8. 注册流程完成后自动执行同一登录回调，不要求用户重复登录。

**一期默认认证方案**：OAuth 2.0/OIDC Authorization Code + PKCE；后端 BFF 持有令牌，浏览器仅保存 `HttpOnly + Secure + SameSite=Lax` 的 Host-only 会话 Cookie。用户中心实际协议、端点和字段映射标记为待确认，未确认前按此方案完成适配层。

### 6.3 Agent 配置发布流程

1. 租户管理员或运营新建/编辑 Agent 草稿。
2. 选择模型参数，绑定已启用 Skill、健康的 MCP 工具和已授权本地 Tool。
3. 点击“校验”：检查必填字段、资源状态、MCP 连通性、权限和敏感配置。
4. 校验通过后点击“发布”，系统在事务中生成不可变 Agent 版本和绑定快照。
5. 发布成功后刷新租户 Agent 列表缓存；新会话使用新版本，旧会话维持原版本。
6. 发布失败不修改线上版本，展示可操作的失败原因并写入审计。

### 6.4 新建会话与 AI 对话流程

1. 登录用户点击“新聊天”或选择已发布 Agent。
2. 用户输入 1～20,000 个 Unicode 字符；纯空白不可发送。
3. 首次发送时服务端原子创建会话、绑定 `tenant_id + user_id + agent_id + agent_version`，保存用户消息。
4. 服务端组装系统提示、Skill、历史上下文和可用工具清单，所有读取均在当前租户上下文内。
5. 模型以流式方式返回内容；前端显示生成状态、文本分片和工具调用状态。
6. 工具调用前再次校验当前租户授权、工具状态和风险等级；高风险工具必须获得用户本次确认。
7. 完成后保存助手消息、模型用量、工具调用摘要；首轮成功后自动生成会话标题。
8. 失败时保留用户消息，失败的助手消息标记为 `failed`，用户可重试；重试不得重复创建用户消息或重复执行已成功的非幂等工具。

### 6.5 会话管理流程

- 会话列表仅返回当前租户、当前用户、未删除数据，按 `updated_at DESC` 排序，每页默认 20 条、最大 100 条。
- 用户可打开、重命名和删除本人会话。
- 自动标题取首条用户消息去除换行后的前 40 个 Unicode 字符，最长 60 字符；模型标题生成失败时使用该规则。
- 用户手动重命名后，系统不得再次自动覆盖。
- 删除需二次确认；成功后立即从列表移除，30 天内仅平台受控恢复，租户角色无恢复入口。
- 使用其他租户或其他用户的会话 ID 访问时统一返回 404。

### 8.2 租户与站点配置

- 平台管理员可创建租户草稿，填写租户号、名称、主域名、时区和语言。
- 启用前必须通过：域名唯一性、HTTPS 可用、站点配置已发布、至少一个已发布启用 Agent、默认 Agent 合法。
- 站点配置支持草稿预览；预览链接仅管理角色可访问，10 分钟失效，不进入搜索引擎。
- 发布后通过版本号刷新缓存，正常情况下 30 秒内全节点生效。
- 回滚本质为基于历史版本创建新版本并发布，保留完整审计链，不修改历史记录。

### 8.3 登录、注册与用户信息

- 未登录点击发送、历史会话或管理入口时，保存当前安全站内地址，登录成功后回跳。
- 回跳地址只允许同一租户 Host 下的相对路径，禁止开放重定向。
- 一期至少同步：外部用户唯一 ID、昵称、头像、手机号掩码、邮箱掩码、用户状态、更新时间；实际字段以用户中心为准。
- 手机号、邮箱只保存业务需要的规范化值或掩码；日志和埋点禁止记录完整值。
- 用户中心头像拉取失败时展示昵称首字符，不阻断登录。
- 外部用户被禁用、令牌失效或当前租户用户被禁用时，清除本地会话并提示重新登录或联系管理员。
- 登录态默认空闲 2 小时、最长 7 天；每次有效请求可滑动续期但不得超过最长时间。

### 8.4 Agent 管理

- Agent 列表字段：名称、唯一 key、当前发布版本、状态、是否默认、绑定能力数量、更新时间、更新人。
- 支持按名称模糊搜索，按状态筛选，默认按更新时间倒序。
- Agent 表单包含基础信息、模型配置、系统提示、上下文策略、能力绑定和安全策略。
- `agent_key` 在租户内唯一，发布后不可修改；不同租户允许相同 key。
- 复制 Agent 时复制当前草稿或最新发布配置，但生成新 ID、新 key 草稿，不复制密钥明文和审计记录。
- 删除仅允许未被会话引用的草稿 Agent；存在历史会话时只能停用。
- 发布前必须验证所绑定资源均为同租户、已发布且可用。

### 8.5 Skill 管理

- Skill 内容由名称、key、描述、指令正文、输入变量定义、输出约束和版本组成。
- 指令正文最长 50,000 字符；变量使用 `{{variable_name}}`，未声明变量校验失败。
- Skill 发布后不可修改；Agent 发布时保存 Skill 版本快照引用。
- Skill 停用后不可被新 Agent 版本绑定；已发布 Agent 的历史会话仍使用版本快照中的静态指令，但不得因此恢复已停用的外部工具权限。

### 8.6 MCP 管理

- 一期默认支持 `streamable_http` 和 `sse` 传输；`stdio` 不向租户开放。
- 管理者填写服务地址、鉴权方式、加密凭据、超时和允许工具清单。
- 服务地址只允许 HTTPS；内网地址必须来自平台维护的允许列表，防止 SSRF。
- “测试连接”返回成功、DNS 失败、TLS 失败、鉴权失败、超时、协议不兼容、无可用工具等分类结果。
- 连接成功后拉取工具清单；管理员逐个启用。服务端响应新增工具时默认禁用，不得自动授予 Agent。
- 密钥写入后仅显示是否已配置及末 4 位；查看接口永不返回完整密钥。
- MCP 输出按不可信外部内容处理，不得覆盖系统级权限规则或泄露系统提示和密钥。

### 8.7 本地 Tool 管理

- 平台管理员注册 Tool：key、版本、输入 JSON Schema、输出 JSON Schema、风险级别、执行超时、幂等性和说明。
- 租户管理员只能授权/停用、填写允许的非代码配置并绑定 Agent。
- 风险等级：`low` 自动执行；`medium` 根据 Agent 策略自动或确认；`high` 每次必须由终端用户确认。
- Tool 调用必须校验租户授权、Agent 绑定、输入 Schema、超时和结果大小。
- 单次结果默认最大 1 MB，超出则截断并标记；默认超时 30 秒，最大 120 秒。

### 8.8 会话与 AI 对话

- 消息角色支持 `user`、`assistant`、`system_internal`、`tool`；仅 `user` 和 `assistant` 正文对终端用户可见。
- 用户消息发送后立即展示本地状态；服务端确认保存后变为已发送，失败时展示重试按钮。
- 助手消息状态依次为 `queued → streaming → completed`，也可进入 `stopped`、`failed`。
- Markdown 必须安全渲染并过滤脚本、事件属性、危险 URL；代码块支持复制，不执行代码。
- 点击停止后 1 秒内停止前端追加，并向服务端取消上游生成；已生成内容保存为 `stopped`。
- 重新生成以最近一条用户消息为输入生成新的助手尝试；旧尝试保留但默认折叠，可切换查看。
- 单用户单租户默认限流：30 次消息/分钟、120 次消息/小时；超限展示剩余等待秒数。限额可由平台配置但不得跨租户共享计数。
- 上下文超过模型限制时，优先保留系统提示、最近消息和未完成工具链；对更早内容生成摘要。摘要失败时使用确定性的滑动窗口，不阻断本轮。
- 无可用 Agent 时输入框禁用，展示租户配置的不可用提示；管理角色额外看到“前往配置”入口。

### 8.9 管理后台通用规则

- 列表页均支持加载、空、正常、失败状态；失败不得展示旧租户数据。
- 表单离开时若有未保存修改，必须二次确认。
- 保存草稿不影响线上；发布操作必须二次确认并展示版本差异摘要。
- 所有敏感操作均由后端鉴权；前端菜单隐藏不能替代权限校验。
- 同一配置被并发编辑时使用版本号乐观锁；后提交者收到冲突提示，可查看差异并重新应用，不得静默覆盖。

## 10. 状态与枚举

### 10.1 租户状态

| 状态 | 进入条件 | 可执行操作 | 对外行为 |
|---|---|---|---|
| draft | 创建后默认 | 编辑、配置、校验、启用 | 域名访问返回 404 |
| enabled | 启用校验全部通过 | 正常使用、暂停 | 正常服务 |
| suspended | 平台管理员暂停 | 查看、整改、恢复 | 返回 403 暂停页 |
| archived | 已终止且完成数据处置 | 仅平台审计查看 | 返回 404，不可恢复为 enabled |

### 10.2 配置状态

`draft → published → archived`

- `draft`：可编辑，不影响线上。
- `published`：不可变，线上可使用；同一配置对象可有多个历史 published 版本，但只有一个 current 指针。
- `archived`：不可用于新绑定，仅保留审计和历史引用。

### 10.3 Agent 运行状态

| 状态 | 说明 |
|---|---|
| enabled | 已有发布版本且允许新建/继续对话 |
| disabled | 不允许新建或继续对话，历史只读 |
| deleted | 仅无引用草稿允许软删除，不对终端用户展示 |

### 10.4 会话状态

| 状态 | 进入条件 | 退出条件 |
|---|---|---|
| active | 首条用户消息保存成功 | 用户删除或 Agent 停用导致只读 |
| read_only | 绑定 Agent 停用/归档 | Agent 恢复启用；归档不可恢复时保持只读 |
| deleted | 用户确认删除 | 30 天后物理清除 |

### 10.5 消息与工具状态

- 消息：`queued / streaming / completed / stopped / failed`
- 工具调用：`pending / awaiting_confirmation / running / succeeded / failed / timed_out / cancelled / denied`
- MCP 健康：`unchecked / healthy / unhealthy`
- 租户用户：`active / disabled`

## 14. 非功能需求

### 14.1 安全

1. 全站仅允许 HTTPS，启用 HSTS；Cookie 使用 `HttpOnly + Secure + SameSite=Lax + Host-only`。
2. 管理操作防 CSRF；富文本/Markdown 防 XSS；所有数据库访问参数化；重定向地址使用允许列表。
3. MCP endpoint 防 SSRF，禁止访问云元数据地址、环回地址和未授权内网网段。
4. 密钥由密钥管理服务或等效机制加密保存；页面、接口、日志、审计不得返回明文。
5. 敏感字段传输 TLS 1.2+；会话正文和凭据静态加密。
6. 后端每次请求重新校验租户上下文和权限，禁止仅依赖前端传值。
7. 上线前必须通过跨租户 ID 枚举、缓存污染、Host 伪造、水平越权、开放重定向、XSS、CSRF、SSRF 测试。

### 14.2 性能与容量

- 租户识别与配置缓存命中 P95 ≤20ms。
- 非 AI 管理/查询接口 P95 ≤500ms，P99 ≤1s。
- AI 首字响应 P95 ≤5s；停止生成指令前端反馈 ≤1s。
- 会话列表首屏 P95 ≤1s。
- 一期设计基线：单租户 10 万用户、100 万会话、1000 万消息；扩容不得改变租户隔离语义。
- 分页必须使用稳定排序；大数据量下禁止无界查询和全表导出。

### 14.3 可用性与一致性

- 核心服务月可用性目标 ≥99.9%。
- 配置发布采用原子切换；缓存失效失败时以版本校验和回源保证不读取其他租户配置。
- 消息保存采用幂等机制；模型生成与工具调用失败不破坏已保存的用户消息。
- 外部服务故障必须隔离，不得导致其他租户、其他 Agent 整体不可用。

### 14.4 兼容性与可访问性

- 支持 Chrome、Edge、Safari 最新两个大版本；桌面宽度 1280px 以上完整布局，768～1279px 折叠侧栏，375～767px 使用移动单栏。
- 关键操作可使用键盘完成；焦点可见；图标按钮有无障碍名称。
- 正文和背景对比度满足 WCAG 2.1 AA；不只用颜色表达状态。
- 流式内容更新避免抢夺屏幕阅读器焦点。

### 14.5 数据保留与删除

- 用户会话：保留至用户删除；软删除 30 天后物理清除。
- 运行日志：默认保留 30 天并脱敏。
- 审计日志：默认保留 180 天，不随业务对象删除；法律或安全要求可由平台延长。
- 模型调用用量与工具摘要：默认保留 180 天，不保存不必要的正文副本。

## 16. 验收标准

### 16.1 租户与隔离验收

1. **AC-TEN-001**：给定 `albedo-gift.eyescode.top`，访问公开配置时只返回 `gift` 已发布配置。
2. **AC-TEN-002**：给定 `albedo-redbook.eyescode.top`，请求体伪造 `tenant_id=gift`，仍只能访问 `redbook` 数据并生成安全日志。
3. **AC-TEN-003**：两个租户可分别创建相同 `agent_key`、Skill key 和会话标题，不发生唯一键冲突。
4. **AC-TEN-004**：使用 gift 用户的会话 ID 在 redbook 域名访问，返回 404，响应、日志前台信息均不暴露 gift。
5. **AC-TEN-005**：抽查所有业务 SQL/ORM、缓存键、对象路径、任务消息和审计记录，租户字段完整率 100%。
6. **AC-TEN-006**：租户暂停后，已有登录态也不能读取会话或发起对话。

### 16.2 认证验收

1. **AC-AUTH-001**：登录和注册均可从当前租户跳转用户中心并安全回跳原页面。
2. **AC-AUTH-002**：篡改、过期、重复使用或跨租户使用 `state` 均被拒绝。
3. **AC-AUTH-003**：同一外部用户登录两个租户后形成两条独立 `tenant_user` 关系，角色和状态互不影响。
4. **AC-AUTH-004**：退出 gift 后 gift 会话失效；redbook 的独立 Host 登录态不被错误清除。
5. **AC-AUTH-005**：用户中心不可用时不建立半成品本地登录态，页面提供明确重试入口。

### 16.3 配置与 Agent 验收

1. **AC-CFG-001**：修改站点标题、欢迎语和输入提示并发布后，30 秒内新请求生效，旧版本可追溯。

1. **AC-SKL-001**：未声明变量导致 Skill 校验失败；发布版本不可直接修改。
2. **AC-MCP-001**：MCP 密钥创建后任何查询接口和页面均不返回明文。
3. **AC-MCP-002**：MCP 新发现工具默认禁用，未授权工具无法进入模型可调用清单。

1. **AC-CON-001**：未登录发送消息时进入登录流程，登录后回到原页面且输入草稿不泄露给其他租户。

## 18. 风险与依赖

| 风险 ID | 风险 | 影响 | 应对 |
|---|---|---|---|
| RISK-001 | 租户上下文在异步链路丢失 | 跨租户处理或数据泄露 | 无 tenant_id 的业务任务拒绝消费并告警；契约测试覆盖 |
| RISK-002 | 用户中心接口不稳定或字段变化 | 登录失败、资料不同步 | 认证适配层、超时熔断、字段版本兼容、明确错误提示 |
| RISK-003 | MCP 服务不可信或被入侵 | SSRF、数据外泄、提示注入 | 地址白名单、权限最小化、输出清洗、密钥隔离、调用审计 |
| RISK-004 | 缓存键漏租户 | 返回其他租户配置或权限 | 统一 Key Builder，禁止手写业务缓存键，自动化扫描和测试 |
| RISK-005 | Agent 配置变更影响历史会话 | 回答行为不可复现 | 会话固定 Agent 发布版本，版本不可变 |
| RISK-006 | 非幂等工具在重试中重复执行 | 产生重复业务副作用 | 工具声明幂等性；未知结果禁止自动重试；租户级幂等键 |
