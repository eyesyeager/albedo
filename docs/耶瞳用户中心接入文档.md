# eyesUser 单点登录 —— 第三方接入指南

> 适用对象：需要接入 eyesUser 账号体系的第三方应用开发者
> 后端方案：仅提供 Java 版（基于 `eyesAuth-spring-boot-starter`）

---

## 一、系统概述

eyesUser 是统一账号中心。第三方应用接入后，用户在 eyesUser 登录一次，即可免登访问所有已接入的应用。

**接入模式**：浏览器重定向 + JWT Token + 后端 Thrift 校验。

### 登录流程图

```
 用户浏览器                第三方应用              eyesUser
     │                         │                      │
     │  ① 访问业务页面         │                      │
     ├────────────────────────►│                      │
     │                         │                      │
     │  ② 未登录，302 重定向   │                      │
     │◄────────────────────────┤                      │
     │                                                │
     │  ③ GET /OAuth2?clientId=X&redirectUrl=Y        │
     ├───────────────────────────────────────────────►│
     │                                                │
     │  ④ 用户登录 + 授权                             │
     │◄──────────────────────────────────────────────►│
     │                                                │
     │  ⑤ 302 回跳 Y?authorization=<jwt>              │
     │◄───────────────────────────────────────────────┤
     │                         │
     │  ⑥ 携带 token 调用业务接口                     │
     ├────────────────────────►│                      │
     │                         │  ⑦ Thrift 校验 token │
     │                         ├─────────────────────►│
     │                         │◄─────────────────────┤
     │                         │   返回 uid / role    │
     │  ⑧ 业务正常响应         │                      │
     │◄────────────────────────┤                      │
```

整体过程分两段：

- **前端**：负责发起授权跳转、接收并存储 token、后续请求携带 token、识别失效后重新授权。
- **后端**：通过 starter 的 `@Permission` 注解自动校验 token，并把 `uid` / `role` 注入 ThreadLocal 供业务使用。

## 二、接入前置条件

### 2.1 向 eyesUser 管理员申请的信息

| 项 | 用途 | 示例 |
|----|------|------|
| `clientId` | 应用唯一 ID（整数），**前端**发起授权时使用 | `10001` |
| `appId` | 应用字符串 ID，**后端**校验 token 时使用 | `yourApp` |
| 鉴权类型 `type` | `0` 永不过期 / `1` 单 token | `1` |

### 2.2 环境要求

- **前端**：浏览器支持 `localStorage`，可解析 URL query。
- **后端**：引入 `eyesAuth-spring-boot-starter` 即可（无需自行编写 `.thrift` 或安装 thrift 编译器）。
- **网络**：生产环境必须 HTTPS；后端到 eyesUser 的 Thrift 端口需内网互通。

## 三、前端接入

### 步骤 1：未登录时跳转到授权页

```ts
const CLIENT_ID = ${yourClientId};                  // 申请到的 clientId
const SSO_URL   = "https://user.eyescode.top";
const REDIRECT  = encodeURIComponent(location.href); // 当前页作为回跳地址

location.href = `${SSO_URL}/OAuth2?clientId=${CLIENT_ID}&redirectUrl=${REDIRECT}`;
```

### 步骤 2：处理回跳，保存 Token

用户授权后，浏览器会带着 token 回到回跳地址：

```
https://your-app.com/somepage?authorization=<jwt>
```

入口处解析并保存，随后立即清理 URL，避免日志 / Referer 泄露：

```ts
function saveTokenFromUrl() {
  const qs = new URLSearchParams(location.search);
  const token = qs.get("authorization");
  if (!token) return;

  localStorage.setItem("authorization", token);
  // 清除 URL 中的 token
  history.replaceState(null, "", location.pathname);
}
```

### 步骤 3：请求时携带 Token，并处理失效与续期

每次调用受保护接口时，从 `localStorage` 读取 token，写入 HTTP Header `authorization`（Header 名需与后端约定一致）。

下面是基于 axios 的完整封装示例：

```ts
import axios from "axios";

const TOKEN_KEY    = "authorization";   // localStorage key
const HEADER_TOKEN = "authorization";   // HTTP Header 名（请求 / 响应共用）
const CLIENT_ID    = ${yourClientId};

// 这些错误码统一处理为"清 token + 跳登录"
const AUTH_ERROR_CODES = [20000, 20001, 20002, 20003, 20004, 20005];

const service = axios.create({
  baseURL: import.meta.env.VITE_API_DOMAIN,
  timeout: 60 * 1000,
});

// 请求拦截器：自动注入 token
service.interceptors.request.use(cfg => {
  const token = localStorage.getItem(TOKEN_KEY);
  if (token) {
    cfg.headers = cfg.headers || {};
    cfg.headers[HEADER_TOKEN] = token;
  }
  return cfg;
});

// 响应拦截器：① 回写续期 token；② 鉴权失效跳登录
service.interceptors.response.use(resp => {
  // ① type=1（单 token）模式下，starter 会把刷新后的新 token 写入响应头
  //    前端必须回写到 localStorage，否则下次请求仍用旧 token，会校验失败
  const newToken = resp.headers[HEADER_TOKEN];
  if (newToken) {
    localStorage.setItem(TOKEN_KEY, newToken);
  }

  // ② 鉴权失效统一处理
  const data = resp.data;
  if (data && AUTH_ERROR_CODES.includes(data.code)) {
    localStorage.removeItem(TOKEN_KEY);
    const redirect = encodeURIComponent(location.href);
    location.href =
      `https://user.eyescode.top/OAuth2?clientId=${CLIENT_ID}&redirectUrl=${redirect}`;
  }
  return data;
});

export default service;
```

> **要点**
> - 仅通过 Header 传递 token，**不要**放到 URL query。
> - `type=1`（单 token）模式下，每次请求都会签发新 token，必须在响应拦截器回写。

## 四、后端接入（Java）

### 4.1 引入依赖

starter 已把 Thrift 生成类、连接池、AOP 拦截器、常量等一并打包，引入坐标即可使用：

```xml
<dependency>
    <groupId>com.eyes</groupId>
    <artifactId>eyesAuth-spring-boot-starter</artifactId>
    <version>1.1.0</version>
</dependency>
```

### 4.2 配置 `application.yml`

starter 通过 `@ConditionalOnProperty` 控制是否启用：

```yaml
eyes-auth:
  enabled: true
  app-id: yourApp          # 申请到的 appId
  auth-type: 1             # 0=永不过期 1=单 token
  thrift:
    host: 119.29.213.134   # eyesUser Thrift 服务地址
    port: 9011
```

### 4.3 starter 提供的核心 API

| 类 / 注解 | 用途 |
|-----------|------|
| `@com.eyes.eyesAuth.permission.Permission` | 接口鉴权注解，标在 Controller 类或方法上 |
| `com.eyes.eyesAuth.permission.PermissionEnum` | 权限等级：`NO`（无需登录）、`USER`、`ADMIN` |
| `com.eyes.eyesAuth.context.UserInfoHolder` | 校验通过后从 ThreadLocal 取 `uid` / `role` |
| `com.eyes.eyesAuth.exception.EyesAuthException` | 鉴权失败时抛出的运行时异常，需配合全局异常处理 |
| `com.eyes.eyesAuth.thrift.TTClientPool` | 自动装配的 Thrift 连接池，业务调用 `UserService` 时使用 |
| `com.eyes.eyesAuth.constant.AuthConfigConstant` | Header 常量（`HEADER_TOKEN`=`authorization` 等） |
| `com.eyes.eyesAuth.constant.AuthTypeConstant` | 鉴权类型常量（`NEVER_EXPIRED`=0、`SINGLE`=1） |

### 4.4 在 Controller 上声明权限

通过 AOP 拦截 `@Permission`，**不需要手写 `HandlerInterceptor`，也不需要直接调用 Thrift Client**：

```java
@RestController
@RequestMapping("/api/order")
public class OrderController {

    // 无需登录（默认值）
    @Permission
    @GetMapping("/public")
    public Object publicApi() { ... }

    // 需要登录
    @Permission(PermissionEnum.USER)
    @GetMapping("/mine")
    public Object myOrders() {
        Long uid    = UserInfoHolder.getUid();   // 从 ThreadLocal 取当前用户
        String role = UserInfoHolder.getRole();
        return orderService.listByUid(uid);
    }

    // 仅管理员
    @Permission(PermissionEnum.ADMIN)
    @DeleteMapping("/{id}")
    public Object delete(@PathVariable Long id) { ... }
}
```

### 4.5 调用 eyesUser 的用户接口（可选）

若业务需要查询用户详情，可注入 starter 装配好的 `TTClientPool`，按"借出 → 调用 → 归还（异常时失效）"的方式使用：

```java
@RestController
@RequestMapping("/api/profile")
public class ProfileController {

    @Resource
    private TTClientPool ttClientPool;

    @Permission(PermissionEnum.USER)
    @GetMapping("/me")
    public UserInfoReturnee me() {
        Long uid = UserInfoHolder.getUid();
        TTSocket ttSocket = null;
        try {
            ttSocket = ttClientPool.getConnect();
            return ttSocket.getUserClient().getUserInfo(uid);
        } catch (TTCustomException e) {
            ttClientPool.returnConnection(ttSocket);
            throw new BizException(e.getMsg());
        } catch (Exception e) {
            ttClientPool.invalidateObject(ttSocket);
            log.error("getUserInfo error", e);
            throw new BizException(ResultCode.FAILURE);
        } finally {
            if (ttSocket != null && ttSocket.isOpen()) {
                ttClientPool.returnConnection(ttSocket);
            }
        }
    }
}
```

### 4.6 全局异常处理

鉴权失败时 `PermissionAdvice` 会抛出 `EyesAuthException`，请在全局异常处理器中转换为业务错误码（参见第五节"错误码对照表"），让前端拦截器能识别并触发跳登录：

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(EyesAuthException.class)
    public Result<?> handleAuth(EyesAuthException e) {
        // 根据 e.getMessage() 映射到 20000~20005，或直接返回 20001
        return Result.fail(20001, e.getMessage());
    }
}
```

## 五、错误码与 Header 约定

### 5.1 错误码对照表

| code | 含义 | 处理建议 |
|------|------|----------|
| 200   | 成功 | 正常继续 |
| 20000 | 权限不足 | 跳登录 |
| 20001 | Token 非法 / 伪造 / appId 不匹配 | 清 token，跳登录 |
| 20002 | Token 已过期 | 清 token，跳登录 |
| 20003 | 账号被冻结 | 提示并跳登录 |
| 20004 | 账户不存在 | 跳登录 |
| 20005 | 非法角色 | 跳登录 |
| 20008 | 参数非法 | 修正参数 |

> 前端可将 `[20000, 20001, 20002, 20003, 20004, 20005]` 统一处理为"清 token + 跳登录"。

### 5.2 Header 与鉴权类型

| 鉴权类型 | 请求 Header | 响应 Header（续期） | starter 内部校验方法 |
|---------|-------------|--------------------|---------------------|
| `type=0` 永不过期 | `authorization` | —（不会刷新） | `checkAuthByNeverExpire` |
| `type=1` 单 token | `authorization` | `authorization` | `checkAuthBySingle` |

> - HTTP Header 名不区分大小写，axios 读取到的一般是全小写。
> - `type=1` 模式下，前端**必须**在响应拦截器中把响应头里的新 token 回写到 `localStorage`，否则下一次请求仍使用旧 token 会校验失败。
