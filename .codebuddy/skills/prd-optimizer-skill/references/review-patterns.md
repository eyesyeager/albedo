# PRD 审查补充参考

## 常见 PRD 问题模式

以下是审查过程中高频出现的问题模式，按类型归纳，辅助快速识别。

### 一、流程类

| 问题模式 | 典型表现 | 追问方向 |
|---------|---------|---------|
| 流程章节为空 | 只有标题没有内容，或只贴了流程图没有文字描述 | 要求提供完整的状态流转描述 |
| 审批流过于粗略 | 仅写「需要审批」，未说明审批人、层级、超时机制 | 审批人是谁？如何确定？审批驳回后怎么处理？ |
| 编辑场景未考虑 | 只描述了新建流程，未说明编辑后是否需要重新审批 | 编辑哪些字段需要重新审批？审批期间原数据如何处理？ |
| 下线/删除逻辑缺失 | 未定义数据的终态处理 | 如何下线/删除？是否需要审批？是否可恢复？ |
| 状态机不完备 | 状态之间的流转条件不清楚，或有遗漏 | 画出完整的状态流转图，每个状态标明进入/退出条件 |

### 二、字段类

| 问题模式 | 典型表现 | 追问方向 |
|---------|---------|---------|
| 枚举值未定义 | 写了「下拉选择」但没列出选项，或标了「?」 | 请提供完整枚举值列表 |
| 单位/格式歧义 | 「优惠力度」不同类型应有不同单位但未区分 | 不同业务场景下该字段的单位分别是什么？ |
| 必填/选填未标注 | 表单字段没有标明是否必填 | 请标明每个字段的必填属性 |
| 文本字段无长度限制 | 输入框未定义最大字符数 | 字符数上限是多少？ |
| 时间格式不规范 | 使用 24:00 等非标准时间 | 应使用 23:59 或次日 00:00 |
| 金额字段无精度定义 | 未说明小数位数 | 保留几位小数？ |

### 三、一致性类

| 问题模式 | 典型表现 | 追问方向 |
|---------|---------|---------|
| 文档与 demo 图不一致 | 文档写的字段名和图中不同 | 以哪个为准？ |
| 筛选条件与列表字段不对齐 | 筛选枚举值和列表实际状态值命名不同 | 统一枚举值命名 |
| 新建/编辑/查看字段不一致 | 新建有的字段编辑里没提 | 三个页面的字段是否完全一致？ |
| 章节编号跳跃 | 从第四章直接跳到 5.1 | 统一修正编号 |

### 四、权限类

| 问题模式 | 典型表现 | 追问方向 |
|---------|---------|---------|
| 权限模型未定义 | 未说明不同角色的数据可见范围 | 普通用户、管理者、管理员分别能看到和操作什么？ |
| 操作权限未与状态关联 | 未说明各状态下哪些按钮可点 | 请列出状态×操作的完整矩阵 |

### 五、交互/体验类

| 问题模式 | 典型表现 | 追问方向 |
|---------|---------|---------|
| 批量操作缺乏细节 | 写了「批量输入」但未说明格式、校验、错误处理 | 支持什么输入格式？校验失败如何提示？ |
| 弹窗/提示文案缺失 | 只写了「弹窗确认」但没有具体文案 | 弹窗标题、内容、按钮文案分别是什么？ |
| 导出功能未定义 | 有导出按钮但未说明格式、范围、上限 | 导出什么格式？最多多少条？ |
| ID 生成规则不清 | 只写了「系统生成」但没说生成逻辑 | 前缀？自增？有无业务含义？ |

## 追问技巧

1. **给选项而非开放问题**：「审批驳回后是回到草稿态还是保持驳回态？」比「审批驳回后怎么办？」更高效
2. **一次一个核心点**：不要在一个追问里塞多个问题
3. **用确认而非提问的方式**：「我理解是 X，对吗？」比「这是什么意思？」更节省沟通成本
4. **标记追问编号**：用「追问 A」「追问 B」方便回溯
