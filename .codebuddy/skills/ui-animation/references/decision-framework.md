# 动画决策框架

在编写任何动画代码之前，按顺序回答以下四个问题。

## 1. 这个应该有动画吗？

**用户会看到这个动画多少次？**

| 频率 | 示例 | 决策 |
|---|---|---|
| 每天 100+ 次 | 键盘快捷键、命令面板切换 | 不要动画。永远不要。 |
| 每天几十次 | 悬停效果、列表导航 | 移除或大幅减少 |
| 偶尔 | 模态框、抽屉、Toast | 标准动画 |
| 罕见 / 首次 | 引导流程、反馈表单、庆祝动画 | 可以添加愉悦感 |

永远不要为键盘触发的操作添加动画。它们每天重复数百次 — 动画会让它们感觉缓慢且断开连接。

## 2. 动画的目的是什么？

在编写代码之前回答"为什么要有动画？"

| 目的 | 描述 | 示例 |
|---|---|---|
| **反馈** | 确认用户操作已被接收 | 按钮按下时缩放、切换状态 |
| **定位** | 显示空间关系 | 抽屉从边缘滑入、菜单从触发点缩放 |
| **连续性** | 跨状态变化保持上下文 | 页面过渡、布局位移 |
| **愉悦** | 增添个性（谨慎使用） | 交错揭示、弹簧过冲 |

如果目的只是"看起来很酷"而用户会经常看到，就不要添加动画。

## 3. 应该使用什么缓动？

遵循此决策树：

- **进入视口？** → 入场曲线：`cubic-bezier(0.22, 1, 0.36, 1)`
- **离开视口？** → 同样的曲线，更短的时长
- **在屏幕上移动/滑动？** → 移动曲线：`cubic-bezier(0.25, 1, 0.5, 1)`
- **简单悬停（颜色/透明度）？** → `200ms ease`
- **需要物理感？** → spring
- **直接操作（拖拽）？** → 无缓动，跟随指针
- **匀速运动（跑马灯、加载圈）？** → `linear`

使用自定义缓动曲线。UI 中避免使用 `ease-in`。

**缓动资源：** [easing.dev](https://easing.dev/) 和 [easings.co](https://easings.co/) 提供更强的自定义变体。

## 4. 速度应该多快？

| 元素 | 时长 |
|---|---|
| 按钮按下反馈 | 100–160ms |
| 工具提示、小型弹出框 | 125–200ms |
| 下拉菜单、选择器 | 150–250ms |
| 模态框、抽屉 | 200–350ms |
| 页面过渡 | 250–400ms |
| 演示 / 营销 | 最长 1000ms |

**规则：常规 UI 动画保持在 300ms 以内。**

### 感知性能

动画速度会改变感知性能：

- 快速旋转的加载圈让加载感觉更快（相同的加载时间，不同的感知）
- `ease-out` 在 200ms 时 _感觉_ 比 `ease-in` 在 200ms 时更快，因为用户看到了即时的运动
- 第一个工具提示打开后，后续的立即显示（跳过延迟 + 跳过动画）会让工具栏感觉更快

### 非对称时序

进入可以比退出稍慢。例如：长按删除在按下时使用 2s linear，释放时使用 200ms ease-out。

```css
/* 释放：快速 */
.overlay {
  transition: clip-path 200ms ease-out;
}

/* 按下：缓慢而刻意 */
.button:active .overlay {
  transition: clip-path 2s linear;
}
```
